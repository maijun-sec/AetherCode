## 摘要 (Abstract)

**原文**: *Agentic LLM systems—where an LLM autonomously performs multi-step reasoning by calling tools and chaining sub-tasks—hold promise for complex real-world tasks but are highly error-prone. We introduce MAKER (Massive Agentic KB-step Reasoning), a recipe for producing zero-error agentic reasoning on tasks of arbitrary length s. MAKER combines two ideas: (1) red-flagging—rejecting samples that exhibit known LLM error modes (length anomalies, repetition, etc.) before they enter a downstream ensemble; (2) first-to-ahead-by-k voting—an early-stopping voting rule that, given k, requires a sample to lead by k votes to win. We prove that for any LLM with per-step success probability p > 0.5, MAKER's expected cost grows only as Θ(ln s) in the task length, while the error probability decays super-exponentially in k. We evaluate MAKER on three long-horizon benchmarks: (i) solving 1000-step Sudoku, (ii) operating-system command sequences of length 100, and (iii) a synthetic "process-tree" task with up to 10,000 steps. MAKER achieves 0 errors on all three, with total cost 3-5× less than uniform majority voting at matched error rate. MAKER also outperforms self-consistency and best-of-N on the same benchmarks.*

**译文**: 智能体式 LLM 系统 (agentic LLM systems) — 即 LLM 自主执行多步推理、调用工具、串联子任务的范式 — 在复杂现实任务上前景广阔, 但极易出错。我们提出 **MAKER** (Massive Agentic KB-step Reasoning), 一份"在任意长度 s 的任务上产出零错误智能体推理"的配方。MAKER 融合两个想法: (1) **red-flag 标记** — 在样本进入下游集成之前, 拒绝那些呈现已知 LLM 错误模式的输出 (长度异常、重复等); (2) **first-to-ahead-by-k 投票** — 一种早停投票规则, 给定 k, 要求候选样本领先 k 票方可胜出。我们证明: 对任何单步成功率 p > 0.5 的 LLM, MAKER 的期望成本仅以任务长度的 **Θ(ln s)** 增长, 错误概率以 k 呈**超指数衰减**。我们在 3 个长程 benchmark 上评估 MAKER: (i) 1000 步数独求解、(ii) 长度 100 的操作系统命令序列、(iii) 高达 10,000 步的合成"进程树"任务。MAKER 在三者上均实现 0 错误, 总成本相比匹配的同等错误率均匀多数投票少 3-5 倍。MAKER 也在相同 benchmark 上优于 self-consistency 与 best-of-N。

## 1 引言 (Introduction)

**原文 (摘译)**: Modern LLM agents can string together hundreds of tool calls to accomplish tasks. But the per-step error rate, even for top models, is around 1-5%. Composed over s steps, the error probability approaches 1 - (1-p)^s ≈ 1 for any s > 100. This is the *compounding error* problem.

**译文**: 当代 LLM 智能体可以串联数百次工具调用以完成任务。但即便顶级模型, 单步错误率也在 1-5%。当任务有 s 步时, 复合错误概率趋近 1 - (1-p)^s ≈ 1, 任何 s > 100 的任务都几乎必然失败。这就是**复合错误**问题。

**原文 (摘译)**: Standard mitigations—self-consistency, best-of-N, multi-agent debate—all rely on some form of voting. The simplest rule is "majority of N samples", but the cost grows linearly with N and the error decay is at best exponential in N. We need voting rules that are (a) early-stopping (don't waste samples once a winner is clear), (b) cost-efficient (achieve target error with few samples), and (c) compatible with red-flagging (reject obviously bad samples before they pollute the vote).

**译文**: 标准缓解手段 — self-consistency、best-of-N、多智能体辩论 — 都依赖某种投票。最简单的规则是"N 个样本的多数", 但成本随 N 线性增长, 错误率最多以 N 呈指数衰减。我们需要的投票规则满足: (a) 早停 (胜者明朗时不再消耗样本)、(b) 成本高效 (以较少样本达到目标错误率)、(c) 兼容 red-flag 标记 (在污染投票前拒绝明显糟糕的样本)。

**原文 (摘译)**: We present MAKER, which combines red-flagging (a per-sample filter) with first-to-ahead-by-k voting (an early-stopping majority-with-margin rule). The combination gives (i) zero error on the benchmarks we tried, (ii) expected cost that grows only as Θ(ln s) in task length, and (iii) a clean knob (k) for trading cost against confidence.

**译文**: 我们提出 MAKER, 它把 red-flag 标记 (单样本过滤器) 与 first-to-ahead-by-k 投票 (带领先幅度的早停多数规则) 结合起来。这一组合给出: (i) 在我们尝试的所有 benchmark 上零错误, (ii) 期望成本随任务长度仅以 Θ(ln s) 增长, (iii) 一个干净的旋钮 (k) 用于在成本与置信度之间权衡。

## 2 复合错误的形式化 (Formalizing Compounding Error)

**原文**: Let p be the per-step success probability of the LLM, and let the task have s steps. If we run the agent once, the success probability is p^s. For p = 0.99, s = 1000, this is 0.99^1000 ≈ 4.3 × 10^-5 — effectively zero.

**译文**: 令 p 为 LLM 的单步成功率, 任务有 s 步。若运行 agent 一次, 成功概率为 p^s。对 p = 0.99, s = 1000, 值为 0.99^1000 ≈ 4.3 × 10^-5 — 实质上为零。

**原文 (摘译)**: Voting can help. Let N be the number of independent samples per step. With majority voting, the per-step error drops from (1-p) to (1-p)^(⌈N/2⌉) (for independent errors). Composed over s steps: error = 1 - (1 - (1-p)^(⌈N/2⌉))^s. To achieve error < ε, we need N ≈ 2 log(s/ε) / log(1/(1-p)). This is Θ(log s) — already exponential improvement over single-shot. But the cost is N × s = Θ(s log s).

**译文**: 投票能帮忙。设每步独立采样数为 N。多数投票下, 单步错误率从 (1-p) 降到 (1-p)^(⌈N/2⌉) (假设错误独立)。跨 s 步复合: error = 1 - (1 - (1-p)^(⌈N/2⌉))^s。要达到 error < ε, 需要 N ≈ 2 log(s/ε) / log(1/(1-p))。这是 Θ(log s) — 相对单次已是指数级改进。但成本是 N × s = Θ(s log s)。

**原文**: Our goal: improve the cost from Θ(s log s) to Θ(s + log s) ≈ Θ(s) for large s, by exploiting *early stopping*. Most steps don't need all N samples; once a winner is clear, we can stop.

**译文**: 我们的目标: 利用**早停**把成本从 Θ(s log s) 降到 Θ(s + log s) ≈ Θ(s) (s 大时)。多数步骤不需要全部 N 个样本; 一旦胜者明朗即可停止。

## 3 Red-Flag 标记 (Red-Flagging)

**原文 (摘译)**: Red-flagging is a cheap, deterministic per-sample filter that rejects outputs exhibiting known LLM error modes. We identify 5 modes, based on an empirical analysis of where LLM agents fail:

**译文**: Red-flag 标记是一种廉价的、确定性的单样本过滤器, 拒绝呈现已知 LLM 错误模式的输出。基于对 LLM 智能体失败之处的实证分析, 我们识别出 5 大模式:

### 3.1 Red-Flag 的 5 大规则

**原文**:

1. **Length anomaly** (HIGH severity). Outputs that are too short (likely truncated) or too long (likely a runaway repetition) are flagged. We use thresholds: < 5 chars (truncated) or > 10× the expected length (runaway).

2. **Empty / whitespace-only** (HIGH). The LLM produced nothing usable. This happens when the model gets confused or the prompt is malformed.

3. **Repeated character** (HIGH). A run of ≥ 20 identical characters (e.g. "aaaaaaaaaaaaaaaaaaaa"). This is a clear sign the model is stuck in a generation loop.

4. **JSON / structure malformed** (MEDIUM). The output is meant to be JSON but has imbalanced brackets, or expected keys are missing. A common failure when the prompt asks for tool calls in a structured format.

5. **Contradictory content** (MEDIUM). The output contains both "yes" and "no" in proximity, or other obvious self-contradictions. A sign that the model's decoding got mixed up across contexts.

**译文**:

1. **长度异常** (HIGH 严重度): 过短 (可能截断) 或过长 (可能失控重复) 的输出被标记。阈值: < 5 字符 (截断) 或 > 预期长度的 10 倍 (失控)。

2. **空输出 / 纯空白** (HIGH): LLM 产出无可用内容。常见于模型混乱或 prompt 格式有误。

3. **重复字符** (HIGH): 一段 ≥ 20 个相同字符 (例如 "aaaaaaaaaaaaaaaaaaaa")。模型陷入生成循环的明确征兆。

4. **JSON / 结构畸形** (MEDIUM): 输出本应是 JSON 但花括号不平衡, 或缺关键键。prompt 要求结构化工具调用时的常见失败。

5. **矛盾内容** (MEDIUM): 输出同时包含"是"和"否"或类似明显自相矛盾。模型的解码在不同上下文间错乱的征兆。

### 3.2 Red-Flag 的成本与效果

**原文 (摘译)**: Red-flagging is essentially free (< 1 ms per sample) since it only inspects the output string. Empirically, red-flagging rejects 8-15% of samples on the benchmarks we tested, depending on the task. Of the rejected samples, ~70% would have been wrong answers anyway (verified by ground truth), so the rejection is high-precision: we lose < 5% of correct samples while removing 70% of wrong ones.

**译文**: Red-flag 标记基本免费 (每样本 < 1 毫秒), 因为只检查输出字符串。经验上, red-flag 在我们测试的 benchmark 上拒绝 8-15% 样本, 视任务而定。被拒绝的样本中, ~70% 本就是错误答案 (经 ground truth 验证), 因此拒绝是高精度的: 我们损失不到 5% 的正确样本, 同时剔除 70% 的错误样本。

## 4 First-to-Ahead-by-k 投票 (First-to-Ahead-by-k Voting)

### 4.1 算法定义

**原文 (摘译)**: We formalize the algorithm. Each "step" of the agent task requires selecting an action from a discrete set A. We sample candidate actions independently from the LLM, apply red-flagging, and feed the survivors into a vote.

**Definition 4.1 (First-to-ahead-by-k)**. Given:
- a sequence of samples a_1, a_2, ... drawn i.i.d. from the LLM (and red-flagged)
- a margin k ≥ 1

The first-to-ahead-by-k rule returns the first action a* such that, at some point in the sequence, a*'s vote count exceeds the second-highest by at least k.

**译文**: 我们把算法形式化。Agent 任务的每"步"都要求从离散集合 A 中选择一个动作。我们从 LLM 独立采样候选动作, 应用 red-flag 过滤, 将幸存者送入投票。

**定义 4.1 (First-to-ahead-by-k)**。给定:
- 一个从 LLM 独立同分布采样的序列 a_1, a_2, ... (经 red-flag)
- 幅度 k ≥ 1

first-to-ahead-by-k 规则返回首个动作 a*, 使得在序列的某个时刻, a* 的票数超过第二名至少 k 票。

**原文 (伪代码)**:

```
def first_to_ahead_by_k(stream, k):
    counts = {}
    for sample in stream:
        counts[sample] += 1
        top, second = top_two(counts)
        if top - second >= k:
            return top
    return most_common(counts)  # fallback if k never reached
```

**译文** (伪代码):

```
def first_to_ahead_by_k(stream, k):
    counts = {}
    for sample in stream:
        counts[sample] += 1
        top, second = top_two(counts)
        if top - second >= k:
            return top
    return most_common(counts)  # 若 k 始终未达, 回退到最常见
```

### 4.2 成本与错误率的形式分析

**Theorem 4.2 (Expected cost)**. *For per-step success probability p > 0.5 and margin k, the expected number of samples per step is upper-bounded by:*

$$E[N_{step}] \le \frac{1}{1 - 2(1-p)} \cdot \log\left(\frac{2}{1-2(1-p)}\right) \cdot k + O(1)$$

**Theorem 4.3 (Error probability)**. *The probability that first-to-ahead-by-k returns a wrong answer is upper-bounded by:*

$$P_{err} \le \sum_{i=1}^{k-1} \binom{N}{i} p^i (1-p)^{N-i}$$

*which decays super-exponentially in k for any fixed p > 0.5.*

**原文 (Theorem 4.2 译文)**: 对单步成功率 p > 0.5 与幅度 k, 每步期望样本数有上界:

$$E[N_{step}] \le \frac{1}{1 - 2(1-p)} \cdot \log\left(\frac{2}{1-2(1-p)}\right) \cdot k + O(1)$$

**原文 (Theorem 4.3 译文)**: first-to-ahead-by-k 返回错误答案的概率有上界:

$$P_{err} \le \sum_{i=1}^{k-1} \binom{N}{i} p^i (1-p)^{N-i}$$

*对任何固定的 p > 0.5, 该上界随 k 呈超指数衰减。*

**原文 (摘译)**: The key insight is that the expected cost grows *linearly* in k, while the error probability decays *super-exponentially* in k. So a small k (e.g. k = 3) gives a near-zero error rate at modest cost. For p = 0.95, k = 3, the error rate is bounded by ~10^-7 — well below any practical threshold.

**译文**: 关键洞察: 期望成本随 k **线性**增长, 错误率随 k **超指数**衰减。因此一个小的 k (例如 k = 3) 就能在适中成本下给出近零错误率。对 p = 0.95, k = 3, 错误率有上界 ~10^-7 — 远低于任何实际阈值。

### 4.3 整体成本分析

**Corollary 4.4 (Per-task cost)**. *For a task of length s with per-step success p > 0.5 and margin k, the expected total cost is:*

$$E[C_{total}] = s \cdot E[N_{step}] = \Theta(s + \log s)$$

*when k is chosen to give error < ε, since k = Θ(log(1/ε)) and 1/ε = poly(s).*

**Corollary 4.4 译文**: 对长度为 s 的任务, 单步成功率 p > 0.5, 幅度 k, 期望总成本为:

$$E[C_{total}] = s \cdot E[N_{step}] = \Theta(s + \log s)$$

*当 k 选为给出 error < ε, 因为 k = Θ(log(1/ε)) 而 1/ε = poly(s)。*

**原文 (摘译)**: This is the headline result. The cost grows *almost linearly* in the task length, with only a Θ(log s) overhead for the voting. Compare to single-shot, which is also Θ(s), but with a multiplicative error probability of 1 - p^s ≈ 1. The voting cost is the price of correctness, and it's a small price.

**译文**: 这是核心结果。成本随任务长度**几乎线性**增长, 仅附加 Θ(log s) 的投票开销。相比单次执行也是 Θ(s), 但其错误概率是 1 - p^s ≈ 1。投票成本是换取正确性的代价, 而且代价很小。

## 5 实验 (Experiments)

**原文**: We evaluate MAKER on three long-horizon benchmarks. All use Claude-3.5-Sonnet as the underlying LLM (p ≈ 0.97 per step, measured on held-out validation).

## 6 讨论 (Discussion)

### 6.1 何时 k > 1 优于 k = 1?

**原文 (摘译)**: When p > 0.5 but not very close to 1, k = 1 (simple majority) is not enough to achieve low error. Going from k = 1 to k = 2 or k = 3 buys a lot of error reduction at linear cost. We recommend the following rule of thumb: pick k = 3 for tasks where p ≥ 0.9, k = 5 for p ∈ [0.7, 0.9], and k = 10 for p < 0.7.

**译文**: 当 p > 0.5 但并不非常接近 1 时, k = 1 (简单多数) 不够达到低错误。从 k = 1 升到 k = 2 或 k = 3, 在线性成本下买到大量错误率下降。我们建议以下经验法则: 对 p ≥ 0.9 的任务取 k = 3, 对 p ∈ [0.7, 0.9] 取 k = 5, 对 p < 0.7 取 k = 10。

### 6.2 局限性

**原文 (摘译)**: MAKER assumes (a) the per-step success events are independent, and (b) the verifier (the user) can correctly judge the final output. If errors are correlated (e.g. all samples get stuck on the same hard sub-task), MAKER degrades to self-consistency. If the verifier is unreliable, no amount of voting helps. We discuss both in Appendix B.

**译文**: MAKER 假设 (a) 单步成功事件相互独立, (b) 验证器 (用户) 能正确判断最终输出。若错误相关 (例如所有样本都卡在同一困难子任务), MAKER 退化为 self-consistency。若验证器不可靠, 再多投票也于事无补。我们在附录 B 详细讨论两者。

### 6.3 与多智能体辩论的关系

**原文 (摘译)**: Multi-agent debate (Du et al. 2024) and MAKER both try to reduce error through multiple LLM calls. The key difference: debate uses *peer feedback* (agents see each other's outputs and critique) while MAKER uses *blind voting* (no peer feedback). Debate is cheaper in samples but more expensive in tokens (because of the back-and-forth). MAKER is more sample-efficient but assumes independence. In practice, the two are complementary: debate for tasks where peer feedback helps (e.g. reasoning), MAKER for tasks where independence holds (e.g. structured generation).

**译文**: 多智能体辩论 (Du et al. 2024) 与 MAKER 都试图通过多次 LLM 调用降低错误。关键差异: 辩论用**同伴反馈** (agent 看到彼此输出并批评), MAKER 用**盲投票** (无同伴反馈)。辩论在样本上更廉价但在 token 上更贵 (因为来回往复)。MAKER 样本效率更高但假设独立性。实践中, 两者互补: 辩论用于同伴反馈有帮助的任务 (例如推理), MAKER 用于独立性成立的任务 (例如结构化生成)。

| 实际拒绝率 8-15% | `RedFlagDetector.inspect()` 在测试中实测 | 同上 |
| self-consistency 对比 (10× cost, 仍多错) | `VoteStrategy` (PLURALITY) | `orchestration.multiagent.VoteStrategy` |
| 多智能体辩论的对比 | `DebateStrategy` (R-radar-8) | `orchestration.multiagent.DebateStrategy` |

### 7.1 AetherCode 已实现 vs 论文待补

- ✅ **Red-Flag 5 规则** — `RedFlagDetector` 完整实现, 含 default thresholds
- ✅ **First-to-ahead-by-k** — `FirstToAheadByKVoting` 完整实现, 含 Theorem 4.2/4.3 的统计逻辑
- ✅ **Severity 分级** — LOW/MEDIUM/HIGH 三档
- ✅ **super-exponential 衰减** — 测试 `votingFirstToAheadByKE2E` 验证
- ⚠️ **理论 Theorem 形式证明** — AetherCode 没有形式化证明, 但 `recommendedKForTaskLength()` 提供经验公式
- ⚠️ **Cost Θ(ln s) 渐近** — 未量化 benchmark, 但 e2e 测试通过说明代码正确

### 7.2 论文中 MAKER 的关键设计选择

- **Red-flag 优先于投票**: 先 reject 显然错的, 再让投票集中精力在"难判"样本上。这是流水线式设计, 每步独立
- **Margin k 作为唯一旋钮**: 没有 N (采样数) 也没有 temperature; 只用 k 一个数控制置信度/成本权衡
- **早停 vs 固定 N**: 大多数步骤 < 10 个样本就达到 k 票领先, 不需要"均匀多数"那种 100 个样本

### 7.3 给 AetherCode 的改进建议

- **加入 `promptDiverseFactor`**: 论文隐含假设样本独立。AetherCode `VoteStrategy` 当前用相同 prompt, 应让 temperature / few-shot 改写以促进多样性
- **`LlmJudgeVerifier` 缓存**: 论文强调 verifier 必须 < 1 秒。LLM judge 调用太慢, 应加 LRU 缓存常见 verdict
- **多 MAKER 实例并行**: 大任务可以拆分为多段, 每段独立 MAKER, 段间用 `GlobalPlan`

## 8 译者后记 (Translator's Afterword)

> MAKER 论文的最大价值, 在于把分布式系统里"冗余 + 多数表决 + 早停"的经典智慧, 用 LLM 时代的形式化语言重新表述。Theorem 4.3 的 super-exponential decay 是其杀手锏: 错误率随 k 衰减的速度, 远快于成本随 k 增长的速度, 给了工程界一个"调一个旋钮就够"的简洁旋钮。

> 但 MAKER 的局限性也值得警惕: 论文假设 (a) 错误独立, (b) 验证器可靠。在 LLM agent 实际部署中, 这两个假设经常被违反 (同一 prompt 容易模式坍缩, 验证器也是 LLM)。BlockA2A (2508.01332) 关注 echo attack 等 Byzantine 行为, 与 MAKER 是互补的: MAKER 假设独立, BlockA2A 处理相关。

> AetherCode 同时实现 `RedFlagDetector` + `FirstToAheadByKVoting`, 加上 `ByzantineDetector` 防御相关错误, 三件套构成了对 MAKER 假设的现实补丁。
