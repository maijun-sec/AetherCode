# 2506.01804 A Study on the MCP × A2A Framework for Enhancing Interoperability

**作者**: Cheonsu Jeong (Samsung SDS)

**会议**: Journal of Intelligence and Information Systems, 31(3), 141-170 (2025)

**日期**: 2025-06-02 (v1) / 2025-06-09 (v2)

**PDF**: 1.1 MB · 12 pages

**核心**: **MCP + A2A 集成方法论** — 互操作协议不是二选一, 是互补: **MCP 管 tool, A2A 管 agent**, 企业级 agent system 的标准双协议栈。

## 1. 角色分工

| 协议 | 角色 | 调用方向 |
|---|---|---|
| **MCP** | agent ↔ tool 通信, 结构化 I/O | vertical (agent 下沉到 tool) |
| **A2A** | agent ↔ agent 协作, peer-to-peer | horizontal (agent 之间对话) |

**没有 MCP**: agent 没有工具能力
**没有 A2A**: agent 之间无法协作
**两者都有**: agent 既能调 tool, 又能跟其他 agent 对话, 完整 enterprise stack

## 2. 集成架构 (Figure 1 描述)

```
User Query
    ↓
[Agent A] ←── A2A ──→ [Agent B] ←── A2A ──→ [Agent C]
    ↓                       ↓                     ↓
  MCP                     MCP                   MCP
    ↓                       ↓                     ↓
[Tool 1]              [Tool 2,3]              [Tool 4,5]
```

## 3. 实施方法论 (7 步)

1. **Capability Modeling**: 用 Agent Card 描述 agent 能力
2. **Tool Wrapping**: 用 MCP 把外部 tool 包装为 JSON-RPC 接口
3. **Protocol Selection**: 选 MCP 或 A2A 取决于交互方向
4. **Discovery**: A2A 的 Agent Card + MCP 的 tool registry
5. **Authentication**: OAuth 2.0 + API key + DID
6. **Task Delegation**: A2A Task/TaskStatus 状态机
7. **Result Aggregation**: 收集多 agent 结果, 聚合成最终输出

## 6. 教训

- **MCP + A2A 是互补, 不是竞争** — paper 给出明确分工: tool vs agent
- **企业级 agent stack = MCP + A2A 双协议** — 单协议不够
- **Capability Modeling 自动化** — Agent Card 不应手写, 应从代码生成
- **Protocol 路由可自动** — 调用方向决定协议, 不必人肉选
- **Authentication 是横切关注** — 所有协议都要, 不在协议内
