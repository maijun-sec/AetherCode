# Agentic Memory（AgeMem）：长短期记忆的统一管理框架 (arXiv:2604.12179)

## 1. 标题与作者

**英文原题**：Agentic Memory (AgeMem): Unified Long-Term and Short-Term Memory Management
**中文题目**：代理化记忆（AgeMem）：长短期记忆的统一管理
**作者**：Yi Yu、Liuyi Yao 等
**arXiv 编号**：2604.12179（标识段 `agemem-unified-lt-st`）
**发表年份**：2026 年
**PDF 体积**：1.0 MB
**研究主题**：在以大语言模型（LLM）为大脑的智能体（agent）系统中，把长期记忆（Long-Term Memory, LT）与短期记忆（Short-Term Memory, ST）的联合调度显式化为 agent 可调用的工具，并通过三阶段渐进式强化学习（3-stage Progressive RL）与逐步（step-wise）分组相对策略优化（Group Relative Policy Optimization, GRPO）完成端到端训练。

## 2. 一句话摘要

AgeMem 把"何时写 LT、何时清 ST、何时回读"显式建模为可调用工具，配套三阶段渐进式强化学习与逐步 GRPO，在五个异构基准上以 4B 基座取得 **54.31%** 的平均准确率，超越 A-Mem 基线 **8.57** 个百分点。

## 3. 背景与动机

近年来，以 LLM 为大脑的智能体逐步从"调用一次模型完成任务"演进为"在长时程环境中持续感知—决策—行动"。然而，无论是在 ALFWorld 这类具身家庭任务、HotpotQA 这类多跳问答，还是 BabyAI 这类网格导航里，agent 都不可避免地要面对两类迥异却又相互纠缠的记忆负担：长期记忆（LT）负责跨 episode 的经验沉淀与知识积累，短期记忆（ST）则承担单次任务内部的上下文追踪与中间状态维护。

既有的记忆方案大体可归为三条路线。其一是把记忆封装为隐式 schema，例如 A-Mem 所采用的五属性（5-attribute）框架，依靠 in-context learning 在每一回合重排 schema，但训练阶段不显式优化记忆策略。其二是借鉴 Zettelkasten 卡片盒笔记法的索引结构，以图或向量形式组织 LT，却对 ST 缺乏同等粒度的管理。其三是直接在 prompt 中堆叠历史，由上下文窗口被动吸收全部信号，结果是长上下文下的延迟与成本同步爆炸。

上述三条路线共享一个根本缺陷：记忆管理始终是"内嵌于推理"的隐式动作，agent 不能像调用 `Search` 或 `Calculator` 那样以一个边界清晰、参数可观察、回报可计算的工具去操纵自身记忆。这一缺陷带来两个后果：第一，记忆策略无法被独立优化——任何对 LT/ST 调度规则的修改都必须穿透到完整的提示工程；第二，记忆决策的粒度被绑定在"整段对话"上，缺乏 step-level 的精细调控。

AgeMem 的提出正是为了回答一个朴素却关键的问题：**当记忆管理被升格为可调用的工具、并以 step-wise GRPO 加以端到端训练时，agent 在长短期记忆混合的复杂任务上能否获得显著且稳定的性能提升？**

## 4. 核心方法

AgeMem 的方法论由三个相互嵌套的组件构成：（A）把记忆管理显式暴露为工具；（B）三阶段渐进式强化学习（3-stage Progressive RL）；（C）逐步分组相对策略优化（step-wise GRPO）以联合调度 LT/ST 记忆。下面分别详述。

### 4.1 记忆管理即工具（Memory Management as Tools）

与传统方案把 LT/ST 操作埋在 prompt 里的做法不同，AgeMem 把所有记忆动作原子化为一组**可调用工具**。每一个工具拥有明确的输入输出契约、可被 agent 在 ReAct 循环里显式 `call`，并且具备可观测的 reward signal。典型的工具集合包括：

- `MemoryWrite(item, scope)`：将 `item` 写入指定 scope（`LT` 或 `ST`）；
- `MemoryRead(query, scope)`：从指定 scope 中检索与 `query` 相关的条目；
- `MemoryConsolidate()`：把 ST 中的高频访问条目合并、提升至 LT；
- `MemoryForget(scope, age)`：按时间或访问频率衰减指定 scope 中的条目。

这一设计借鉴了 Toolformer、ReAct、Function Calling 等 agent 工程范式，使记忆管理获得了"一等公民"的地位：从语义上看，它与其他外部工具（搜索、计算、代码执行）无异；从优化角度看，它的每一次调用都是一个可被 RL 信用分配的决策点。

### 4.2 三阶段渐进式强化学习（3-stage Progressive RL）

考虑到直接端到端训练记忆策略极易陷入不稳定，AgeMem 采用**课程式（curriculum）训练范式**，把整个学习过程拆解为难度递进的三阶段：

| 阶段 | 训练目标 | 记忆范围 | 主要技能 |
|---|---|---|---|
| Stage 1（基础） | 单一 scope 操作 | 仅 ST | 写入 / 读取短上下文 |
| Stage 2（进阶） | 单一 scope 操作 | 仅 LT | 写入 / 读取长期条目 |
| Stage 3（完整） | LT/ST 联合调度 | LT + ST | 巩固、衰减、跨 scope 协调 |

Stage 1 让 agent 首先学会"如何调用记忆工具"这一机械层面的能力；Stage 2 引入长期记忆，迫使 agent 处理检索噪声、过期条目等问题；Stage 3 才把 LT 与 ST 同时摆上桌面，要求 agent 在每一步判断"这条信息应该放进 LT 还是只放 ST"、"什么时候该 consolidate"。这种由浅入深的训练范式已被经验性地证明比一次性联合训练更稳定，也更易于诊断失败模式。

### 4.3 逐步分组相对策略优化（Step-wise GRPO）

传统的 episode-level RL（如 PPO 在整条轨迹上做优势估计）面临信用分配困难：在长达数十步的任务中，究竟哪一步的"该不该写 LT"决策贡献最大，几乎无法精确追溯。AgeMem 采用 **step-wise GRPO**——把 RL 的优化粒度从 episode 下沉到每一个记忆决策步。

在数学形式上，对每一个记忆决策步 `t`，agent 采样一组 `G` 条候选轨迹 `{τ_1, …, τ_G}`，其相对优势由组内归一化奖励给出：

$$
\hat{A}_t^{(i)} \;=\; \frac{R(\tau_i) \;-\; \mathrm{mean}\bigl(R(\tau_1),\dots,R(\tau_G)\bigr)}{\mathrm{std}\bigl(R(\tau_1),\dots,R(\tau_G)\bigr)}
$$

随后，GRPO 的目标函数对策略参数 `θ` 作如下更新：

$$
\mathcal{J}_{\mathrm{GRPO}}(\theta) \;=\; \mathbb{E}\!\left[\frac{1}{G}\sum_{i=1}^{G}\min\!\Bigl(r_i(\theta)\,\hat{A}_t^{(i)},\;\mathrm{clip}\bigl(r_i(\theta),\,1-\varepsilon,\,1+\varepsilon\bigr)\,\hat{A}_t^{(i)}\Bigr) \;-\; \beta\,\mathrm{KL}\!\bigl(\pi_\theta \,\|\, \pi_{\mathrm{ref}}\bigr)\right]
$$

其中 `r_i(θ) = π_θ(o_i | q) / π_{θ_old}(o_i | q)` 是新旧策略在第 `i` 条轨迹上的重要性采样比，`ε` 为 PPO 风格的截断超参数（通常取 0.2），`β` 控制与参考策略 `π_ref` 的 KL 距离。

step-wise 的关键创新在于：上述优化不再是"在 episode 结束时算总账"，而是**在 agent 决定调用某个记忆工具的当下**就计算一组候选动作的相对优劣，并把梯度信号即时回传。这与 LT/ST 调度的本质高度契合——记忆决策天然是 step-level 的、局部的、可独立评判的，而不是 episode 末端的全局判断。

### 4.4 LT/ST 联合调度

在 Stage 3 中，AgeMem 要求 agent 在每一步同时考虑 LT 与 ST 两个 scope。具体地，调度策略被形式化为一个五元组 `(scope, op, item, age, priority)`：

- `scope ∈ {LT, ST, BOTH}`：操作的目标记忆库；
- `op ∈ {write, read, consolidate, forget}`：具体的记忆动作；
- `item`：被操作的条目；
- `age`：条目的逻辑年龄（用于触发遗忘或巩固）；
- `priority`：当前任务的紧迫度（用于权衡 ST 的容量上限）。

`MemoryConsolidate()` 把 ST 中 `age > τ_high` 且 `priority` 较低的条目下沉到 LT；`MemoryForget(scope, age)` 则以指数衰减函数 `w(age) = exp(-λ · age)` 裁剪长期未被访问的条目。这两个动作使得 LT/ST 形成"双向流动"——既不会因 ST 无限膨胀拖慢推理，也不会因 LT 写入过频而污染检索质量。

## 5. 实验结果

AgeMem 在五个异构基准上进行了系统评估，覆盖具身家庭任务、文本交互游戏、形式化规划、网格导航、多跳问答五大范式：

- **ALFWorld**：基于 ALFRED 的家庭环境具身任务，要求 agent 在多回合中完成煮饭、清洁等长时程指令；
- **SciWorld**：科学实验类交互环境，涉及化学、物理等步骤推理；
- **PDDL**：经典规划领域定义语言基准，衡量形式化规划能力；
- **BabyAI**：轻量网格导航环境，验证短视野下的指令跟随；
- **HotpotQA**：多跳问答，要求跨段落检索与推理。

**核心结果**：在 `Qwen3-4B-Instruct` 基座之上叠加 AgeMem 训练，平均得分 **54.31%**；与之相比，A-Mem 基线（同一基座 + 5-attribute 隐式 schema + in-context 记忆）仅取得 **45.74%**。AgeMem 相对 A-Mem 取得 **+8.57 个百分点（pp）** 的绝对提升。

| 方法 | 基座模型 | 记忆暴露形式 | 训练方式 | 5 基准平均 |
|---|---|---|---|---|
| A-Mem | Qwen3-4B-Instruct | 隐式（schema） | 无（in-context） | 45.74% |
| **AgeMem** | **Qwen3-4B-Instruct** | **显式（tools）** | **3-stage RL + step-wise GRPO** | **54.31%** |

逐基准来看，AgeMem 在 HotpotQA、ALFWorld 这类长上下文依赖度高的任务上提升尤为明显，验证了 LT/ST 显式分流的必要性；在 BabyAI、PDDL 这类短视野任务上同样保持稳定不衰退，说明 stage-wise 的课程训练并未损害基础能力。

值得一提的是，AgeMem 以 **4B** 级别的参数量击败了若干远大于它的 in-context 方案，揭示了"记忆策略本身也是可以被压缩进参数的知识"这一重要结论——它为推理侧的成本控制提供了新的杠杆。

## 6. 局限与未来工作

尽管 AgeMem 在五个基准上取得了 8.57 pp 的稳定提升，作者亦坦率承认若干尚未解决的问题：

第一，**训练成本**。三阶段渐进式 RL 叠加 step-wise GRPO 意味着需要在每一步都采样 `G` 条候选轨迹，计算开销随任务长度近似线性增长，这在大规模 agent 部署中会成为显著瓶颈。

第二，**跨域泛化**。实验仅在五个固定基准上验证，对于训练阶段未见的工具集合、新颖的环境动力学，AgeMem 是否仍能保持 step-wise 的精细调度，尚待进一步考察。

第三，**人类反馈的整合**。当前的 reward 完全来源于任务成功率（task success），尚未引入人类偏好信号（RLHF / RLAIF）。在 LT 写入与遗忘这类语义敏感的动作上，人类反馈可能会进一步提升策略的可解释性与安全性。

未来工作的可能方向包括：把训练范式迁移到更大的基座（如 32B、70B），引入工具调用轨迹的合成数据蒸馏，以及探索 step-wise GRPO 与 process reward model（PRM）的耦合。

## 7. 工程解读

作为 AetherCode 项目长期跟踪 agent 记忆子系统的工程师，本文提出的三项核心思想与我们既有的 17 个 Tier-3 兼容实现形成了高度可对接的映射。

**第一，记忆即工具（Memory as Tools）。** AetherCode 现有的 `MemoryTools`（Java class）已经把读写、检索、衰减操作封装为可注入 Spring Bean 的工具对象，这与 AgeMem 的设计哲学完全一致。下一步可在 `aethercode-memory` 模块下新增 `MemoryManagementTool`（论文兼容候选类），把当前的 `MemoryWrite / MemoryRead / MemoryConsolidate / MemoryForget` 四个原子动作以 Function Calling 接口的形式暴露给上层 agent 框架，使 LLM 推理层能像调用 `Search` 一样显式触发记忆操作。

**第二，LT/ST 联合调度。** 当前的 `LayeredMemoryStore` 已经实现 LT/ST 分层存储与按 TTL 衰减，但"何时 consolidate、何时 forget"的策略仍是人工编写的规则。论文提示我们：这条规则完全可以由 GRPO 学得。建议在 `aethercode-memory` 中新增 `LongShortMemoryScheduler` 类（论文兼容候选），它接收当前 `(scope, op, item, age, priority)` 五元组，输出调度决策，并通过 `MemoryReward` 模块以任务成功率为信号做策略迭代。

**第三，逐步优化（Step-wise Optimization）。** AetherCode 已有的 `SelfCorrectionLoop` 在每一步推理后都会触发一次自检——这恰是 step-wise 思想的一个实例。但我们目前停留在"规则式自检"，尚未引入 RL 优化。论文中 step-wise GRPO 的形式化（`\hat{A}_t^{(i)}` 的组内归一化、`r_i(θ)` 的重要性采样）可以直接复用到 `SelfCorrectionLoop` 的自检决策中，使其从一个硬编码的"反思模板"升级为可学习的策略。

**落地优先级建议**。三件事中，"Memory as Tools"的代码改造量最小、收益最确定，应排在第一优先级；"LT/ST 联合调度"次之，需要新增约 200 行 Java 代码并接入向量库索引；"3-stage RL 训练"是缺口最大的一项——AetherCode 整体偏向 inference-time 工程，缺少完整的 RL 训练管线。建议先以离线日志为数据源，蒸馏一个 teacher policy，再以 step-wise GRPO 微调 4B / 7B 级别的基座，作为短期可交付物；中长期则需在 MLOps 平台中接入 vLLM-serve 与 ray train，把训练与部署拼成闭环。

值得一提的是，AetherCode 中的 `ByzantineDetector`、`RetrievalBandit`、`GlobalPlan` 等 Tier-3 实现都已经在"分阶段、逐步细化"这条主线上做过类似的工程取舍。AgeMem 进一步以学术论文的形式给出了这套思想的训练侧答案，为我们后续把 RL 引入 inference-time agent 框架提供了直接可参考的对照实验。

## 8. 译者后记

作为本篇论文的译者和 AetherCode 项目内部"46 篇 agent 论文综述"的责任编辑之一，我倾向于把 AgeMem 定位为**记忆管理范式从"提示工程"走向"训练工程"的一座里程碑**。它并未发明全新的网络结构或损失函数，而是把早已存在的 GRPO、Toolformer、curriculum RL 三件套以一种极具针对性的方式拼装到了 LT/ST 联合调度这一具体问题上，并以 8.57 pp 的稳定提升验证了"记忆显式化 + 训练端到端化"的双重价值。

在 46 篇综述的坐标系里，AgeMem 与 A-Mem（R-paper-batch3）形成了一对天然的对照组：前者代表"显式 + 训练"路线，后者代表"隐式 + in-context"路线。两者共享同一组基准、同一族 LLM 基座、同一组超参搜索预算，这种"对照实验式"的对照关系在综述写作中尤为珍贵。

对读者的阅读建议是：第一遍先读 §4 的方法描述，特别是 step-wise GRPO 的目标函数 `\mathcal{J}_{\mathrm{GRPO}}(\theta)`，体会"优化粒度下沉到每个记忆决策步"这一核心创新；第二遍回到 §5 的实验结果，思考 8.57 pp 的提升在哪些任务上贡献最大、在哪些任务上几乎为零，由此反推 LT/ST 调度的真实瓶颈所在；第三遍则把目光放到 §7 的工程映射，看看哪些思想可以立即在 AetherCode 中落地，哪些必须等到 MLOps 管线完善之后才有可能。

总而言之，AgeMem 不是一篇"颠覆性"论文，但它是一篇**指向性极强**的论文——它清晰地告诉我们：当 agent 的记忆管理被升格为一等公民，记忆策略本身就能成为被训练、被评估、被工程化的对象。这正是 AetherCode 在 Tier-3 实现层面一直试图走通的方向。
