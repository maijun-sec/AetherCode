# 摘要：超越任务完成 (Beyond Task Completion — Agentic AI 评估框架)

> **原文**: *Beyond Task Completion: An Assessment Framework for Evaluating Agentic AI Systems*
> **作者**: Sreemaee Akshathala, Bassam Adnan, Mahisha Ramesh, Karthik Vaidhyanathan, Basil Muhammed, Kannan Parthasarathy (6 作者, IBM Research 等)
> **来源**: arXiv:2512.12791v1 (cs) [Submitted on 14 Dec 2025, latest 16 Dec 2025 v2]
> **原文链接**: https://www.arxiv.org/abs/2512.12791v1
> **PDF**: `reference/papers/2512.12791-beyond-task-completion.pdf` (1.3 MB)

## 一、核心问题

现有 Agentic AI 评估**只看二元 task completion**, 忽略了 LLM 系统的**非确定性**。作者提出必须看更多维度: 工具调用能力、记忆存取、多 agent 协作、环境交互。

## 二、4 维评估框架 (Agent Assessment Framework)

| 维度 | 子能力 | 跟 AetherCode 已有 |
|---|---|---|
| **LLM** | 推理 / 规划 / 自我纠错 / 提示响应 | R-eval-1, R-eval-4, R-sdk-1, R-sdk-2, R-sdk-8 |
| **Memory** | episodic / semantic / procedural 存取 | R-eval-2, R-sdk-3 |
| **Tools** | 工具选择 / 参数 / 多 tool 链 / canary | R-eval-3, R-eval-10, R-eval-12, R-sdk-4, R-sdk-5, R-sdk-16 |
| **Environment** | 协议 (JSON-RPC, A2A) / 安全 / cost | R-eval-6, R-eval-7, R-eval-8, R-eval-9, R-eval-11, R-sdk-4, R-sdk-6, R-sdk-7 |

## 三、关键发现 (CloudOps 用例)

在 Autonomous CloudOps 场景验证:
- **二元 task completion** metric 漏掉了**行为偏差**
- 同一个 prompt, 不同 run 行为不一致 (call sequence / tool selection / 错误模式)
- **必须评估分布**而非仅平均

## 四、对 AetherCode 的启示

### 已对齐 ✅

我们的 R-eval + R-sdk 双层架构**天然覆盖 4 维**:
- 35 个 R-eval self-contained test 验证 capability
- 121 个 R-sdk 真 class 验证 SDK 实现
- 28 个 R-eval/sdk 9-12 (R-eval-9 Robustness + R-eval-10 MultiTool + R-eval-11 Loop + R-eval-12 Canary) 验证**行为偏差**

### 缺 ❌

**缺一个顶层 AgentAssessmentFramework 入口**:
- 输入: 一次 agent run
- 输出: 4 维评分 (LLM / Memory / Tools / Environment), 每维 0-1
- 支持 percentile / variance / 跨 run 行为对比

## 五、兼容实现计划 (R-eval-14)

### 5.1 AgentAssessmentFramework 主类
```java
class AgentAssessmentFramework {
    AssessmentReport assess(AgentRun run);
    // 4 维 metric: llmScore / memoryScore / toolsScore / envScore
    // 每维 0.0-1.0 + 原始 metric
    // 跨 run 行为分布 (variance)
}

record AssessmentReport(
    double llmScore, double memoryScore, double toolsScore, double envScore,
    Map<String, Double> subMetrics, // 详细 metric
    double variance,                // 跨 run 行为方差
    String worstRun,                // worst-case run id
    String bestRun                   // best-case run id
)
```

### 5.2 4 维 Metric 计算
- **LLM**: planning 成功率 + reflection 成功率 + self-correction 收敛
- **Memory**: episodic 检索 + procedural 复用 + forgetting 触发
- **Tools**: tool 选择准确率 + 参数 mapping + 多 tool 链 + canary rejection + recovery rate
- **Environment**: JSON-RPC 错误率 + 权限违规率 + cost variance + 错误传播因子

### 5.3 跨 Run 行为分布
- Variance (paper 2601.01743 §5.5)
- Worst-case vs best-case run
- 行为聚类 (用 hash(action_sequence))
