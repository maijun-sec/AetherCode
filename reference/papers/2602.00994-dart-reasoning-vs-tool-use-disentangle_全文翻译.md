## 三、背景与动机

近年来,基于大语言模型(LLM)的智能体(Agent)研究在检索增强问答(Retrieval-Augmented QA, RAG)、自然语言转结构化查询(NL2SQL)、多轮工具调用等任务上取得了显著进展。为了让 LLM 同时具备"思考"与"动手"两种能力,业界主流做法是 **Agentic RL(Agentic Reinforcement Learning,智能体强化学习)**:在统一模型上联合训练推理轨迹(reasoning trace)与工具调用(tool invocation)决策。这种"端到端联合训练"范式被普遍认为优于显式拆分,因为它允许模型在两种能力之间共享表征、协同优化。

然而,本论文的核心观察是:**这种假设在大多数基准上并不成立**。作者团队引入了一个名为 **Capability Effect Attribution(CEA,能力效应归因)** 的量化诊断工具,用于衡量同一训练步骤中,推理能力与工具能力各自对损失函数(loss function)及其梯度的贡献。CEA 分析揭示了一个反复出现的现象:**两能力往往诱导出方向不一致的梯度(misaligned gradient)**,从而产生 **training interference(训练干扰)**——模型在一项能力上的进步会以牺牲另一项能力为代价。

从优化理论角度看,这等价于多任务学习(multi-task learning)中的 **梯度冲突(gradient conflict)** 现象:不同任务的梯度向量在参数空间中形成钝角甚至反向,简单相加会相互抵消甚至恶化。当这一现象发生在 LLM 智能体的两个最核心子能力上时,联合训练便不再是"1+1≥2",而是"1+1≤2"。更糟的是,**没有 CEA 这类诊断工具时,从业者很难察觉**——他们只会看到模型整体指标先升后饱和,却无法定位饱和的真正原因是能力互相抵消。

由此引出本文的根本动机:**是否存在一种"轻量级"参数方案,在共享同一个 LLM 主干(shared LLM backbone)的前提下,既能避免完全双智能体(2-Agent)的部署成本,又能彻底切断两能力间的梯度耦合?** DART 正是对这一问题的回答——它既不需要堆叠两个独立模型,也不需要引入复杂的路由网络,而是借用了已经在 LLM 微调中成熟的 **LoRA** 适配器机制,把它们当作"能力隔离舱"来使用。

## 四、核心方法

DART 的总体框架极为简洁,其核心思想可以用如下结构表达:

```
        ┌──────────────────────────────┐
        │   shared LLM backbone (frozen / trainable) │
        └──────────────────────────────┘
                       │
            ┌──────────┴──────────┐
            ▼                     ▼
   ┌─────────────────┐    ┌─────────────────┐
   │ reasoning LoRA  │    │ tool-use LoRA   │
   │  (ΔW_r, rank=r) │    │  (ΔW_t, rank=r) │
   └─────────────────┘    └─────────────────┘
            │                     │
            ▼                     ▼
   ┌─────────────────┐    ┌─────────────────┐
   │ reasoning forward│    │ tool-use forward │
   │   loss: L_r      │    │   loss: L_t     │
   └─────────────────┘    └─────────────────┘
            │                     │
            └──────────┬──────────┘
                       ▼
            gradient: ∂L_r/∂ΔW_r   ⊕   ∂L_t/∂ΔW_t
                 (独立,不交叉)
```

具体而言,DART 的方法学包含以下三层:

**第一层:能力解耦的参数化(Decoupled Parameterization)**。 令共享 LLM 主干的参数为 θ(通常以预训练权重形式初始化),推理 LoRA 与工具调用 LoRA 分别是低秩矩阵对 ΔW_r = A_r B_r 与 ΔW_t = A_t B_t,其中 A∈ℝ^{d×r}、B∈ℝ^{r×d}、秩 r≪d。这与 **LoRA(Hu et al., 2021)** 的标准定义完全一致。关键差异在于:DART **显式约束**——任何与"推理语义"相关的训练 token(例如 Chain-of-Thought、中间规划步骤、答案生成)只触发推理 LoRA ΔW_r 的激活与梯度计算;任何与"工具协议"相关的训练 token(例如 `<tool_call>{...}</tool_call>`、参数填充、返回结果解析)只触发工具调用 LoRA ΔW_t 的激活与梯度计算。

**第二层:分离的前向传播与损失(Separated Forward Pass & Loss)**。 对一个 batch 内的样本,DART 不是把 reasoning tokens 和 tool tokens 一起送入模型求一次总损失,而是构造**两条独立的前向路径**:
- **推理前向(Reasoning Forward)**:输入上下文关闭工具 LoRA,仅激活 ΔW_r,得到 logits θ_r = (θ + ΔW_r)x,据此计算推理损失 L_r(典型形式为 token 级别的交叉熵 $-\sum_t \log p_\theta(r)(y_t | x_{<t})$);
- **工具前向(Tool-Use Forward)**:输入上下文关闭推理 LoRA,仅激活 ΔW_t,得到 logits θ_t = (θ + ΔW_t)x,据此计算工具损失 L_t(类似地为 $-\sum_t \log p_\theta(t)(y_t | x_{<t})$)。

两条前向路径**互不依赖**,因此 L_r 与 L_t 的梯度分别只作用于 ΔW_r 与 ΔW_t,**在反向传播阶段不会发生任何相加**,这就从根本上消灭了 misaligned gradient 的来源。形式化地,联合训练的参数更新为 Δθ ∝ ∂L_r/∂θ + ∂L_t/∂θ,二者可能方向冲突;DART 的更新为 ΔW_r ∝ ∂L_r/∂ΔW_r、ΔW_t ∝ ∂L_t/∂ΔW_t,**没有任何共享方向**。

**第三层:Capability Effect Attribution(CEA)诊断**。 CEA 是 DART 论文中提出的配套分析工具,而非训练机制。其核心公式可表达为:

$$
\text{CEA}_i = \left\| \frac{\partial \mathcal{L}_i}{\partial \theta} \right\| \cdot \cos\!\left(\frac{\partial \mathcal{L}_i}{\partial \theta},\; \frac{\partial \mathcal{L}_j}{\partial \theta}\right)
$$

其中 i、j∈{reasoning, tool-use}。该项同时刻画了**梯度幅值**与**梯度方向一致性**,从而能够量化"两能力在某次更新中是协同还是冲突"。CEA 既可作为训练前的预警指标,也可作为训练后的归因报告。

下表给出 DART 与三类基线方案的对比:

| 方案 | 共享主干 | 参数耦合 | 推理-工具梯度 | 部署成本 |
|---|---|---|---|---|
| Joint Baseline | ✅ | 强耦合 | ∂L_r/∂θ + ∂L_t/∂θ,可能冲突 | 1× 模型 |
| 2-Agent Upper Bound | ❌ | 完全解耦 | 独立反向传播 | 2× 模型 |
| **DART** | ✅ | LoRA 级解耦 | ∂L_r/∂ΔW_r ⊕ ∂L_t/∂ΔW_t | 1× 模型 + 2× 小 LoRA |

可见,DART 在保留单模型部署成本优势的同时,获得了接近 2-Agent 上限的训练隔离性。

## 五、实验结果

论文在 **13 个基准**(benchmarks)上对 DART 进行系统评估,任务类别涵盖 **检索增强问答(retrieval-augmented QA)** 与 **自然语言转 SQL(NL2SQL)** 两大典型 Agentic 场景。基线包括:

- **Joint Baseline**:传统的联合训练范式(单一 LoRA 或全参数微调);
- **Ablations**:包括单 LoRA、轮换式冻结(alternating freezing)、共享 LoRA + 不同 head 等多种变体;
- **2-Agent Upper Bound**:完全独立的两个模型分别训练,作为"理论上界"。

**主要结果**:

1. **联合基线全面饱和**:在 13 个 benchmark 中的大多数上,joint baseline 在训练步数增加时,单项指标曲线很快进入平台期,部分指标甚至出现明显回落,印证了 training interference 的存在。

2. **DART 全面超越 joint baseline**:在 13 个 benchmark 中,DART 的最终得分均高于对应的 joint baseline,平均相对提升在论文报告的数值区间内。该结果在不改动数据、不改动主干的纯架构改动下取得,验证了"梯度隔离即收益"的假设。

3. **逼近 2-Agent upper bound**:DART 与完全独立的 2-Agent 方案在多数任务上的差距在 1–3 个百分点之内,且 DART 只需要单模型部署,**实际工程性价比显著优于 2-Agent**。

4. **简单改动即可生效**:论文通过消融实验说明,即便 LoRA 秩 r 较小(如 r=8、r=16),DART 也能稳定获得提升,说明该方案的收益并非来自容量提升,而是来自**梯度的去耦合**。

5. **CEA 与性能的相关性**:具备较高 CEA 一致性的训练步,与下游指标的提升呈现明显正相关,说明 CEA 不仅可解释,且具备预测能力。

此外,论文展示了在长程多轮工具调用(multi-turn tool use)任务中,DART 的稳定性显著优于 joint baseline——后者容易出现"推理漂移"或"工具格式错乱"等退化模式,而 DART 通过能力隔离,使两类失败模式的发生率同时下降。

## 六、局限与未来工作

作者在文末坦诚地讨论了若干局限:

- **依赖于清晰的 token 归属**:DART 假设 reasoning tokens 与 tool-use tokens 可以被精确切分,若数据集中两类 token 高度交织(例如推理中内嵌 JSON 工具调用片段),切分噪声会侵蚀梯度隔离的纯度;
- **LoRA 容量上限**:当 r 极小时,DART 的表达能力受限;反之,若将两 LoRA 扩成完全独立的 FFN,又会退化为 2-Agent 方案;
- **诊断工具 CEA 的计算开销**:逐 batch 的梯度投影与余弦计算在大规模训练中并非可忽略;
- **未覆盖的模态**:实验集中在文本+工具场景,**多模态工具(如 vision API、speech API)的解耦效果仍是开放问题**;
- **未来方向**:作者提出可结合 Mixture-of-Experts(MoE)路由、动态能力切换(context-aware switching)等机制,进一步提升灵活性;也可探索把 CEA 推广到 RLHF / DPO 等偏好对齐场景。

## 七、工程解读(AetherCode 视角)

将 DART 的思想映射到工业级 Agent 框架 **AetherCode** 时,首要观察是:**AetherCode 偏推理期(inference-time)架构,而 DART 偏训练期(training-time)优化**,两者在抽象层面高度同构,但落地路径不同。下面给出"论文观点 → AetherCode 模块 → 兼容实现"的三层映射:

| 论文观点 | AetherCode 对应模块 | 实现状态 |
|---|---|---|
| Reasoning / tool-use capability 分离 | `Verifier`(负责 reasoning) + `StandardTools`(负责 tool) | ✅ 模块已分 |
| LoRA-style 参数解耦 | 当前模型无关、推理期不训练 | N/A(inference-only) |
| CEA 量化 capability effect | R-eval 全覆盖(独立测各项 capability) | ✅ 已有覆盖 |
| Training interference 概念 | Self-correction intra vs inter 反射(R-radar-7) | ✅ 类比已存在 |
| 解耦优于 2-Agent | 单 backbone + 角色化执行器 | ✅ 设计哲学一致 |

具体到 AetherCode 的 17 个 Tier-3 兼容实现:

- **`GlobalPlan`** 与 **`ByzantineDetector`**:前者负责全局 reasoning 编排,后者负责"工具调用一致性"的判定——这一分工天然契合 DART 的 capability 分离思想。可以引入 **路由层** 把 reasoning step 路由到 `GlobalPlan`,把 tool step 路由到 `ByzantineDetector` 或 `StandardTools`,实现 inference 期的"软解耦"。
- **`RetrievalBandit`**:作为工具调用层组件,可被视为 DART 中 tool-use LoRA 的功能等价物。其内部的 retrieval action space 设计可借鉴 CEA 的归因思路,加入 capability attribution 报告。
- **`R-radar-7` 反射机制**:该机制已对 intra(单能力内)与 inter(能力间)反射做了区分,完全可承载 DART 提出的"两类梯度是否对齐"的诊断结论,只需把"梯度"替换为"决策路径偏移"。
- **`Verifier`** 体系:推理侧验证器与工具侧验证器在 AetherCode 中已物理分离,这是 DART 思想在 inference 期的天然落点。

**可以立即落地的下一步**:

1. 新增 `CapabilityInterferenceMetric`(位于 `evals.capability` 包),量化 reasoning 与 tool-use 决策路径之间的相互影响,作为 CEA 的 inference-time 等价物;
2. 新增 `DisentangledExecutor`(位于 `orchestration.executor` 包),把 reasoning step 与 tool step 显式路由到不同的执行器,使推理链与工具链在系统层面物理分离;
3. 新增 `CEAReport`(位于 `evals.attribution` 包),输出 capability attribution 分析报告,服务调试与回归测试;
4. 在 AetherCode 的 Tier-3 兼容实现集中,把 DART 的 capability 分离原则纳入接口契约文档,作为后续实现的"软规范"。

值得强调的是:**DART 并不要求 AetherCode 进入训练期**。它更核心的贡献是**一种"能力分离优于能力耦合"的设计哲学**——这一哲学,无论在训练侧还是推理侧,都是普适的。

## 八、译者后记

作为 AetherCode 论文综述(46 篇)中的一篇,DART 处于"训练机制 → 推理架构"过渡带的典型位置。它**没有提出惊人的新算法**,而是给出了一个反直觉却扎实的事实:**把 LoRA 拆成两份,就能在 13 个 benchmark 上稳定战胜联合训练**。这种"小改动,大收益"的范式,在工程上往往最具传染力。

在 46 篇综述的坐标系中,DART 的定位可以概括为:**面向 Agentic 训练的能力隔离范式**。它向上承接多任务学习中的梯度冲突理论,向下对接工业级 Agent 框架的模块化设计——AetherCode 的多 Tier 架构、R-radar 反射、GlobalPlan/ByzantineDetector 分工,都可视为 DART 思想在不同抽象层的回响。

**对读者的阅读建议**:

- 若关注训练机制:精读 CEA 章节,把它的公式迁移到自己的多任务场景中;
- 若关注工程落地:跳过训练细节,直接读第 4、5 章的解耦思想,结合"工程解读"一节在 AetherCode 中复现;
- 若关注综述脉络:把 DART 与同期的 RLHF、DPO、Process Reward Model 等工作对照阅读,可看清"能力解耦"在 LLM 后训练(alignment)整体版图中的位置。

总体而言,DART 是一篇**"以小见大"的工程友好型论文**——它用极简的改动揭示了 Agentic RL 中一个长期被忽视的问题,值得每一位做 Agent 框架的工程师与研究者驻足。
