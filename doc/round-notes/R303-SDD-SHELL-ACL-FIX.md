# R303 — SDD Tauri shell ACL grant + friendly spawn-error UX

**Date**: 2026-09-21
**Round**: R303 (post-R302 user verification)
**Author**: Mavis (mavis)

## TL;DR

After R302 refilled `daemonInfo` and pointed `startSsdFlow` at
`get_app_paths`, the renderer finally wired `TauriSsdDriver`. But the
subprocess never spawned — the Tauri shell plugin's `Command.spawn()`
rejected with:

```
Command plugin:shell|spawn not allowed by ACL
```

The default `src-tauri/capabilities/default.json` only granted
`dialog` + `core:*` defaults. The shell plugin's spawn / stdin_write
/ kill / execute permissions were never listed. The driver choice
card rendered correctly, the catch handler dumped the raw Tauri error
into a "SDD spawn failed" system card — technically accurate, very
unfriendly.

**Fix (2 parts)**:

1. **`src-tauri/capabilities/default.json`**: add `shell:default` +
   `shell:allow-spawn` + `shell:allow-stdin-write` + `shell:allow-kill`
   + `shell:allow-execute`. The desktop can now spawn the JVM, write to
   its stdin (per-phase accept/revise), and kill it on teardown.

2. **`src/store/index.ts`**: a module-scope `friendlySddSpawnError`
   translator maps the raw Tauri errors into actionable Chinese
   user-facing messages. Covers: ACL denial (with self-reference to
   R303), `ENOENT` on `java`, jar missing, `NEEDS_CWD`, generic
   fallback. The catch handler also writes
   `[R303-sdd-spawn-failed]` to `%TEMP%\aethercode-desktop-daemon-info.log`
   so future regressions keep a paper trail. Raw error stays visible
   under a collapsed `<details>` block.

**Verification**: 1200 desktop tests pass (up from 1194, +6 R303
source-pin). Build clean (Tauri 3m21s). exe 6.55 MB / NSIS 55.05 MB /
MSI 56.77 MB. Commit `273d864` pushed to `origin/main`.

## Background

### Symptom

User restarted the R302 build, opened SDD on a project folder. The
driver choice card rendered correctly (showed `--interactive`, the
full command line, the R299 explanation). But the subprocess never
spawned — the chat stream showed:

```
📐 **SDD spawn failed**

```
Command plugin:shell|spawn not allowed by ACL
```

Check the desktop logs ($TEMP/aethercode-daemon-port*.log) for the spawn trace.
```

User feedback: "好像死了，而且输出也非常不友好" ("It seems dead, and the output
is also very unfriendly").

### Root cause

`@tauri-apps/plugin-shell` 2.x gates every command by an ACL declared
in `src-tauri/capabilities/*.json`. Pre-R303, `default.json` granted:

```json
"permissions": [
  "core:default",
  "core:event:default",
  "core:window:default",
  "core:webview:default",
  "dialog:default"
]
```

That covers OS dialogs + core IPC, but NOT shell plugin commands.
`Command.spawn()` (used by `TauriSsdDriver`) checks the
`shell:allow-spawn` permission — without it, the JS-side Promise
rejects with the ACL string and the catch handler renders it as-is.

The shell plugin's permissions live in
`tauri-plugin-shell-2.3.6/permissions/autogenerated/commands/*.toml`
and ship as `shell:allow-spawn`, `shell:allow-stdin-write`,
`shell:allow-kill`, `shell:allow-execute`. `shell:default` only
includes `allow-open` (for `shell.open()` — opening URLs in the
default browser). Spawn needs an explicit grant.

### Why this slipped through R293-R302

R293 introduced `TauriSsdDriver` using
`@tauri-apps/plugin-shell`'s `Command` class. The first round shipped
worked because the desktop dev-mode used `@tauri-apps/cli`'s debug
profile, which often runs in a more permissive capability mode than
release builds. The user has been on release builds (NSIS / MSI
bundles) since R294, so the ACL has been blocking the spawn path
from the very first R293 retest — every user-visible failure since
R293 was actually a `Command.spawn() → ACL reject`, but the catch
handler at the time was a no-op (driver was fire-and-forget until
R298 added the SDD-spawn-failed card) so the rejection was silent.

R298 added the catch handler card. R301 added the
`[R301-sdd-spawn]` log line, but only inside `TauriSsdDriver.start()`
— since the spawn was rejected before `start()` reached its first
log line, the log was always empty for this failure. R302 refilled
`daemonInfo` and confirmed `TauriSsdDriver` was wired. R303 is the
first round where the spawn path executes far enough to hit the
shell plugin's ACL check.

## Fix

### Part 1: shell plugin permissions

`src-tauri/capabilities/default.json`:

```json
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "default",
  "description": "Default capabilities for the AetherCode desktop app",
  "windows": ["main"],
  "permissions": [
    "core:default",
    "core:event:default",
    "core:window:default",
    "core:webview:default",
    "dialog:default",
    "shell:default",
    "shell:allow-spawn",
    "shell:allow-stdin-write",
    "shell:allow-kill",
    "shell:allow-execute"
  ]
}
```

Why each shell permission:

- `shell:default` — base scope (currently only `allow-open`).
- `shell:allow-spawn` — `Command.spawn()` for launching the JVM.
- `shell:allow-stdin-write` — `child.write()` for the per-phase
  accept / revise / skip JSONL lines (R299).
- `shell:allow-kill` — `child.kill()` for `TauriSsdDriver.stop()`
  (called by `setSddEnabled(false)` and the chip close button).
- `shell:allow-execute` — alternate `Command.execute()` API; cheap
  to include and avoids a future ACL round-trip if any other driver
  wants to use it.

### Part 2: friendly error translator

`src/store/index.ts` (module scope, just above `AppState`):

```typescript
function friendlySddSpawnError(raw: string, jarPath: string, cwd: string, slug: string): string {
  // 1. ACL — most common since R293 when TauriSsdDriver started using
  //    @tauri-apps/plugin-shell's Command.
  if (/not allowed by ACL/i.test(raw)) {
    return [
      '📐 **SDD 子进程无法启动 — 桌面权限缺失**',
      '',
      '`TauriSsdDriver` 需要 `@tauri-apps/plugin-shell` 的 `spawn` / '
      + '`stdin_write` / `kill` 权限来启动 `aethercode.jar` 子进程并接收'
      + '你的 ✅ / ✏️ / ⏭️ 指令。当前 desktop 安装包缺少这些权限。',
      '',
      '**解法**：从最新 build 重新安装 desktop ...',
      '',
      '如果已经是最新 build 还报这个错，请贴 `%TEMP%\\aethercode-desktop-daemon-info.log` '
      + '末尾的 `[R303-sdd-spawn-failed]` 行给我定位。',
    ].join('\n');
  }
  // 2. Java missing
  if (/ENOENT|No such file or directory/i.test(raw) && /java/i.test(raw)) {
    return [
      '📐 **SDD 子进程无法启动 — 找不到 Java**',
      // ... actionable text about `java -version` and Settings → Advanced → Java Path
    ].join('\n');
  }
  // 3. Jar missing
  if (jarPath && /jar/i.test(raw) && /not found|missing|exist/i.test(raw)) {
    return [
      '📐 **SDD 子进程无法启动 — 找不到 aethercode.jar**',
      // ... portable vs NSIS / MSI guidance
    ].join('\n');
  }
  // 4. NEEDS_CWD
  if (/NEEDS_CWD/i.test(raw)) {
    return [
      '📐 **SDD 子进程无法启动 — 没有选项目目录**',
      // ... "use the 📁 picker"
    ].join('\n');
  }
  // 5. Generic — show what we know, fall through to raw in details
  return [
    '📐 **SDD spawn failed**',
    '',
    `slug: ${slug || '(none)'}`,
    `jarPath: ${jarPath || '(empty)'}`,
    `cwd: ${cwd || '(empty)'}`,
    '',
    '详细错误见下方 Raw error 折叠块。',
  ].join('\n');
}
```

The catch handler (`Promise.resolve(driver.start()).catch(async (err) => {...})`)
calls the translator, prepends the friendly message to the system
message content, appends the raw error under a `<details>` block, and
writes a `[R303-sdd-spawn-failed]` line to the daemon-info log:

```typescript
const raw = (err as Error)?.message ?? String(err);
const friendly = friendlySddSpawnError(raw, jarPath, cwd, featureSlug);
const content = friendly
  + `\n\n<details><summary>Raw error (show technical details)</summary>\n\n\`\`\`\n${raw}\n\`\`\`\n</details>`
  + `\n\nDiagnostic log: \`%TEMP%\\aethercode-desktop-daemon-info.log\``;
```

## Lessons

- **Lesson 631** (new): **Tauri 2.x plugin commands are ACL-gated by
  default.** `@tauri-apps/plugin-shell` ships permissions
  (`shell:allow-spawn`, `shell:allow-stdin-write`, `shell:allow-kill`,
  `shell:allow-execute`) that must be explicitly listed in
  `src-tauri/capabilities/*.json`. The default `shell:default` only
  grants `allow-open` for `shell.open()`. Without explicit grants,
  `Command.spawn()` rejects with `Command plugin:shell|<cmd> not
  allowed by ACL`. Diagnostic tip: any "Command plugin:<x>|<y> not
  allowed by ACL" error means the capability file is missing the
  matching `x:allow-y` permission.
- **Lesson 632** (new): **Always surface raw errors under a collapsed
  detail block, even after translating them.** The friendly translator
  is for human action; the raw string is for debugging. The user
  complained about unfriendly output, but a future regression might
  need the raw Tauri error to diagnose. R303's catch handler always
  appends `<details><summary>Raw error</summary>...` + points at
  `%TEMP%\aethercode-desktop-daemon-info.log` so future maintainers
  (and Mavis) have the full context.
- **Lesson 633** (new): **GitHub HTTPS port 443 has gone flaky
  again.** Multiple transient "Failed to connect" / "Recv failure:
  Connection was reset" across R302 and R303 pushes. The fix is the
  same as R302's Lesson 630: back off 30s + retry. Both commits
  eventually went through (R302 = `a2b5ee7`, R303 = `273d864`).
