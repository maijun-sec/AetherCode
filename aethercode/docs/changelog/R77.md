# R77 — Metrics endpoint

**Date**: 2026-08-09
**Status**: DONE (9 Java tests + 10 TUI tests + 1 E2E, all pass)

## What it adds

Users previously had no way to see engine activity beyond the
per-turn cost in the status bar. R77 adds a `/metrics` command that
prints a snapshot of every engine counter:

```
engine metrics
  uptimeMs           8947
  turnsStarted       1
  turnsCompleted     1
  toolCalls          1
  toolErrors         0
  toolRetries        0
  loopStops          0
  permissionAsks     0
  permissionDenies   0
  cacheHits          0
  cacheMisses        0
  costUsd            $0.012
  errorRate          0.0%
  cacheHitRate       0.0%
```

## Implementation

### Backend (Java)

- **`aethercode-core/src/main/java/org/aethercode/core/metrics/MetricsCollector.java`**
  - 11 `AtomicLong` counters (turnsStarted, turnsCompleted, toolCalls,
    toolErrors, toolRetries, loopStops, permissionAsks, permissionDenies,
    cacheHits, cacheMisses) + `costUsd` (double) + 2 derived ratios
    (errorRate, cacheHitRate).
  - Thread-safe (8 threads × 1000 inc concurrent test in
    `MetricsCollectorTest`).
  - `snapshot()` returns a `Map<String, Object>` copy (the caller
    can mutate it freely).

- **`AetherCodeEngine.metrics()`** — accessor for the per-engine
  collector. Set in the constructor.

- **`AetherCodeMethods.getMetrics(Object)`** — new RPC. Returns
  `engine.metrics().snapshot()`.

- **`AetherCodeMethods.query()`** — wire-up: as `StreamEvent`s flow
  through `forEach`, increment the relevant counter:
  - `ToolUseStart` → `incToolCall()`
  - `ToolResult.isError()` → `incToolError()`
  - `RunEnd` → `incTurnCompleted()` + `incLoopStop()` if
    `stopReason.startsWith("loop")`

- **`AetherCodeMethods` `registerAll`** — added
  `dispatcher.register("getMetrics", this::getMetrics)`.

### TUI (TypeScript)

- **`/metrics` slash command** — dispatches `rpcMethod: "getMetrics"`.

- **`tui.tsx` rpcMethod handler** — special-cases `getMetrics` to
  pretty-print: percentages with `%` suffix, `costUsd` with `$`
  prefix, other fields left-aligned with `padEnd(18)`. Other RPCs
  still get the plain JSON dump.

- **`SLASH_COMMANDS`** — added `"metrics"`.

## Pitfalls (and how to avoid them next time)

### 1. `mvn package` doesn't rebuild `dist/aethercode-0.2.1.jar`

The first time I ran the E2E, the jar was from `8/8 23:52` — before
R77 was added. `mvn clean install` and `mvn package` both left the
dist jar untouched.

**Fix**: use `build.ps1 -SkipTests` (which uses `maven-shade-plugin`
with explicit `finalName=0.2.1`). The dist jar then updates to
`8/9 8:39:40` with the new `getMetrics` method.

**Documented in**: `dev-guide/adding-rounds.md#6-build-30-seconds`.

### 2. NaN guard in ratio math

A fresh daemon has `cacheHits = 0, cacheMisses = 0`. The naive
`hits / (hits + misses)` gives `0 / 0 = NaN`. Jackson serialises
NaN as `null` by default, which broke the E2E (the test was
checking for numeric fields, got `null`).

**Fix**: `ratio(n, d) = d <= 0 ? 0.0 : (double) n / (double) d`.

**Documented in**: `state-model.md#common-pitfalls-when-adding-state`.
