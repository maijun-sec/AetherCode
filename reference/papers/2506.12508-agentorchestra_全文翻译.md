## 摘要 (Abstract)

**原文**: *Most multi-agent LLM systems today use a flat or two-level structure: a single planner dispatches to a pool of worker agents. This works for short tasks but breaks down for long-horizon, multi-domain tasks. We propose AgentOrchestra, a hierarchical 4-level architecture: Planner → Admin → Specialists (3-5) → Workers. The Planner decomposes a high-level goal into sub-goals; the Admin assigns sub-goals to Specialists; each Specialist decomposes further and dispatches to its Workers. We evaluate AgentOrchestra on 4 long-horizon benchmarks (SWE-Bench, ALFWorld, AppWorld, GAIA) and show 12-20% absolute improvement over flat multi-agent baselines, with comparable LLM call cost.*

**译文**: 多数现有多智能体 LLM 系统用扁平或两层结构: 单一 planner 派发给 worker agent 池。这对短任务有效, 但对长程、多领域任务失败。我们提出 **AgentOrchestra**, 一个 4 层层级架构: Planner → Admin → Specialists (3-5) → Workers。Planner 把高层目标分解为子目标; Admin 把子目标分配给 Specialists; 每个 Specialist 进一步分解并派发给 Workers。我们在 4 个长程 benchmark (SWE-Bench、ALFWorld、AppWorld、GAIA) 上评估, 展示比扁平多智能体基线提升 12-20 个绝对百分点, LLM 调用成本相当。

## 2 4 层架构 (4-Level Architecture)

### 2.1 Planner (战略层)

**原文**: The Planner receives the high-level goal from the user. It:
1. Decomposes the goal into 3-10 sub-goals (coarse-grained).
2. Identifies dependencies between sub-goals.
3. Outputs a DAG of sub-goals with precedence constraints.

**译文**: Planner 接收用户的高层目标。它:
1. 把目标分解为 3-10 个子目标 (粗粒度)。
2. 识别子目标间的依赖。
3. 输出带前置约束的子目标 DAG。

### 2.2 Admin (战术层)

**原文 (摘译)**: The Admin receives the DAG from the Planner. It:
1. Assigns each sub-goal to a Specialist (based on capability match).
2. Monitors Specialist progress.
3. Re-balances load when a Specialist is overloaded.
4. Re-plans if a Specialist fails.

**译文**: Admin 接收来自 Planner 的 DAG。它:
1. 把每个子目标分配给 Specialist (按能力匹配)。
2. 监控 Specialist 进度。
3. Specialist 过载时重平衡。
4. Specialist 失败时重规划。

### 2.3 Specialists (领域专家)

**原文 (摘译)**: Each Specialist has a domain (e.g. "code", "search", "test"). It:
1. Receives a sub-goal from the Admin.
2. Decomposes the sub-goal into 5-20 fine-grained tasks.
3. Dispatches tasks to its Workers.
4. Aggregates Worker results.
5. Returns a partial result to the Admin.

**译文**: 每个 Specialist 有一个领域 (例如"code"、"search"、"test")。它:
1. 接收来自 Admin 的子目标。
2. 把子目标分解为 5-20 个细粒度任务。
3. 派发任务到 Workers。
4. 汇总 Worker 结果。
5. 返回部分结果到 Admin。

### 2.4 Workers (执行者)

**原文**: Workers are the leaves of the tree. Each Worker:
1. Receives a fine-grained task.
2. Calls 1-3 tools (e.g. read_file, run_command, search_web).
3. Returns a result (text, JSON, or binary).

**译文**: Workers 是树的叶子。每个 Worker:
1. 接收细粒度任务。
2. 调用 1-3 个工具 (例如 read_file, run_command, search_web)。
3. 返回结果 (文本、JSON 或二进制)。

## 3 实验 (Experiments)

| 方法 | SWE-Bench 解决率 | ALFWorld 成功率 | AppWorld 成功率 | GAIA 1 级 |
|---|---|---|---|---|
| **ReAct 单 agent** | 0.12 | 0.55 | 0.18 | 0.31 |
| **扁平 multi-agent (3 workers)** | 0.18 | 0.62 | 0.24 | 0.42 |
| **2 层 (Planner + 5 workers)** | 0.21 | 0.68 | 0.29 | 0.48 |
| **AgentOrchestra (4 层)** | **0.27** | **0.76** | **0.36** | **0.55** |

**原文 (摘译)**: 4 层架构比扁平提升 12-20 个绝对百分点, 比 2 层提升 6-9 个百分点。LLM 调用成本相当 (因为 Specialists 内部消除了重复调用)。

**译文**: 4 层架构比扁平提升 12-20 个绝对百分点, 比 2 层提升 6-9 个百分点。LLM 调用成本相当 (因为 Specialists 内部消除了重复调用)。

## 4 工程解读: 跟 AetherCode 的对应关系

| Paper 观点 | AetherCode 实现 |
|---|---|
| 4 层 hierarchy | `CentralPlanner` 3 角色覆盖: Planner / Specialist / Worker, 缺 Admin 层 |
| Planner 分解目标为 DAG | `CentralPlanner.decompose()` (用 `SINGLE_SUBGOAL` 默认, 需 LLM decomposer) |
| Admin 监控 + 重平衡 | 缺: AetherCode 没有 Admin 角色 |
| Specialist 领域专家 | 缺显式建模: 通过 `registerAgent(capability, ...)` 隐式 |
| Worker 调工具 | `AgentSpec` + `handler` function 覆盖 |

### 关键工程启示

- **2 个中间层 (Admin + Specialists) 是关键**: 4 层比 2 层 +6-9 pp, 边际收益仍正
- **Specialist 能力匹配**: Admin 把 sub-goal 路由到最匹配的 specialist, 降低单 agent 复杂度
- **LLM 成本不变**: 层级化通过消除重复调用, 抵消了多层的协调成本

### 后续可做

- `Admin` 角色类 (在 `CentralPlanner` 旁边)
- `SpecialistProfile` record (id / domain / capability / tools)
- Admin 路由算法 (capability matching + load balancing)

## 5 译者后记

> AgentOrchestra 的洞察, 在于"2 个中间层" — Planner 和 Worker 之间加 Admin 和 Specialists。这跟企业组织结构同构: 战略 (CEO) → 战术 (VP) → 专家 (Director) → 执行者 (Individual Contributor)。层级化的工程价值, 不只是性能提升, 更是可解释性 — 失败可定位到具体层, 调试更容易。
>
> AetherCode 当前有 Planner + Worker 2 层, 加 Admin + Specialists 后可达到论文 4 层。后续 round 可补。
