## 1. A2A 协议栈

A2A（Agent-to-Agent）模块覆盖同步、HTTP、SSE 流式与 deepagent 桥接四层能力,任一调用方都可以按需选择入口。

### 1.1 协议核心 (aethercode-a2a)

**A2AServer** 进程内 A2A 服务器,实现 v0.3 规范四个 JSON-RPC 方法:

- `message/send` — 同步, 用户消息 → 单个 Artifact
- `tasks/get` — 按 id 返回任务
- `tasks/cancel` — 任务转为 canceled
- `agent/authenticatedExtendedCard` — 返回 AgentCard

流式扩展通过可选 `StreamingHandler` 实现: 为 null 时, `message/sendSubscribe` 退回同步 handler 发出 working / artifact / completed 三段合成流; 装上后, 流式处理器全权拥有事件序列, 必须在返回前发出终态, 供 SSE 传输层关闭响应流。

**A2AHttpTransport** 基于 JDK 内置 `HttpServer` 的 HTTP 传输, 零新增依赖, 与 BankServer 使用同款风格。

路径契约:
- `POST /a2a` — 同步 JSON-RPC
- `POST /a2a/stream` — `message/sendSubscribe` 流式响应, 帧格式 `text/event-stream`
- `GET /.well-known/agent.json` — AgentCard 发现
- 其它路径 404; `POST /a2a` 与 `POST /a2a/stream` 上的非 POST 返回 405, Allow 头在 `sendResponseHeaders` 之前设置

SSE 帧形如 `event: ...\nid: ...\ndata: ...\n\n`, `id:` 是请求内单调计数, 客户端可凭 `Last-Event-ID` 断点续连; 错误事件以 `event: error` 终态发送, 写完一帧后即关闭响应。

**线缆形态**: JSON-RPC 2.0 信封手工拼装, 避免 record + `@JsonInclude(NON_NULL)` 在错误字段缺省时输出非规范字段。

### 1.2 deepagent 桥接 (aethercode-a2a-deepagent-bridge)

**DeepAgentA2AHandler** 把 `DeepAgent` 一次调用包装为 A2A handler, 同一 agent 同时支持同步与流式两种入口。

两个 handler 形态:
- `syncHandler()` — 返回 `Function<Message, Artifact>`, 收集最终文本后丢弃事件流
- `streamingHandler()` — 返回 `A2AServer.StreamingHandler`, 把运行时事件按 A2A streaming 形态逐条推送, 末尾发终态

事件到 A2A 流的映射:
- `BeforeModel` → `status("working", "iter N")`
- `AfterModel` → 若 AI 消息含非空文本, 推送 `artifact(text reply)`
- `ToolDispatch` → `status("working", "tool: name")`
- `Final` → 推送最终 artifact, 末尾 `status("completed", "done")` 收尾

无 chat model 时退化到 stub: 仅产生单条 Final 事件, 流式形态仍完整, 保证线缆格式正确。

独立成模块的设计: 让协议层不直接依赖 deepagent 运行时, 消费者想用其它 agent 接入 A2A 时, 自行提供 `Function<Message, Artifact>` 即可。

### 1.3 aethercode-cli A2A 集成

CLI 新增 A2A 子命令 (`a2a`), 与 A2A HTTP 端点交互:

- `a2a card <url>` — 拉取 AgentCard (`/.well-known/agent.json`) 并打印
- `a2a send <url> "..."` — 同步 `message/send`
- `a2a stream <url> "..."` — 流式 `message/sendSubscribe`, 边收边打
- `a2a get <url> <task-id>` / `a2a cancel <url> <task-id>` — 任务查询与取消

输出: 卡片走表格/JSON, 任务走字段化文本 + JSON 块, 流式逐帧打 `event: ...` 与 `data: ...`。

测试: 7 个新 Java 用例覆盖上述命令 + 错误路径 (404 / 405 / 解析失败)。

## 2. BankClient 缓存层

**CachingBankClient** 是 `BankClient` 的装饰器, 在读侧方法前加 LRU + TTL 缓存, 写侧 (`touch` / `recordOutcome`) 透传并整盘失效。

**设计要点**:
- 选装饰器而非修改 BankClient, 让 BankClient 保持无状态且不感知缓存, 缓存是部署期关注点
- 不需要缓存的调用方 (一次性 CLI / 测试) 可直接拿原始 BankClient
- 线程模型: `synchronized` + accessOrder 的 `LinkedHashMap`, 读 / 写同一锁, 吞吐受 HTTP RTT 限制, 不在锁上
- 线缆形态不变 — 缓存位于 `List<Map<String,Object>>` 边界之下, 命中 / 缺失对外都是同一份 JSON

**容量与过期**:
- `maxSize` LRU 上限, `<= 0` 表示不限数, 但 TTL 仍生效
- `ttl` 条目 TTL, `null` 表示无过期; 读取时检查, 过期按 miss 处理并重取
- `put` 时先淘汰过期条目再检查容量, 避免一过性新条目挤掉刚被读取的长寿条目
- `accessOrder=true` 头部即最久未用, 迭代器 `next()` 返回头, 直接淘汰
- 缓存内容经防御性拷贝返回, 防止调用方改写

**失效策略**: 写方法不知道 unit 属于哪个 kind, 保守地整盘清空; bank 规模小 (默认 1000 条), 全清比追踪 per-kind dirty 便宜。

测试: 9 个用例覆盖命中/失效/LRU/TTL/并发/穿透。

## 3. VLM 多模态工具

工具面新增 `video_understand` 与 `audio_understand`, 与既有 `image_understand` 平行, schema 独立。

### 3.1 接口设计

`VlmClient` 是 VLM 后端的统一契约, 工具层与 agent 循环不关心底层是:
- 进程内 mock (测试用)
- OpenAI 兼容 HTTP 端点 (覆盖 OpenAI gpt-4o、Anthropic claude-3.5-sonnet, 经 OpenAI 网关服务的 Qwen2-VL / InternVL2 等开源 VLM)
- 本地运行时 (Ollama / vLLM)

接口把「推理在哪跑」与「agent 怎么调」正交化。

`Options` 携带 model / maxTokens / temperature 三项, 任何字段后端可忽略。

`understand` / `understandVideo` / `understandAudio` 都有 2 参与 3 参 (`Options`) 两个重载, 默认实现抛 `UnsupportedOperationException` 保持旧 image-only backend 编译期兼容, 运行时才显式告知不支持。

### 3.2 工具形态

**VideoUnderstandTool** `video_understand`:
- schema 接受 MP4 / MOV / WEBM, prompt 描述查询意图
- 走 `VlmClient.understandVideo`, 后端不支持时返回明确错误, 提示 agent 退回到 `image_understand` 取关键帧
- 与 `image_understand` 形态一致, schema 独立, 避免判别式 schema 让模型选错

**AudioUnderstandTool** `audio_understand`:
- schema 接受 WAV / MP3 / OGG / FLAC / M4A
- 音频是三类模态中后端差异最大的, 行为完全由 client 决定
- 与 `video_understand` 配合处理会议录像等场景: 视频流用 video, 音轨对话用 audio

**ImageUnderstandTool** (既有) `image_understand` 形态保持不变, 三者共享同一默认 client 生命周期。

测试: 12 image + 7 video + 6 audio, 共 25 个用例覆盖 build / call / 错误路径 / 后端不支持。

## 4. WorkflowEngine 实战工作流

R250+ 阶段 WorkflowEngine 落地两个日常高负载工作流: `code-review` 与 `migrate-deps`。R241.3 演示性工作流 (tdd-feature / security-audit / add-changelog / explain-failure) 一并保留。

### 4.1 code-review

评审一段代码变更 (diff、分支、工作区未提交内容), 关注死代码、抽象泄露、缺失测试、不安全并发以及 AetherCode 特有模式。产出按文件归类的结构化报告, 每条带严重等级与修复建议。

**输入**:
- `target` (enum: `working-copy` / `branch` / `last-commit` / `diff-file`, 默认 `working-copy`)
- `diff` (string, `target=diff-file` 时必填)
- `base-branch` (默认 `main`)
- `focus` (enum: `all` / `security` / `performance` / `readability` / `tests`, 默认 `all`)
- `max-findings` (int, 默认 20, 0 = 不限)

**输出**:
- `verdict` (enum: `APPROVE` / `REQUEST-CHANGES` / `NEEDS-DISCUSSION`) — supervisor 凭此决定是否合并不必复读报告
- `findings` (list of {file, lines, severity, category, fix})
- `summary` (一段 PR 描述用摘要)

**Skills**: `code-review` + `security-audit-basics`。

### 4.2 migrate-deps

检查项目依赖清单, 提议升级到已知的最新可用版本 (patch / minor / major), 生成迁移补丁。锁定主版本的依赖默认跳过, 需要主版本升级的依赖必须显式列入 `allow-major`。

**输入**:
- `manifest` (enum: `pom-xml` / `gradle-kts` / `gradle-groovy`, 默认 `pom-xml`)
- `scope` (enum: `patch` / `minor` / `major`, 默认 `minor`)
- `exclude` (string, 逗号分隔 `groupId:artifactId` 列表)
- `allow-major` (string, 逗号分隔坐标, 允许主版本升级)
- `dry-run` (boolean, 默认 `true`) — 首次跑必须显示提议不写文件, 安全默认

**输出**:
- `diff` (unified diff 字符串)
- `upgrade-list` (list of {coordinate, from, to, scope, breaking})
- `removed` (list of {coordinate, reason}) — 移除依赖必须列入并说明理由

**Skills**: `maven` + `gradle` + `semver`。

**关键约定**:
- `exclude` / `allow-major` 用逗号分隔字符串 (R-workflow InputDef schema 无 list 类型)
- 永不删依赖而不列入 `removed:` + 理由
- 永不重排依赖, 复用现有顺序保证 diff 可读
- 主版本升级若影响公共 API, 即便不能自动修复也列出调用点

### 4.3 现有 4 个工作流 (R241.3)

| 名称 | 用途 |
|---|---|
| `tdd-feature` | TDD red-green-refactor 循环 |
| `security-audit` | 安全审计 + CWE-tagged findings |
| `add-changelog` | 加 CHANGELOG entry |
| `explain-failure` | 解释 CI 失败 |

6 个工作流覆盖: 测试驱动 + 安全 + 发布 + 调试 + 依赖迁移 + 代码评审。

测试: 8 个新用例 (R250+6 专属) + ShippedWorkflowsTest 动态发现机制 (加新 workflow 不用改测试, 改 list + ship YAML 即可)。

## 5. Desktop UI 底部行修复

底部 `<StatusBar />` 之后挂载的 2 个组件完全无 CSS, 浏览器用默认样式渲染, 跟暗色 + 紧凑的视觉风格脱节。

### 5.1 修复 1: 移除底部 SessionControlDock

Continue / Pause / Stop 三按钮被移除, 理由:
- **Stop 重复** — `MessageInput` 已有 ⏹ 按钮 (流式期间), `Esc` 也能 cancel
- **Pause / Continue 极少用** — 99% 时间 task 是 `running` 或 `idle`, 这两个按钮都是灰的
- **真正的 pause/resume 入口在别处** — Subagent toast + status bar 已有 "Running" pill

`SessionControl` 组件本身仍保留 (含 SessionControl.css), 供未来嵌入式调用场景 (Subagent 提示卡、暂停任务横幅) 使用。

### 5.2 修复 2: 新增 SessionDetailsDrawer.css

抽屉样式:
- `position: fixed; top: 60px; right: 0; bottom: 28px; width: 320px; z-index: 20`
- 锚定在视口右侧、Header 之下、StatusBar 之上, z-index 介于主内容与模态对话框之间
- 宽度 320px 与 Telemetry 面板一致, 两个侧栏视觉同源
- `transform: translateX(...)` 配合 `transition: transform 220ms cubic-bezier(0.16, 1, 0.3, 1)` 实现开合
- 仅对 transform 设过渡, GPU 合成层处理, 不会因聊天列表重排而抖动
- 关闭态移出视口并禁用 `pointer-events`, 元素始终挂载, 靠 `data-open` 翻转驱动过渡, 既保留内部状态也省去重渲染

调色板沿用 CSS 变量 (`--bg-elevated` / `--bg-input` / `--border` / `--text` / `--accent` / `--text-dim`), 浅色主题由 `:root[data-theme="light"]` 覆盖。

详情行: 3 列网格 (label / value / 操作按钮), 固定首列宽度, 中间列可省略长路径与 id。

### 5.3 修复 3: Header 新增 📋 按钮

新按钮与 Telemetry 📊 共用 `is-active` 按下态, 镜像 R173 模式; 快捷键 `Ctrl+Shift+D` 平行可用。Title 属性显示快捷键以辅助 discoverability。

入口在 Header 而非底部, 跟暗色界面风格一致, 不再有「底部这行是啥」的疑惑。

## 6. 关键设计原则 (R250+ 累计)

下列原则是 R250+ 阶段的反复出现的设计取向, 维护新模块时可参考:

1. **后端兼容默认 throw** — 接口扩展时, 新方法默认抛 `UnsupportedOperationException` 而非抽象, 旧实现编译过, 运行时才显式告知不支持
2. **catch UnsupportedOperationException → clean error** — 工具层把异常转 `ToolResult.error`, 让 agent 循环决定重试 / 升级
3. **3 separate tools > 1 tool + discriminator** — 视觉 / 音频 / 图像分别独立工具而非判别式 schema, schema 清晰, 模型选 tool 不易错
4. **未装配时 stub 完整, 维持线缆形态** — bridge 没 chat model 时流式仍发 working / artifact / completed, SSE 传输层完整演练
5. **缓存装饰器而非修改基类** — 部署期关注点 (缓存) 写在装饰器, 不污染基类的无状态契约
6. **dry-run 默认 true** — 工作流首次跑必须显示提议不写文件, 安全默认
7. **verdict enum in code-review** — 结构化输出让 supervisor 决定 merge 不必 re-read report
8. **major-bump 显式 allow list** — 依赖升级用户可控, 默认空 (no major bumps)
9. **position: fixed + transform: translateX 抽屉首选** — 比 conditional render / display none 平滑, 保留 DOM 状态 (避免重新 fetch)
10. **删除死 UI 优于隐藏** — 99% 时间是灰的按钮只是 clutter, 真用的时候走更显眼的入口
11. **R-workflow InputDef schema 没 list type** — exclude/allow-major 用逗号分隔字符串
12. **ShippedWorkflowsTest dynamic discovery** — 加新 workflow 不用改 test, 改 list + ship YAML
13. **VlmClient 共享同一 client lifecycle** — 三个工具共享 `ImageUnderstandTool.defaultClient()`
14. **JSDoc 显式 override prop + is-active mirror** — Header 新增按钮镜像既有 pressed state, 不引入新视觉风格
15. **CSS 变量驱动主题** — 浅色覆盖通过 `:root[data-theme="light"]` 重写, 不重复选择器
