## 三、背景与动机

大语言模型（LLM）正从"被动的文本生成器"演化为"主动的行动执行者"。从 2023 年 AutoGPT、ReAct、Toolformer 的横空出世，到 2025 年 AgentBench、WebArena、τ-bench 等动态评估基准的规模化落地，LLM 智能体（LLM Agent）已成为人工智能研究的主流方向之一。然而，现有综述存在三大问题：（1）覆盖维度单一——多数综述只关注推理、规划或工具使用中的某一子领域；（2）检索源质量参差——大量预印本、博客文章被纳入统计，权威性存疑；（3）缺乏统一的四层分类法——读者难以横向比较不同架构与训练范式。

本综述的立项动机正是填补这一空白。研究团队历时两年，从 A* 与 A 级会议（ICLR、NeurIPS、ICML、ACL、EMNLP、AAAI、IJCAI、KDD、SIGGRAPH、SIGIR 等）以及 Q1 期刊中严格筛选，最终保留 **108 篇入选论文**（其中 75 篇来自 A* 会议、4 篇来自 A 级会议、29 篇来自 Q1 期刊）。检索时间窗口为 2023–2025 年。入选论文须经过 8 个主题维度、由 4 位合著者独立按 0/1/2 打分，总分 ≥ 48 分门槛方可保留。这种严苛的"门槛筛选法"确保了综述的学术权威性。

在地理分布上，108 篇论文的通讯作者来自：中国 46 项、美国 42 项、德国 5 项、英国与加拿大合计 3 项、其他国家 12 项。这一分布反映了中美在 LLM 智能体研究领域的双极主导格局。数据集层面，综述还对 **68 个公开数据集** 进行了系统梳理，涵盖 AgentBench、WebArena、ToolBench、SWE-bench、GAIA、MINT、τ-bench、HumanEval、MBPP 等主流基准。

作者在论文中明确提出 7 大研究问题（RQ），并通过四层分类法对全部 108 篇文献进行解构，是目前唯一对 **7 个 RQ 全部覆盖** 的 LLM 智能体综述（表 1 显示其他综述最多覆盖 5 个 RQ）。

### 4.3 基线 LLM（表 4）

| 提供方 | 代表模型 | 关键差异 |
|--------|---------|---------|
| **OpenAI** | GPT-4、GPT-3.5、Code-DaVinci-002、o1-preview、o1-mini | 多模态、工具使用、高级推理 |
| **Anthropic** | Claude 3 Opus、3.5/3.7 Sonnet、3 Haiku | 超长上下文、安全优先对齐 |
| **Google DeepMind** | Gemini 1.0/1.5 Pro、PaLM 2、FLAN-T5 | 原生多模态、百万 token |
| **其他** | Mistral-medium、Chinchilla-LM、HyperCLOVA | 推理高效、数据高效扩展 |

**统计**：约 55 项研究使用 GPT-4，约 23 项使用 GPT-3.5。开源侧代表模型包括 LLaMA、Mistral、Qwen、DeepSeek、Baichuan、ChatGLM，在低成本、本地化、隐私保护场景中具有特殊价值。

### 4.4 核心认知机制

**推理（Reasoning）**：从基础 CoT、Zero-shot CoT、Self-Consistency 出发，演进到高级 ToT（思维树）、GoT（思维图），再到工具增强推理（与外部计算器、知识库结合）。

**规划（Planning）**：涵盖任务分解（HTN、ToT）、执行循环（Plan-and-Execute、ReAct）、反思重规划（Reflexion、Self-Refine），以及多智能体跨角色协调。

**记忆（Memory）**：划分为短期（上下文窗口）、长期（外部向量数据库）、情景（过去事件细节）、语义（抽象知识）、程序性（技能与动作模式）五大类。高级架构包括 G-Memory（三层图）与 CAIM（Memory Controller + Retrieval + Post Thinking）。

### 4.5 性能提升三大支柱

1. **提示工程**：Zero-shot、Few-shot、CoT、Self-Ask、ReAct、结构化模板/JSON schema、元提示自我优化
2. **微调**：监督微调（SFT）、RLHF / DPO、工具使用微调（Toolformer 风格）、轨迹微调（agent-centric）
3. **记忆增强**：RAG、长上下文模型、外部记忆系统（MemGPT、向量数据库）、分层记忆

## 五、实验结果

由于本文是综述论文而非实证研究，实验结果以"元分析（meta-analysis）"的形式呈现，而非传统的 accuracy/F1 数值。作者通过对 108 篇入选论文的横向对比，得出以下关键定量发现：

**(1) 模型使用偏好**：GPT-4 在 ~55 项研究中被选为基线 LLM，GPT-3.5 在 ~23 项研究中出现，二者合计占据约 72% 的市场份额。开源模型以 LLaMA、Mistral 为代表，主要在隐私敏感或成本受限场景下出现。

**(2) 评估方法学转向**：综述明确指出"评估范式从静态准确率基准向动态过程导向方法转变"。具体度量维度包括：
- 任务成功率
- 推理质量（步骤可解释性）
- 工具使用正确性（参数正确率、API 调用成功率）
- 效率：延迟 / token 数 / 成本
- 安全：违规率 / 干预率

**(3) 关键基准横向对比**（论文表 3 详述）：

| 基准 | 应用领域 | 评估重点 |
|------|---------|---------|
| **AgentBench** | 综合 | 多环境 LLM 智能体 |
| **WebArena** | 网页 | 真实 UI 任务 |
| **ToolBench** | 工具密集 | 工具选择/参数/执行 |
| **SWE-bench** | 软件工程 | 端到端问题解决 |
| **GAIA** | 通用助手 | 短答案 + 工具 |
| **MINT** | 多轮 | 多轮工具使用 |
| **τ-bench** | 跨域 | 多领域工具 |
| **HumanEval / MBPP** | 编程 | 代码生成 |

**(4) 单智能体 vs. 多智能体的领域敏感性**：综述明确指出这一选择是**领域敏感**的——多智能体在需要社交智能、协作问题求解、高风险决策支持的领域（医疗、科研、复杂工程）有显著优势；而单智能体在低延迟、低成本的流水线任务中更优。

**(5) 工具集成 + 实时数据 + 多模态** 已被作者判定为"使 LLM 智能体超越预训练模型局限"的关键三件套，ReAct、Toolformer、MRKL 是其中最具代表性的实现路径。

## 六、局限与未来工作

作者在论文第 11 章明确归纳了 10 大未来方向，归并为 3 大主题：

**主题一：朝向可验证推理与鲁棒自我改进**
- **可验证推理**：FG-PRM（数学错误分类奖励模型）
- **强自我改进**：Reflexion（口头强化学习）、RISE（递归内省微调）、CORY（pioneer-observer 协作 RL）、COPPER（反射器智能体）
- **学习工具**：AgentOptimizer（工具作为参数）、AVATAR（自动化提示优化）

**主题二：可扩展、自适应、协作**
- **基础设施**：KV 缓存、优化解码器、边缘硬件
- **多智能体协作**：人类启发对话策略、轻量级智能体（交通、仓库、无人机）
- **协商仿真**：Lewis-style 游戏、Diplomacy
- **开源加速**：LLaMA-2-70B 等

**主题三：人机共生——个性化、主动性、信任**
- **长期个性化**：持久演化用户模型
- **意图识别与共创**：Tell Me More、ReHAC
- **隐私保护**：PrivacyAsst
- **伦理风险**：拟人化、过度信任、弱势群体
- **安全防护**：抵御越狱、环境信号触发后门

两大未来核心目标：(1) **可验证推理**——智能体推理透明且可审计；(2) **安全自我改进**——不损害安全的可靠方法。

## 七、工程解读（针对 AetherCode 项目）

AetherCode 作为工业级 Agent 框架，其 **17 个 Tier-3 兼容实现**（包括 GlobalPlan、ByzantineDetector、RetrievalBandit 等）天然与本综述的核心方法形成深度映射。以下逐项解读：

**(1) GlobalPlan 与"规划机制"的对齐**：本综述在 1.3.2 节讨论的 Plan-and-Execute 与 Reflexion 范式，正是 GlobalPlan 的理论根基。建议立即在 GlobalPlan 中集成"反思重规划"子模块——当执行反馈中出现连续 3 次 token 级 reward < 阈值时，触发 Reflexion 风格的自然语言反思，进而重新生成 HTN 子任务分解。

**(2) ByzantineDetector 与"安全与鲁棒性"的对齐**：综述 4.2 节"故障智能体韧性"是 ByzantineDetector 的直接理论支撑。综述明确列出"环境信号触发后门"作为未来方向之一，建议 ByzantineDetector 在现有签名验证之外，新增"环境信号感知"通道——检测工具调用链中的异常输入分布（如 token entropy 突增、API latency 异常）。

**(3) RetrievalBandit 与"记忆增强"的对齐**：综述 5.3 节将 RAG 列入"记忆增强"的核心技术，建议 RetrievalBandit 在传统 contextual bandit 之上，引入 MemGPT 风格的"分层记忆"——短期上下文用于即时决策，长期向量数据库用于跨会话知识累积，情景记忆用于回溯特定任务的失败轨迹。

**(4) ReAct / Toolformer 风格的工具集成**：本综述 2.1 节强调"工具作为参数"的 AgentOptimizer 范式，建议在 AetherCode 的 tool registry 中引入"参数化工具调用"接口，使得工具描述本身可作为可学习参数，与 LLM 的 embedding 联合优化。

**(5) 单智能体 vs. 多智能体的领域敏感选择**：综述核心结论之一指出"领域敏感性"——这恰好是 AetherCode 当前架构的关键设计依据。在医疗、EDA、云 RCA 等高风险领域，应优先启用多智能体协作；在低延迟数据流水线任务中，应保持单智能体架构。

**(6) 立即可做的下一步**：
- 在 GlobalPlan 集成 Reflexion 式反思触发器（1–2 周）
- 给 ByzantineDetector 增加环境信号异常检测模块（2–3 周）
- 为 RetrievalBandit 引入 MemGPT 风格分层记忆（3–4 周）
- 启动与 AgentBench、WebArena 兼容的 Tier-3 评估套件（4–6 周）
- 跟进 FG-PRM 等可验证推理奖励模型，争取在推理引擎层落地（中期规划）
