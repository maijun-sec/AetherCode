# 2607.20064 PRO-LONG: Programmatic Memory Enables Long-Horizon Reasoning

**作者**: Alexis Fox, Junlin Wang, Paul Rosu, Bhuwan Dhingra (Duke University)

**日期**: 2026

**PDF**: 0.7 MB · GitHub: alexisfox7/PRO-LONG

**核心**: **PRO-LONG** — 用 code agent 处理 long context, 完整 log + 编程式搜索, 4.2-5.8× token 节省。

## 1. 关键洞察

- 现有 context 管理困境: 保留多 → 检索难; 压缩多 → 丢信息
- **Programmatic memory**: 把 log 存为文件, 让 code agent 用 code 搜索
- 跟 coding agent 趋势结合 (code agent 自己就是 context processor)

## 2. 关键数据

ARC-AGI-3 public game set:
- 平均 +18.0 pp 超过 base coding agent
- **76.1% pass@1** (SOTA specialized harness)
- **4.2-5.8× token 节省** vs specialized harness
- Fable 5 game: **97.4% best@2** with $1,750 total cost

## 3. 核心机制

```
[Long environment log] 
    ↓
[Persistent log file] (程序化访问)
    ↓
[Code agent] 用 code 查询 log (e.g. grep / SQL)
    ↓
[Filtered context] → LLM
```

**关键**: 不动 LLM, 把长 context 转化为可程序化查询的数据。

## 4. AetherCode 关联

| 论文观点 | AetherCode 对应 | 实现状态 |

## 5. 兼容实现候选

| 类 | 用途 | 文件位置 |
|---|---|---|
| `ProgrammaticMemory` | 把 log 存为可代码查询的结构 | `orchestration.memory` |
| `CodeSearchBridge` | LLM 写 code 查 log, 替代 similarity search | `orchestration.context` |
| `LogQueryLanguage` | 限制 LLM 写的 code 子集 (避免越界) | `orchestration.context` |

## 6. 教训

- **Code agent + memory 是绝配** — LLM 写 code 查 log, 比 vector search 更灵活
- **持久 log 比 in-memory 强** — 跨 session 可访问
- **4-5× token 节省** 验证 approach 实用
- **Code search vs vector search**: code 精确但需写 code, vector 模糊但易用
- **ARC-AGI-3 76% pass@1** 跟 SOTA specialized harness 持平
