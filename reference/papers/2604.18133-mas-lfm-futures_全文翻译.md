## 2. 一句话摘要

本综述以"五维分类法"系统对比 CMAS 与 LMAS，揭示 LFM 把多智能体协调从"状态交换"推向"语义推理"的范式跃迁。

## 3. 背景与动机

多智能体系统（Multi-Agent Systems, MAS）的概念可追溯至上世纪八十年代的分布式人工智能（Distributed AI）研究。彼时的研究者试图让多个具备局部感知能力的自主实体在共享环境中协作完成单智能体难以胜任的任务，由此催生了合同网协议（Contract Net Protocol）、黑板系统（Blackboard System）、BDI（Belief–Desire–Intention）模型等一系列经典范式，这些范式在本文中被统一归类为 **CMAS（Classical MAS）**。CMAS 的成功离不开四条隐含假设：通信信道可靠且带宽充足、智能体内部决策逻辑可形式化、全局观测可由局部观测聚合、任务环境高度结构化。然而进入二十一世纪二十年代，应用场景迅速向开放域、跨模态、长链路规划倾斜，固定的行为规则与预设的消息协议逐渐力不从心。

与此同时，以大语言模型（LLM）为代表的 **大基础模型（Large Foundation Model, LFM）** 在自然语言理解、世界知识压缩、零样本推理等方面取得突破，使研究者开始尝试用 LFM 替代或增强 CMAS 中的"决策内核"。由此衍生出的新范式被作者命名为 **LMAS（LFM-enabled MAS）**——其特征是：智能体之间不再交换结构化的状态向量或事实三元组，而是交换自然语言意图、推理链乃至反思段落。这一变化带来了根本性的能力跃升，但也引入 CMAS 时代不曾有过的开放性挑战。

本文正是在这一背景下系统回答三个核心问题：（1）CMAS 与 LMAS 的统一刻画框架是什么？（2）二者各自的运行机制与适用边界在哪里？（3）面向未来，应该沿着哪些方向继续推进 MAS 研究？为同时回答这三点，作者提出"四维闭环协调框架 + LFM 跨层赋能"的双层分析视角。

## 4. 核心方法

### 4.1 闭环协调的四维框架

作者首先将 CMAS 的全部行为抽象进一个**闭环协调框架**，并沿四个基本维度展开：

| 维度 | CMAS 典型机制 | 关键问题 |
|---|---|---|
| 感知（Perception） | 局部传感器融合、Kalman 滤波、SLAM 片段 | 在有限观测下估计全局状态 |
| 通信（Communication） | 消息广播、合同网、ACL/KQML、黑板 | 何时与谁通信、传输何种内容 |
| 决策（Decision） | 博弈论均衡、规划器、BDI 推理机 | 选择使团队效用最大化的动作 |
| 控制（Control） | 分布式控制器、Leader–Follower、共识协议 | 将高层意图落实为可执行轨迹 |

作者强调，这四个维度并非孤岛，而是构成一个**感知 → 通信 → 决策 → 控制 → 感知**的反馈环：感知产出状态估计，状态估计通过通信扩散至邻居，邻居基于共享信息做出决策，决策结果经控制层执行后改变环境，环境又触发新一轮感知。任何一环失稳都会引发全环振荡，这正是 CMAS 鲁棒性研究的逻辑起点。

### 4.2 LFM 的跨层赋能

LMAS 与 CMAS 的根本差异在于 **LFM 充当跨层"语义中枢"**。具体地，LFM 可以介入以下任意一层：

1. **感知层增强**：将原始传感器流或多模态数据直接送入视觉–语言模型（VLM），由模型输出富含语义的场景描述，替代手工特征工程。
2. **通信层升级**：智能体之间传递的不再是 `<belief, time, conf>` 这样的事实三元组，而是一段自然语言"提案 + 理由 + 风险评估"。这显著降低了协议设计成本，但也使得消息长度从字节级跃迁到 token 级（通常 50–500 token/条）。
3. **决策层重写**：博弈论被 LLM 模拟推演取代；规划器被 ReAct、Reflexion、ToT 等思维链策略替代；BDI 中的"信念更新"被提示词驱动的反思循环所重写。
4. **控制层混合**：高层意图由 LFM 解析，低层控制仍交回经典控制器执行，形成"语义决策 + 反应式控制"的混合栈。

### 4.3 五维分类法

为同时容纳 CMAS 与 LMAS，作者构建了一张 **5 维分类表**：行维度是"CMAS / LMAS"，列维度即上述 4 个协调维度，因此产生 **2 × 4 = 8 个配置象限**。任意一个实际系统，都可以用这张表打分定位。例如 AetherCode 的 `MultiAgentOrchestrator` 默认采取 *LMAS × Hybrid Control* 象限；而经典合同网协议则是 *CMAS × Decentralized Decision × Broadcast Communication* 的典型代表。

### 4.4 对比维度：架构、运行机制、适应性、应用

作者进一步从四个横切维度对 CMAS 与 LMAS 进行横向对比：

- **架构**：CMAS 倾向于同构、模块化、紧耦合；LMAS 倾向于异构、提示词驱动、松耦合。
- **运行机制**：CMAS 依赖预编译策略与形式化协议；LMAS 依赖上下文窗口与推理时计算（inference-time compute）。
- **适应性**：CMAS 在分布漂移（distribution shift）下需要重训练或重设计协议；LMAS 仅需调整提示词或示例。
- **应用**：CMAS 主战场为机器人编队、智能电网、无人机集群；LMAS 主战场为代码生成、自动化科研、对话式业务流程编排。

### 4.5 未来五大挑战

作者在文末列出 MAS 的五项开放挑战：

1. **评估基准**：当前基准多以任务成功率衡量，缺少对"协作质量"（如沟通效率、共识深度、信任校准）的度量。
2. **通信效率**：LFM 之间每轮交互需 2 次以上前向推理，延迟在秒级，与 CMAS 毫秒级响应存在数量级差距。
3. **可扩展性**：智能体数量 $N$ 增长时，通信量呈 $O(N^2)$，需引入广播抑制、订阅过滤或层次化拓扑。
4. **异构 MAS**：不同 LFM（GPT、Claude、Gemini、Llama、自研模型）之间的协议兼容与能力对齐尚未解决。
5. **安全可解释性**：当决策来源于 LLM 推理链而非显式规则时，归因（attribution）与审计（audit）变得困难。

## 5. 实验结果（对比分析）

由于本文为综述论文，原作者并未给出单一基准上的数值结果，而是以**结构化对比表**的形式给出 CMAS 与 LMAS 在四个维度上的横向表现：

**表 1：架构对比**

| 维度 | CMAS | LMAS |
|---|---|---|
| 智能体同构性 | 强同构 | 弱同构（多模型并存常见） |
| 决策可追溯性 | 高（规则可枚举） | 低（推理链黑盒） |
| 模块化边界 | 清晰（感知/通信/决策/控制分层） | 模糊（LFM 跨层） |
| 部署成本 | 中（开发协议） | 高（推理算力） |

**表 2：运行机制对比**

| 机制 | CMAS | LMAS |
|---|---|---|
| 通信单元 | 结构化消息（KB tuple / ACL） | 自然语言 token 流（50–500 token/条） |
| 决策时延 | 毫秒级 | 秒级（2–10s/轮） |
| 协议设计 | 一次设计，长期复用 | 每次任务需重写提示词 |
| 失败模式 | 死锁 / 活锁 | 幻觉 / 跑题 / 循环论证 |

**表 3：适应性对比**

| 情境 | CMAS 调整成本 | LMAS 调整成本 |
|---|---|---|
| 任务目标变更 | 重编译 / 重部署 | 修改 system prompt |
| 新增智能体 | 重写协议 | 仅添加角色描述 |
| 观测噪声变化 | 重训练感知模块 | 调高 temperature / 引入 CoT |
| 跨域迁移 | 困难 | 相对容易（zero-shot） |

**表 4：典型应用分布**

| 领域 | CMAS 占比 | LMAS 占比 |
|---|---|---|
| 工业机器人编队 | 约 80% | 约 20% |
| 智能电网调度 | 约 70% | 约 30% |
| 软件开发 | 约 10% | 约 90% |
| 自动化科研 | 约 5% | 约 95% |
| 业务流程编排 | 约 25% | 约 75% |

综合上述对比，作者得出三点定性结论：（1）CMAS 在低延迟、强可解释、确定性强场景仍不可替代；（2）LMAS 在开放域、长链路、强语义场景具备压倒性优势；（3）未来主流架构将是**"LFM 语义决策 + CMAS 反应式控制"**的混合形态。

## 6. 局限与未来工作

作者坦言本综述存在三点局限：其一，受限于篇幅，对 CMAS 经典文献的引用偏向近 5 年，对 2000 年前奠基性工作的覆盖略显单薄；其二，未提供可复现的端到端开源实现，读者难以直接验证"CMAS × 4 维"框架在异构平台上的适配性；其三，五大挑战虽被识别但缺乏量化定义，例如"协作质量"缺少公认的度量函数。

未来工作被作者归纳为三个方向：第一，构建统一的 MAS 评测套件，覆盖任务指标与协作指标；第二，设计 LFM 间的高效通信协议，例如分层路由、语义压缩、增量更新；第三，融合形式化方法（时序逻辑、可验证合约）与 LFM 推理，建立兼具灵活性与可证明性的混合智能体架构。

## 7. 工程解读

站在 **AetherCode** 工业级 Agent 框架的视角重读本综述，可以得到三层落地启示。

### 7.1 已落地的思想对齐

AetherCode 已有的 17 个 Tier-3 兼容实现中，至少有 4 个直接呼应本综述的论点：

- `MultiAgentOrchestrator` 对应综述第 4.3 节的 **5 维分类法**：它显式支持 single / independent / centralized / decentralized / hybrid 五种拓扑，本质上是 Control 维度的实例化。但综述强调的 hierarchical controller 在 AetherCode 中尚未独立成类，建议在下个版本拆出 `HierarchicalController` 子模块。
- `CritiqueStrategy` 对应综述 4.2 节"语义决策"——它用 proposer-critic 模式实现"提案 + 评审批议"，是 LFM 替代 BDI 推理机的工程范本。
- `VoteStrategy` 对应综述挑战 3（可扩展性）——它通过"广播 → 集中 tally"的折中，把 $O(N^2)$ 通信压缩为 $O(N)$ 单向广播加一次汇聚。
- `ByzantineDetector` 与 `RedFlagDetector` 对应挑战 5（安全可解释）——它们提供了 CMAS 时代常见的故障检测语义，但仍未触及 LMAS 时代的"决策归因"问题。

此外，`GlobalPlan` 与 `RetrievalBandit` 分别从"全局规划"与"检索臂选择"两个角度，把综述"语义决策 + 反应式控制"混合栈的思想落到了工程代码。

### 7.2 立即可做的下一步

基于综述的五大挑战，作者强烈建议在 AetherCode 中新增 3 个 Tier-3 模块：

1. **`DebateStrategy`** —— 综述指出 LMAS 的协调已从"状态交换"升到"语义推理"，最自然的载体是多轮辩论。建议实现"提案 → 多视角质疑 → 修订 → 早停"的循环，并在能量低于阈值时自动终止，避免 round-trip 成本失控。
2. **`PubSubTopology`** —— 对应挑战 3 的 $O(N^2)$ 通信瓶颈。建议引入选择性订阅：智能体声明兴趣主题（topic），由 broker 完成过滤，使消息复杂度降到 $O(N \cdot k)$，其中 $k$ 为订阅因子。这一拓扑在 MetaGPT 等开源框架中已被验证。
3. **`DecisionAttributor`** —— 对应综述提到的 "Find faults through attribution"（LIFE 框架的 Find 阶段）。建议记录每个决策节点上的（输入、提示词、模型 ID、输出、置信度）五元组，失败时可沿链路反向回溯，把"为什么是这个动作"从黑箱叙事变成可审计证据。

### 7.3 仍待探索的方向

综述提出的**异构 MAS** 与**评估基准**两点，AetherCode 目前完全未覆盖。前者涉及跨厂商 LLM（OpenAI / Anthropic / Google / Meta / 自研）的协议网关，建议作为 `HeterogeneousGateway` Tier-4 模块立项；后者则需联合社区定义"协作质量"度量函数，可作为 AetherCode 评测子项目 `AetherBench` 的下一里程碑。
