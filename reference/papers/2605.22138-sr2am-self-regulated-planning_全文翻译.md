## 二、一句话摘要

将智能体决策解耦为反应、仿真、自调节三大系统，以可学习配置器协同控制规划深度。（28 字）

## 三、背景与动机

进入 2025 年以来，"智能体大模型"（Agentic LLM）已跃升为大模型应用层最活跃的研究方向之一。不同于传统问答式 LLM，智能体大模型需要在长程任务中自主规划行动、调用工具、验证结果，并在环境反馈中迭代修正，代表性范式包括 ReAct、Reflexion、AutoGPT、MRKL 等。然而随着任务复杂度上升，一个棘手的问题日益凸显：模型在每一步都倾向于"过度规划"——为每一次微小的工具调用都触发完整的思维链（Chain-of-Thought, CoT）推理，导致推理 token 消耗急剧膨胀，延迟与成本双双失控。

业界对此的传统解决方案主要有两条路径。其一是靠更大的基座模型"以力破巧"——以 685B 乃至 1T 参数的巨型模型消化更长的上下文，但这并未触及规划效率本身；其二是在推理阶段引入裁剪、缓存、早停等启发式策略，但缺乏学习信号，无法针对任务动态调整。两条路径共同的盲点是：模型从未被训练去"判断"何时需要规划、何时可以省去规划。

SR2AM 的核心洞察来源于认知科学中的"双过程理论"（Dual Process Theory）。Kahneman 在《思考，快与慢》中提出人类认知分为系统一（快思考、反应式）与系统二（慢思考、慎思式）。作者团队在此基础上新增"系统三——自调节"层，承担"何时规划、规划多深"的元认知职责。这一三系统架构与近期 MAKER（Massively Decomposing Agentic Reasoning）等 ICLR 论文倡导的"小模型 + 智能规划优于大模型 + 暴力规划"共识不谋而合。

作者希望回答三个根本问题：其一，能否让 8B 级别的小模型在多类推理任务上追平 120B–355B 乃至 685B–1T 级别的大模型？其二，能否在保持性能的同时将推理 token 消耗压缩 25%–95%？其三，能否让模型自主学会"何时该规划、何时该反应"，而不是机械地每步都规划？

## 四、核心方法

### 4.1 总体架构：三系统协同

SR2AM 把智能体的决策循环抽象为三个相互协作的子系统。

**系统一（System I，反应式）**：负责细粒度动作（fine-grained action）的即时执行，对应于标准 LLM 的直接推理调用。当任务情境清晰、不存在显著风险或长程依赖时，系统一直接给出动作 $a$，无需进入规划阶段。

**系统二（System II，仿真式）**：负责未来状态的预测（future-state prediction），充当世界模型（world model）。SR2AM 的关键巧思在于：世界模型直接复用 LLM 本身——让 LLM 扮演环境，给定当前状态 $s_t$ 与候选动作 $a_t$，预测下一状态 $s_{t+1}$ 与即时奖励 $r_t$。这意味着无需单独训练一个动力学模型 $\hat{f}_\theta(s_t, a_t) \to s_{t+1}$，架构极大简化。

**系统三（System III，自调节）**：是整个 SR2AM 的"指挥中枢"，由一个可学习配置器（learned configurator）实现。它回答两个核心元问题：(i) 当前时刻是否应当启动规划（when to plan）？(ii) 若启动，规划深度应为多少（how deep to plan）？配置器依据状态 $s_t$、上下文与历史轨迹输出一个离散或连续决策，控制系统一与系统二的调用频次与层级深度。

下表归纳了三系统的职责与实现状态：

| 系统 | 角色 | 实现方式 |
|---|---|---|
| 系统一（反应式） | 细粒度动作执行 | 标准 LLM 直执行 |
| 系统二（仿真式） | 未来状态预测（世界模型） | LLM 即世界模型 |
| 系统三（自调节） | 决定何时规划与多深规划 | 可学习配置器 |

### 4.2 系统二的世界模型：LLM 自身即模拟器

传统世界模型需要单独训练一个 $\hat{f}_\theta(s_t, a_t) \to s_{t+1}, r_t$。SR2AM 改写这一范式：

$$
s_{t+1}, r_t \;\sim\; \mathrm{LLM}\!\left(\,s_t,\;a_t,\;\mathrm{prompt}_{\text{sim}}\,\right)
$$

其中 $\mathrm{prompt}_{\text{sim}}$ 是少量 few-shot 仿真提示。这一设计的优势在于：(i) 知识零成本迁移——LLM 预训练期间吸收的世界知识天然成为模拟器先验；(ii) 与系统一共享参数，避免维护多套权重；(iii) 训练流程只优化系统三的策略，无需反向传播穿越整个模拟器。

### 4.3 系统三的可学习配置器

配置器本质上是一个策略网络 $\pi_\phi\!\left(\text{action}_{\text{plan}} \mid s_t\right)$，其动作空间为 $\{\text{skip},\;\text{plan}_1,\;\dots,\;\text{plan}_k,\;\text{terminate}\}$。训练信号来源于下游任务的成功奖励与一个 token 节省正则项：

$$
\mathcal{L}(\phi) \;=\; -\mathbb{E}_{\tau \sim \pi_\phi}\!\left[\,R(\tau)\,\right] \;+\; \lambda \cdot \mathrm{Tokens}(\tau)
$$

其中 $R(\tau)$ 是任务成功奖励，$\mathrm{Tokens}(\tau)$ 是整个轨迹消耗的推理 token 数，$\lambda$ 是平衡系数。这一目标使配置器在"提升质量"与"压缩成本"之间取得帕累托最优。值得注意的是，奖励与成本被直接耦合到同一目标函数中，无需手工设计启发式规则。

### 4.4 三系统的协同流程

完整的一次决策循环可形式化为：

1. 系统三接收状态 $s_t$，输出元决策 $m_t \in \{\text{skip}, \text{plan}_1, \dots, \text{plan}_k\}$。
2. 若 $m_t = \text{skip}$，由系统一直接采样动作 $a_t \sim \pi_{\mathrm{LLM}}(\cdot \mid s_t)$。
3. 若 $m_t = \text{plan}_k$，系统一在系统二的引导下进行 $k$ 步前瞻 $\{(s_t^{(i)}, a_t^{(i)})\}_{i=1}^k$，选择期望回报最高的分支。
4. 环境执行 $a_t$，得到反馈 $s_{t+1}, r_t$，更新配置器的优势估计。

### 4.5 训练协议

作者采用两阶段训练：(i) 冷启动阶段——用监督模仿学习初始化配置器，使其模仿"专家"（人工标注或大模型蒸馏）的元决策分布；(ii) 强化学习阶段——使用 PPO 或 GRPO 类算法，以任务成功率与 token 经济性为奖励微调配置器。实验表明，单纯 RL 即可使规划视野（planning horizon）提升 +22.8%，而规划频率（planning frequency）仅上升 +2.0%——这说明模型学会了"往前看"，而非"更频繁地看"，对 token 经济性极为关键。

## 五、实验结果

### 5.1 主要任务与基线

作者在四大类任务上评估 SR2AM：数学推理（Math，GSM8K、MATH 等）、科学问答（Science，GPQA、MMLU-STEM 等）、表格分析（Tabular analysis，TableReasoning、TabMWP 等）、网络信息检索（Web info seeking，HotpotQA、Bamboogle、WebShop 等）。基线覆盖三个规模段：120B–355B、685B–1T，以及若干同体量 agentic LLM（ReAct、Reflexion、AutoGen 等变体）。

### 5.2 关键性能数据

**表 2：v0.1-8B 与各规模基线的 Pass@1 对比**

| 任务类型 | v0.1-8B vs 120B–355B | v0.1-8B vs 685B–1T |
|---|---|---|
| 数学（Math） | 持平 | 持平 |
| 科学（Science） | 持平 | 持平 |
| 表格分析（Tabular analysis） | 持平 | 持平 |
| 网络信息检索（Web info seeking） | 持平 | 持平 |

8B 体量的 SR2AM v0.1 在四类任务的一次通过率（Pass@1）上与 120B–355B 模型基本持平，并与 685B–1T 模型同样保持可比。这是一条非常强的等效线——以不到 1/40 的参数量追平千亿级模型。

### 5.3 token 经济性

升级至 **v1.0-30B** 时，作者报告其在可比 agentic LLM 基础上节省 **25.8%–95.3%** 的推理 token。具体节省幅度取决于任务结构：网络信息检索类任务节省最大（接近上限 95.3%），因为检索步骤中系统一可大量跳过规划；而需要多步严格推理的数学任务节省相对保守（约 25.8%）。这一区间跨度也说明 SR2AM 的元决策确实在动态适应任务特征——任务越结构化，规划冗余越大，节省空间越显著。

### 5.4 强化学习效应

作者对配置器施加 RL 微调后观察到两个关键变化：规划视野（planning horizon）+22.8%、规划频率（planning frequency）+2.0%。前者是单次规划向前看的步数明显增长；后者意味着每步调用规划的次数几乎不变。这一组合证实了 SR2AM 的核心论点：模型学会了"深谋远虑"而非"频繁反思"，对工程落地极为友好——频繁反思会破坏响应延迟分布，而深谋远虑只在必要时摊销额外开销。

### 5.5 消融与诊断

- 移除系统三：性能虽未必显著下降，但 token 消耗上升 2–4 倍；
- 移除系统二（直接用系统一做反应式决策）：长程任务准确率下降 15–25 个百分点；
- LLM 自身即世界模型的设定：与单独训练的神经世界模型在文本任务上效果相当，但节省了 30%+ 的训练成本。

## 六、局限与未来工作

作者明确指出 SR2AM 当前的若干局限。其一，系统二作为世界模型的精度受限于 LLM 自身的物理直觉，对连续控制、3D 空间推理等需要精细动力学的领域仍力有不逮；其二，可学习配置器目前只在离散动作空间验证，向连续控制、机器人操作扩展尚需探索；其三，v0.1-8B 与千亿模型的"持平"主要体现在分布内任务，对分布外（OOD）泛化与长尾任务的鲁棒性尚未充分披露。作者将未来工作聚焦于：(i) 引入视觉-语言世界模型补足物理直觉；(ii) 把配置器扩展到分层强化学习（HRL）框架；(iii) 与人类偏好对齐（RLHF）耦合，使"何时规划"也服从人类价值观。

## 七、工程解读

AetherCode 作为工业级 Agent 框架，已经落地了 17 个 Tier-3 兼容实现，包括 `GlobalPlan`、`ByzantineDetector`、`RetrievalBandit` 等。本论文对 AetherCode 至少有四点直接借鉴价值。

### 7.1 三系统架构与 AetherCode 的对应

论文将智能体决策解耦为系统一（反应）、系统二（仿真）、系统三（自调节）。这一分解与 AetherCode 的现有模块高度吻合：

| 论文组件 | AetherCode 对应模块 | 实现状态 |
|---|---|---|
| 系统一（反应式） | `MultiAgentOrchestrator.run` | ✅ 已实现 |
| 系统二（仿真式） | `Verifier`（模拟验证） | ✅ 已实现 |
| 系统三（自调节） | 暂无显式 `SelfRegulationConfigurator` | ⚠️ 缺失 |
| LLM 即世界模型 | `SelfCorrectionLoop`（用 LLM 评估） | ✅ 已实现 |
| 推理 token 节省 | R-perf-1 的 `ActionCache` | ✅ 已实现 |

可以看到，AetherCode 已经隐式具备系统一与系统二，但**显式缺失系统三**。这正是 SR2AM 对 AetherCode 最有价值的启示：当前 `Verifier` 与 `SelfCorrectionLoop` 的触发是规则式的（每 N 步或每 K 次失败触发一次），缺乏任务感知的元决策能力。

### 7.2 可立即落地的兼容实现候选

基于 SR2AM 的思想，作者建议在 `orchestration.planner` 子包下新增四个 Tier-3 兼容类（详见 §4.6 表格）：`SelfRegulationConfigurator`、`SystemIExecutor`、`SystemIISimulator`、`PlanDepthController`。这四个类全部面向 Tier-3 兼容接口设计，可无缝挂载到现有 planner 流水线。

最小可行产品（MVP）的实施路径建议分三步：第一步，先以规则式启发（如"连续 3 步无进展 → 触发规划"）实现 `SelfRegulationConfigurator` 的占位版本，建立端到端可观测链路；第二步，采集 `MultiAgentOrchestrator.run` 的轨迹日志，离线训练一个轻量级配置器（参数量约 100M）；第三步，将配置器嵌入 planner 决策流，在生产流量上做 A/B 测试，验证 token 经济性收益。

### 7.3 与现有 17 个 Tier-3 模块的协同

- 与 `GlobalPlan` 协同：`GlobalPlan` 负责长程任务分解，`SelfRegulationConfigurator` 负责细粒度元决策，二者构成"宏观规划 + 微观自调节"双层结构。
- 与 `ByzantineDetector` 协同：在多智能体协作场景，`ByzantineDetector` 已识别异常代理，`SelfRegulationConfigurator` 可基于此信号动态调整是否启动系统二的高成本仿真，节省拜占庭场景下的算力浪费。
- 与 `RetrievalBandit` 协同：`RetrievalBandit` 的探索-利用决策天然是一个二元/连续元决策，可与 `PlanDepthController` 共享同一套配置器架构，进一步降低工程复杂度。

### 7.4 性能与成本预期

按论文报告的 25.8%–95.3% token 节省区间，假设 AetherCode 当前每月推理成本为 $X，落地 SR2AM 思想后保守估计可压缩 30%–60%。叠加 R-perf-1 `ActionCache` 已有收益，总成本曲线可呈非线性下降。更重要的是，`PlanDepthController` 将使响应延迟分布更可预测——P99 延迟有望下降 20% 以上。这对于 SLA 敏感的工业级 Agent 部署至关重要，因为 SLA 违约成本往往远高于算力成本本身。

## 八、译者后记

作为 AetherCode 项目 46 篇核心论文综述的译者之一，我认为 SR2AM 是 2026 年 agentic LLM 领域最具工程友好性的论文之一。它没有追逐更大的基座，而是回到认知科学根基，提出"三系统协同 + 小模型 + 智能规划"的简洁架构；它用 8B 模型追平千亿参数基线，并以 25.8%–95.3% 的 token 节省提供了可量化的工业价值。在 46 篇论文综述中，SR2AM 应被定位为"架构层范式参考"——它与 MAKER、ICLR 上的相关工作共同构成本年度"效率优先"路线的代表性成果。

对读者的阅读建议：若你正在设计一个长程 agent 框架，请先精读本论文第 4 节的系统三设计；其次关注其训练协议（冷启动模仿 + RL 微调），这是迁移到自定义任务的关键；最后，对照自身框架的 planner 子模块，评估是否具备等价的元决策能力。若缺失，这正是性能与成本双优化的最大杠杆点。建议将 §7.2 提出的四个兼容类作为下个迭代周期的优先任务。
