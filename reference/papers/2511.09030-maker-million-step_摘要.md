# 2511.09030 MAKER: Solving a Million-Step LLM Task with Zero Errors

**作者**: Elliot Meyerson, Giuseppe Paolo, Roberto Dailey, Hormoz Shahrzad, Olivier Francon, Conor F. Hayes, Xin Qiu, Babak Hodjat, Risto Miikkulainen (Cognizant AI Lab + UT Austin)

**日期**: 2025-11-13 (v1)

**PDF**: 8.3 MB · 29 pages

**核心**: 提出 **MDAP (Massively Decomposed Agentic Processes)** 框架, 解决 "LLM 在长链任务中必然累积错误" 问题, 实测 100 万步零错误。

## 1. 问题

LLM per-step 错误率即使 1/1000, 在 100 万步长链任务中也几乎必然失败 (Towers of Hanoi 验证: 6 盘之后成功率断崖归零)。仅靠提升 base model 不足以解决问题, 需正交路径。

## 2. MDAP 三件套

| 组件 | 作用 | 形式化 |
|---|---|---|
| **MAD (Maximal Agentic Decomposition)** | 任务拆到 m=1, 每步一个 micro-agent | r_i ~ M(φ(x_i)), 单步 context 极小 |
| **First-to-ahead-by-k Voting** | 多个 sample 投票, 胜出 margin ≥ k 才接受 | gambler's ruin hitting probability: p_sub = 1/(1+(1-p)/p)^k |
| **Red-flagging** | 检测高风险 response (格式异常等) 拒绝 | 输出 red flag → 重新 sample |

## 3. Scaling Law

每步 per-step success rate p, 任务总步数 s, 投票阈值 k 满足 k_min = Θ(ln s)。即投票开销随任务长度**对数增长**而非线性, 极经济。

## 4. 实验

**Towers of Hanoi 20 盘 = 1,048,575 步**:
- base model: 必然失败
- MAKER (m=1, k 适当, 红旗检测): 0 errors 跑完 1M+ 步
- 用极小 LLM (gpt-4.1-nano, llama-3.2-3B 等) 即可, 不需要 frontier reasoning model

## 5. AetherCode 关联

| 论文观点 | AetherCode 对应 | 实现状态 |
|---|---|---|
| 极小 LLM + 大量 micro-agent | `AgentRuntime.run` 单步粒度 | ✅ |
| First-to-ahead-by-k 投票 | `VoteStrategy.MAJORITY` (阈值 51%) | ✅ 但 k 一般化未暴露 |
| Red-flagging (格式异常) | `Verifier` + `VerificationResult.fail(reason)` | ✅ |
| m=1 decomposition | 任务拆解在 `DagPlan` step 粒度 | ✅ |

| 类 | 用途 | 文件位置 |

## 7. 教训

- **极小 LLM + 大量微任务 > 极大 LLM + 单任务** — orthogonal scaling 路径
- **投票阈值 k 是 log(s) 关系** — 不是 linear, 经济上可行
- **红旗检测是 0 错误的关键** — 单纯 voting 不够, 必须拒绝异常 output
- **State-of-the-art reasoning 不是必要** — 7B 以下小模型 + 极细拆解 + voting 即可
