# 2508.01332 BlockA2A: Towards Secure and Verifiable Agent-to-Agent Interoperability

**作者**: Zhenhua Zou, Zhuotao Liu, Lepeng Zhao, Qiuyang Zhan (清华大学)

**日期**: 2025-08-02 (v1) / 2025-09-21 (v3)

**PDF**: 0.72 MB · 43 pages

**核心**: **BlockA2A** = 区块链 + DID + smart contract, 给 A2A 协议加信任层, 解决 LLM-driven MAS 的 3 大安全漏洞 (身份碎片化 / 不安全通信 / 无 Byzantine 防御)。

## 1. 3 大安全漏洞

| 漏洞 | 描述 | 后果 |
|---|---|---|
| **Fragmented identity** | 不同厂商 agent 身份框架不互认 | 无法验证消息来源, 跨域协作断 |
| **Insecure communication** | API/数据交换暴露 attack surface | 数据拦截 / 命令注入 / workflow sabotage |
| **Inadequate Byzantine defense** | 恶意 / 偏离 agent 无防御机制 | 一个坏 agent 拖垮整个 MAS |

## 2. BlockA2A 3 大支柱

| 支柱 | 技术 | 作用 |
|---|---|---|
| **DID (Decentralized Identifiers)** | W3C DID 标准 | 跨域 agent 身份认证, 无中心 CA |
| **Blockchain-anchored ledger** | 不可篡改审计 | 记录所有 agent 交互, 事后追溯 |
| **Smart contract** | 链上代码 | 动态 context-aware access control |

## 3. Defense Orchestration Engine (DOE)

- **Byzantine agent flagging**: 检测偏离预期行为的 agent, 标记
- **Reactive execution halting**: 恶意行为触发, 立即停止
- **Instant permission revocation**: 撤销 agent 权限, 实时生效

**关键指标**: sub-second overhead, 适合 production LLM-based MAS 部署。

## 4. AetherCode 关联

| 论文观点 | AetherCode 对应 | 实现状态 |
|---|---|---|
| 跨域 agent 身份 | `aethercode-a2a` AgentCard (但只本地) | ⚠️ 缺 DID |
| 不可篡改审计 | ⚠️ 当前 RuntimeTrace 在内存, 不持久 | 缺 |
| Byzantine agent 检测 | ❌ 无 | 缺 |
| 智能合约 access control | `aethercode-permission` CommandAllowlist | ✅ (但非 chain) |

## 5. 兼容实现候选

| 类 | 用途 | 文件位置 |
|---|---|---|
| `ByzantineDetector` | 监控 agent 行为, 标记偏离, 触发 halt | `orchestration.security` |
| `PersistentRuntimeTrace` | RuntimeTrace 持久化到 append-only log (or 区块链) | `orchestration.runtime` |
| `DidAgentIdentity` | W3C DID 风格 agent 身份, 跟 AgentCard 集成 | `aethercode-a2a` |
| `DefenseOrchestrationEngine` | 检测 + halt + revoke 3 件套, 跟 CommandAllowlist 联动 | `aethercode-permission` |

## 6. 教训

- **A2A 需要信任层** — 仅 capability-based 不足以防 Byzantine / 不安全通信
- **BlockA2A 不是必须用区块链** — 核心思想是 *identity + audit + access control* 三件套
- **Byzantine detection 关键** — 1 个坏 agent 可拖垮整个 MAS
- **Sub-second overhead 是底线** — 安全机制不能拖慢生产
- **Append-only log = 简化版区块链** — 不必真用 chain, log 即可满足审计
