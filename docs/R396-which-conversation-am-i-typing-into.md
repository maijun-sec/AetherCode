## 0. 结论先说

1. **剪掉了**：`default.jsonl` 末尾 21 行（27,642 字节）是 R394 的测试残留，已删除；文件 1867 → **1846 行**，会话索引计数同步改成真值。备份在 `sessions.bak-r396/`。
2. **「为什么进主流程」有两个答案**：

## 1. 残留的边界（先取证，再动手）

`~/.aethercode/sessions/default.jsonl` 共 **1867 行**：

| 行 | 内容 |
| --- | --- |
| 1–1846 | 用户自己的对话，最后一条是那条 HashMap 结论 |
| 1847 | 我的 6 步提示词（`todo_write` 那一步） |
| 1848 | 引擎 anchor |
| 1849–1866 | 模型 / tool 流水 |
| 1867 | 模型的总结（模型自己确认「未修改任何文件」） |

⇒ 边界在 **1846 / 1847** 之间，是**双向确认**的，不是猜的。

### 1.1 剪除的做法

- **按 bytes 切**（`\n`），不是按字符串行 —— 中文会话里 UTF-8 多字节，按字符切会切坏。
- **动手前双向校验**：被删的第一行必须含 `todo_write`（证明它是我的），保留的最后一行必须含 `HashMap`（证明用户的最后一条没被切掉）。任一条不满足 ⇒ **不动手**。
- **备份放在 `sessions.bak-r396/`**，**不放** `sessions/` 目录里 —— 放进去会被 daemon 当成「第 8 个会话」读出来。
- 剪完把 SQLite 索引里的 `message_count` / `size_bytes` 改成真值（1846 / 4073650）。索引里的数字本来就已经是漂移的（`default` 那一行记的是 33）。

### 1.2 别的地方有残留吗？三处都查了

| 地方 | 结论 |
| --- | --- |
| `~/.aethercode/**` 今天被写过的文件 | 只有 `sessions/default.jsonl`、`sessions/sessions.db`(+shm) |
| 记忆层 DB（`~/.aethercode/sessions.db`，`SessionMemoryStore`） | `session_info` 81 行、**`session_messages` 0 行** ⇒ 没有消息残留 |
| `localStorage` | 没有 `aethercode-session:*` 键 —— 消息缓存早已退休 |
| `aethercode-prompt-history` | 23 条全是用户 8–9 月的输入，我的提示词不在里面 |

⚠️ **两个坑，都记下来了**：

- 记忆层 DB 和会话库**同名不同目录**（`~/.aethercode/sessions.db` vs `~/.aethercode/sessions/sessions.db`）⇒ 查错了地方就会得出「没有残留」的**假阴性**。
- 上一轮我记过「要清 localStorage 缓存」—— **那是错的**：消息缓存早已退休（`migrateLegacyLocalStorage()` 一次性清过），localStorage 里根本没有会话消息。第一版探针用 `String(x)` 匹配对象，是**空针**（`String({})` = `"[object Object]"`）—— 修正成 `JSON.stringify` 后复查，结论才成立。

## 2. 为什么「测试内容」会进主流程 —— 两条责任

### 2.1 我的那一半：repro 往活动会话里打字

产品行为是**对的**：你按回车，消息发给**当前会话**。问题在 R394 的 `r394-live-repro2.mjs`：它连到 CDP 后，直接往当时那个**活动**的输入框打字回车 —— 而那个活动会话就是用户的 RAG 会话。

⇒ 规则（写进 AGENTS.md）：**live repro 动手前必须先开一次性会话**。
⇒ 工具化（`scripts/oneshot-session.mjs`）：

```powershell
node scripts/oneshot-session.mjs open --cwd D:\tmp\abc_1
# → SESSION_ID=...（同时把既有会话的消息数记成基线）
#   ... 跑 repro ...
node scripts/oneshot-session.mjs verify
# → OK：没有既有会话变长
#   或者：!! 有既有会话变长 —— 测试内容漏进了主流程（并逐条列出）
node scripts/oneshot-session.mjs drop <sessionId>
```

`verify` 的判据是**「既有会话的消息数有没有变长」**，不是「我记不记得」。这才是能替代记性的东西。

### 2.2 产品的那一半：应用外壳不显示会话名

CDP 探针读到的实机 DOM：

- header：`✦ AetherCode › No active task`（**task** 名，不是会话名）
- 输入条：`📂 CWD D:\tmp\abc_1`（**cwd**，不是会话名）

⇒ **应用外壳里从来没有出现过会话名**。而用户的 7 个会话**共用同一个 cwd** ⇒ 「我现在打字的这条消息会进哪个会话？」这个问题，**在问它的地方没有答案**。

这不只是「测试会漏进去」的问题 —— 它是用户每天都会遇到的问题：切了会话、切了窗口、看一眼输入条，**分不清**。

## 3. 修法：会话名住 **header**

### 3.1 先量「放哪儿」，再写代码

第一版把会话名放进**输入条**（输入条上有 `📂 cwd`，两个线索并排，视线所在）。代码写完、测试写完、变异台也绿了 —— **然后实测把它否决了**。

实测方法：不在新构建上量，而是**在正在跑的旧版 exe 上注入同样的 CSS + markup**（CDP），直接量布局。理由：cargo 重新链接要 7–9 分钟，而布局在 DOM 层面就能量出来；先量清楚，一次构建到位。

量出来的三件事：

| 量 | 旧版（无 chip） | 加了 chip 之后 |
| --- | --- | --- |
| 输入条内容总宽 | 971px（容器 1110px） | 1046px |
| **输入条高度** | **26px** | **42px** ⬅ 回归 |
| 「🧠 思考」按钮 | 69px，单行 | 58px，**文字换行** |
| 「0.7 / 32k」提示 | 54px，单行 | 38px，**文字换行** |

⇒ **那条输入条已经排满了。** 971 ≠ 139px 余量可用：flex item 的**基线是 max-content 宽度**，加一个组就会挤压其它组，而这些组的文字**恰好卡在临界宽度**上（`🧠 思考` 正好 69px），挤 2px 就换行 ⇒ 输入条从一行变成两行。

⇒ 试了 8 个方案（标签 `🗂 session` / `🗂 会话` / `🗂`，名字上限 76–130px，`flex: 0 10 auto` 让 chip 优先收缩），**全部 FAIL**：不管 chip 多小，别组都会被挤到换行。

### 3.2 于是去量第二个候选：header

| 量 | 值 |
| --- | --- |
| `.header` 宽 | 1440px |
| `.header-left` 宽 | **1015px** |
| `.header-left` 内容实际占 | **223px**（brand 99 + sep 4 + task name 80） |
| ⇒ 横向余量 | **约 790px** |

⇒ header 有近 800px 的余量，**零布局代价**；而且「哪个会话」本来就该住在 header（它是**窗格的身份**，不是输入框的属性）。层级也顺：`✦ AetherCode › 🗂 会话名 › task`。

⇒ 最终形态：

```
✦ AetherCode › 🗂 新增排序方向与字节数组支持 › No active task
```

- 会话名用 `--text-dim`（比 task 名暗）：task 是「你此刻在做什么」，会话是「它发生在哪个容器里」；
- 名字过长 ⇒ 省略号；tooltip 带**完整名 + id**；
- 没有会话 ⇒ 这一段整个不出现（brand › task 保持原样）。

### 3.3 显示什么

| 情况 | 显示 | 为什么 |
| --- | --- | --- |
| 有 title（R393 的模型摘要，5–15 字） | title | 它读起来就像一个名字 |
| 有会话但**没有** title | 短 id（`sess-1`） | 空名字 = 静默失败 |
| **列表还没跟上**（`currentSessionId` 不在 `sessions` 里） | 短 id | ⚠️ **绝不借用别的会话的名字** —— 那比不显示更糟：用户会以为消息要去一个它不去的地方 |
| 还没有会话 | 这一段不出现 | 而不是渲染一个空盒子 |

## 4. 门禁

### 4.1 8 例真渲染测试

`aethercode-desktop/src/components/__tests__/headerSessionR396.test.tsx` —— 真组件 + 真 store + 真 DOM（`useStore.setState` → `render` → 读 DOM），pin 的是**不变量**而不是拼写（R384 的 Lesson 1233）：

1. 会话身份在 header 里
2. 名字跟着**活动会话**走，不是列表第一行
3. 列表没跟上时显示**自己的**短 id，绝不显示别人的名字
4. 未命名会话也有身份（不是空白）
5. 没有会话时不渲染这一段，且 brand / task 名都还在
6. tooltip 带完整名 **+ id**
7. 会话名在 DOM 顺序上**先于** task 名（app › session › task）
8. task 名仍然在（加会话名没有把 task 名顶掉）

### 4.2 8 个变异，全部按设计变红

| 变异 | 注入的缺陷 | 预期红 | 实测红 |
| --- | --- | --- | --- |
| M1 | 永远显示列表第一行 | 2 | 2 ✅ |
| M2 | 去掉短 id 兜底 | 2 | 2 ✅ |
| M3 | 整个会话元素被删 | ≤6 | ✅ |
| M4 | 会话名被挪到 task 名之后 | 1 | 1 ✅ |
| M5 | tooltip 去掉 id | 1 | 1 ✅ |
| M6 | 没有会话时名字为空 | 1 | 1 ✅ |
| M7 | 显示 cwd 而不是会话 | ≤4 | ✅ |
| M8 | 会话元素被渲染到 header **外面** | ≤2 | ✅ |

**变异打在副本上**（`aethercode-desktop/.mutate-r396/src/`）—— 工作树的字节是**输入**，不是输出；跑完还会断言真文件**逐字节未变**。

### 4.3 变异台自己翻过的车

- **量具读错了对象**：第一版比对用了 `it()` 标题的**全等**，而实际标题带破折号后半句 ⇒ 8 个变异全被判「MISSING red」，可红的**条数**其实逐条相符。⇒ 改成**前缀唯一匹配**（一个针脚落在两处 = 没测到东西）。
- **我自己写的空洞断言**：M6（名字置空）暴露了 —— 我读的是**整块**的 `textContent`，而里面还有静态文案 `🗂` ⇒ 名字空了断言照样绿。⇒ 改成读**名字本身**。**这条是变异台抓出来的，不是 review 抓出来的。**

### 4.4 三个探针的自证

实机验证用的探针都先证明自己**能**抓到东西：

- 布局探针在旧版上注入 chip，量出 26 → 42px 的回归（而不是「注入没生效」）；
- 最终探针在旧版上**读得到输入条**（8 个组、clientWidth 1110）但**读不到会话名** ⇒ selector 有效；
- `oneshot-session.mjs verify` 的**负向对照**：把基线里某一条会话的记录数调小 1，verify 必须报出**那一条**并以非零码退出 ⇒ 它不是永远说 OK 的检查。
