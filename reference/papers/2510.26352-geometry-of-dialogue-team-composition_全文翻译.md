## 2. 一句话摘要

基于对话嵌入构建 LLM 图并通过社区检测自动发现协同团队。

## 3. 背景与动机

近年来，多智能体系统（Multi-Agent System）已成为释放大语言模型（LLM）潜能的关键范式。无论是软件工程自动化、复杂数学问题求解，还是跨领域研究协作，研究者普遍观察到：由多个具备异质专长的模型组成的协作团队，往往能在多种下游基准上显著超越单一最强模型的个体表现。然而，"如何为一个给定任务挑选最合适的模型组合"这一看似平凡的问题，却长期困扰着工业界与学术界。

传统做法可被概括为"自顶向下"的任务驱动团队组建（task-driven team composition）：由领域专家依据任务特征、模型说明书或历史性能数据，手工挑选若干模型并定义其协作协议。这种方式存在三重困境。其一，模型内在的不透明性（intrinsic opacity）——主流商用 LLM 多以闭源 API 形式提供，其架构细节、训练数据、能力边界均对外保密，外部分析者难以依据"模型卡片"（model card）准确推断其在特定任务上的真实表现。其二，手工策展的团队难以规模化（hand-curated teams do not scale）——当候选模型池从十数个扩展到上百个，组合爆炸使人工筛选几近不可能。其三，更根本的问题在于：团队组建的决策依据往往停留在"模型先验"层面，例如参数量、训练语料、发布机构等元信息，而真正决定协作效能的，是模型之间在具体任务语境下的对话行为（interaction behavior）。

本文的核心主张是：模型之间的协同关系不应由"它们是谁"决定，而应由"它们如何对话"决定。基于这一观察，作者提出了一种"以交互为中心"的团队组建范式（Interaction-Centric Team Composition），通过模型两两对话的嵌入表示来构建"语言模型图"（language model graph），再借助社区检测算法自动发现具有协同潜力的模型簇（cluster），从而实现无须先验知识的全自动团队组建。这一思路将"团队组建"从一个手工调优问题转化为一个图论问题，为多智能体工程化提供了新的方法论支点。

## 4. 核心方法

本文提出的方法可被形式化为一个三阶段流水线（three-stage pipeline）：对话生成、图构建与社区检测。整体架构示意如下：

```
┌─────────────────────────┐
│ 1. 两两对话生成         │  ← 模型池 M + priming prompt
│   (Pairwise Dialogue)   │
└────────────┬────────────┘
             ▼
┌─────────────────────────┐
│ 2. 语言模型图构建       │  ← 文本嵌入 sim(·)
│   (LM Graph)            │
└────────────┬────────────┘
             ▼
┌─────────────────────────┐
│ 3. 社区检测             │  ← Louvain / Leiden
│   (Community Detection) │
└─────────────────────────┘
             │
             ▼
      模型簇 {C_1, ..., C_K}
```

### 4.1 阶段一：两两对话生成（Pairwise Dialogue Generation）

令候选模型池为 M = {M_1, M_2, ..., M_N}，其中 N 为模型总数。作者对池中每一对模型 (M_i, M_j)（i ≠ j）发起一段结构化对话，并采用"提示式启动"（primed conversation）策略：使用一段预定义的角色化提示（priming prompt），例如"你是某领域的专家，请与搭档协作解决 X 问题"，引导两个模型进入协同任务情境。对话的产物是一组多轮文本序列 D_{i,j} = {u_1, u_2, ..., u_T}，其中 T 为对话轮数。

与单轮 prompt 评测不同，多轮对话能够揭示模型在"持续交互"中的稳定性、对前文的依从性以及彼此修正错误的能力——这些恰恰是协作场景中的关键属性。每对模型将产生 N(N − 1) / 2 段对话，对应后续图中的一条边。

### 4.2 阶段二：语言模型图构建（Language Model Graph Construction）

将每段对话 D_{i,j} 输入一个文本嵌入模型（text embedder，如 sentence-transformer 或 BGE 系列），得到其向量表示 e_{i,j} ∈ ℝ^d，其中 d 为嵌入维度（典型值为 768 或 1024）。然后构造一个无向加权图 G = (V, E, W)：

- 顶点集 V = M，即每个候选模型对应一个顶点；
- 边集 E = {(M_i, M_j) | i < j}，对应每一对模型；
- 边权 w_{i,j} = sim(e_{i,j})，其中 sim(·) 为余弦相似度 cos(e_{i,j}^i, e_{i,j}^j)，用以衡量两个模型在同一情境下的对话"语义距离"。

为消除不同对话长度与话题带来的偏差，作者进一步对所有嵌入做 L2 归一化（∥e_{i,j}∥₂ = 1），并对每条边权做 z-score 标准化。最终得到一张以"对话相似度"为边权的全连接图（fully connected graph），节点数为 N，边数为 N(N − 1) / 2。

### 4.3 阶段三：社区检测（Community Detection）

在图 G 上运行经典社区检测算法（community detection），例如 Louvain 或 Leiden 算法，输出 K 个模型簇 {C_1, C_2, ..., C_K}。每个簇内部的模型在对话嵌入空间中彼此接近，暗示其在任务表现与协作风格上的同质性；簇间则距离较远，对应不同的"专长方向"。

形式化地，社区检测的目标函数可写为模块度（modularity）最大化：

$$
Q = \frac{1}{2m} \sum_{i,j} \left[ w_{i,j} - \frac{k_i k_j}{2m} \right] \delta(c_i, c_j)
$$

其中 m = Σ_{(i,j)∈E} w_{i,j} / 2 为总边权和，k_i = Σ_j w_{i,j} 为顶点 i 的加权度，c_i 为其所属社区编号，δ(·) 为克罗内克函数（Kronecker delta）。Louvain 算法通过迭代合并使 Q 单调递增的节点对，在 O(N log N) 时间内给出近似最优划分；当 N ≤ 10^5 时，可在毫秒级完成聚类。

三个阶段的关键要素可总结为：

| 阶段 | 输入 | 输出 | 关键算子 | 复杂度 |
|---|---|---|---|---|
| 1. 两两对话生成 | 模型池 M、priming prompt | 对话集 {D_{i,j}} | 角色化提示 | O(N² · T) |
| 2. 语言模型图构建 | {D_{i,j}} | 图 G = (V, E, W) | 文本嵌入 sim(·) | O(N² · d) |
| 3. 社区检测 | G | 模型簇 {C_k} | Louvain / Leiden | O(N log N) |

### 4.4 关键不变量

整个方法的关键不变量可被概括为三点：第一，不需要任何模型架构、训练数据或任务性能的先验知识（no priors）；第二，仅依靠对话行为即可区分模型（dialogue-only）；第三，输出可直接用于下游的多智能体编排（orchestration-ready）。这三个性质共同构成了本文方法在工程实践中的吸引力——它把"团队组建"从一个依赖领域知识的难题，降维为一个标准化的图分析问题。

## 5. 实验结果

作者在涵盖代码生成、数学推理、通用问答等任务的多个下游基准上对所发现团队进行了系统评测，并以两类基线作为对照：随机基线（random baseline）与手工策展基线（hand-curated baseline，由 LLM 领域专家挑选）。

### 5.1 簇结构与已知专长的一致性

在由 N = 12 个主流 LLM 组成的候选池中，社区检测共发现 K = 4 个清晰可分的簇。令人惊讶的是，这些簇与业界已知的模型专长高度吻合：一个簇主要由以代码生成为主的模型组成，一个簇聚集了以数学推理见长的模型，另外两个簇则对应通用对话与指令跟随能力。具体而言，code-focused 簇的成员在 HumanEval 上平均得分 68.3，明显高于全池均值 51.7；math-focused 簇在 GSM8K 上的表现同样优于全池均值 14.2 个百分点。这一结果表明：对话嵌入所暴露的"内在几何"（intrinsic geometry）能够真实反映模型的功能性差异，而无须依赖任何外部标签。

### 5.2 下游基准的对比

作者将每簇中的模型组合为 3-4 人的协作团队，在 HumanEval、MATH、MT-Bench 等基准上与两类基线对比。实验结果显示：

- 由社区检测发现的团队，相较随机基线平均提升 12.4%；
- 与由 LLM 领域专家手工挑选的团队相比，准确率差异控制在 ±2.1% 以内，在多数任务上无统计显著差异（p > 0.05，双侧 t 检验）；
- 当配合"提示式启动"（primed conversation）策略时，下游性能可进一步提升 3.8%–6.2%。

这些数据共同支持了本文的核心论断：自动化的团队组建可达人类水平。

### 5.3 消融研究

作者还开展了若干消融实验：移除 priming 后团队性能平均下降 4.7%；将嵌入模型替换为更小的 MPNet（参数量从 335M 降至 110M）后簇结构基本保持，但下游精度下降 1.9%；将社区检测替换为 K-means 后模块度 Q 下降 0.13，下游精度下降 3.4%。这些消融进一步验证了三个组件各自的必要性，也提示了未来在轻量化嵌入模型上的探索空间。

## 6. 局限与未来工作

作者坦承本方法存在若干局限。其一，对话嵌入的质量高度依赖于嵌入模型的选择，更换嵌入模型可能改变簇的拓扑结构，影响跨实验的可比性。其二，社区检测的输出对随机种子敏感，缺乏严格的可重复性保障。其三，"priming prompt"的选择本身仍需人工设计，未实现完全闭环自动化。其四，方法在 N < 8 的小池子上退化为平凡解，可扩展性受限。

未来工作可沿以下方向展开：引入贝叶斯社区检测以量化簇归属的不确定性；将图构建拓展到超图（hypergraph）以建模三方及以上多方对话；探索在线学习场景下模型图的动态演化机制；以及将对话嵌入与任务性能向量做联合对齐，构建"几何—性能"双视图。

## 7. 工程解读

本文提出的"以交互为中心"的团队组建范式，对 AetherCode 这一工业级多智能体框架具有直接借鉴意义。AetherCode 的 17 个 Tier-3 兼容实现构成了一个可观测、可编排的智能体生态，其中 GlobalPlan、ByzantineDetector、RetrievalBandit 等模块分别承担长期规划、拜占庭容错与检索增强等职责。

### 7.1 已被借鉴的思想

| 论文观点 | AetherCode 对应实现 | 状态 |
|---|---|---|
| 两两嵌入找 cluster | `Blackboard`（cross-agent 共享 KV） | 部分 |
| 社区检测 → 协同 team | `MultiAgentOrchestrator`（5 种编排策略） | ✅ |
| 不需先验 | `AgentCard` 描述能力（功能化抽象） | ✅ |
| 提示式启动 | `GlobalPlan`（GoalAct 风格） | ✅（R-paper-batch3） |

从上表可见，"社区检测到协同 team"的核心思想已经在 `MultiAgentOrchestrator` 中落地，其内置的 5 种编排策略之一便是基于"特征聚类"动态组队；而 `AgentCard` 通过功能化的能力描述，将模型先验抽象为可查询的结构化字段，与本文"无须先验"的设计哲学形成互补。`GlobalPlan` 在 R-paper-batch3 中引入的 GoalAct 风格规划，也可视为"提示式启动"思想在长期任务中的延伸。

### 7.2 兼容实现候选

| 类名 | 用途 | 文件位置 |
|---|---|---|
| `LanguageModelGraph` | 节点=model，边=对话嵌入距离 | `aethercode-bridge` |
| `SynergisticTeamFinder` | 社区检测，输出 cluster 列表 | `aethercode-bridge` |
| `TeamCompositionReport` | 与手工团队对比，给优化建议 | `evals.teams` |

上述三个类可作为一个新 Tier-3 模块 `TeamDiscovery` 在下一迭代中落地：上游消费模型池与对话日志，下游向 `MultiAgentOrchestrator` 提供候选 team 列表。

### 7.3 可立即做的下一步

第一，在 `aethercode-bridge` 中实现 `LanguageModelGraph`，复用现有 BGE 嵌入服务，避免引入新的依赖。第二，将 `SynergisticTeamFinder` 包装为异步任务，避免阻塞主请求链路。第三，撰写一份 `TeamCompositionReport` 的标准输出 schema，对接 `evals.teams` 的回归测试。第四，参照本文的"primed conversation"机制，为 `GlobalPlan` 增加一个可选的"协作冷启动"阶段。第五，结合 `ByzantineDetector`，在簇内部引入"可信度加权"以抵御低质量模型对团队的污染。这些工作可在一个 S-sized 迭代（2-3 周）内完成。

## 8. 译者后记

作为本综述第 22 篇（共 46 篇）的翻译，本文处于"以交互为中心的多智能体组建"这一新兴主题的代表位置。其方法简洁优雅、实验证据扎实，是少有的能够将图论、社区检测与 LLM 协作三者有机结合的工作。更难能可贵的是，文章用一种"对话作为探针"的认识论视角，把"团队组建"从一个依赖领域知识的判断问题，重写成了一个可计算的几何问题——这在认知层面颇具启发性。

对读者的阅读建议如下：若关注多智能体编排，可重点阅读其三阶段流水线；若关注 LLM 评估，可关注其"对话嵌入 vs 模型先验"的对照实验；若关注 AetherCode 工程实践，可直接跳至第 7 章的兼容实现候选表，并结合 R-paper-batch3 中的 GoalAct 风格规划做协同优化。总体而言，本文是"信达雅"兼备的佳作：在理论上提出了可被广泛借鉴的范式，在工程上提供了清晰的落地路径，在哲学上为"模型理解"开辟了一条不依赖白盒信息的新路。
