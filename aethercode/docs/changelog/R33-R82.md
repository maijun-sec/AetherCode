## R33-R48 retrospective (highlights)

See [R33-R48-PROGRESS.md](R33-R48-PROGRESS.md) for the per-round table.

The R33-R48 work focused on **TUI visual differentiation**:
- 5 distinct tool categories (read/write/search/run/agent) with
  unique colors + icons + spinner variants
- 5 distinct stop reasons with color-coded borders + sticky banners
- 11 keybindings, 22 slash commands, 3 themes, 3 layout presets

**Critical pitfall (R59)**: I added a `<Welcome>` render in `tui.tsx`
without importing it. The esbuild bundle succeeded (lenient) but
the `tsc` compile failed. From R59 onwards, every test file ends
with a `tsc --jsx react` smoke test.

## R49-R61 retrospective (highlights)

See [R33-R61-PROGRESS.md](R33-R61-PROGRESS.md) for the per-round table.

## R77 retrospective

See [R77.md](R77.md).

First **backend + TUI** round. New RPC `getMetrics` exposes engine
counters. E2E proved the counters reflect real activity
(`turnsStarted=1, toolCalls=1, turnsCompleted=1` after a real query).

**Pitfall (R77)**: `mvn package` doesn't rebuild the dist JAR. Must
use `build.ps1 -SkipTests` (which uses `maven-shade-plugin` with
explicit `finalName=0.2.1`). This is now documented in
[adding-rounds.md](../dev-guide/adding-rounds.md#6-build-30-seconds).

**Pitfall (R77)**: rate ratios must guard against 0-division
(`d <= 0 ? 0.0 : n/d`). Without the guard, a fresh daemon
returned `NaN` which serialised to `null` and broke the E2E.

## R78 retrospective

See [R78.md](R78.md).

Second **backend + TUI** round. New RPC `getTraces` exposes the
recent span recorder (one root `query` span per turn + one
`tool.<name>` span per tool invocation). `/trace` (and
`/trace <n>`) renders a small table with status icon + name +
duration. E2E proved the recorder reflects real activity
(`completed=1, traces=1` after a real query that triggered a
`tool.glob` call).

**Pitfall (R78)**: `ConcurrentLinkedDeque` is not enough for a
bounded deque under concurrent writers. The size-guard + addLast
pair needs to be atomic. The first test pass failed the 8-thread
× 200-iter concurrent test (`expected: <true> but was: <false>`);
marking `endSpan` `synchronized` fixed it. Same class of pitfall
as the R59 `Welcome` import bug — small test leaks the race.

**Pattern (R78 generalises R77)**: every "engine observability"
feature follows the same recipe —
1. New Java class (`MetricsCollector`, `TraceRecorder`, future
   `AuditLog`, `RateLimiter`).
2. `AetherCodeEngine` accessor (`metrics()`, `traces()`, ...).
3. New `AetherCodeMethods` RPC.
4. TUI state field + reducer action.
5. Slash command + TUI render.
6. Java test + TUI test + E2E.
7. Doc update (5 files: features, keybindings, slash-commands,
   jsonrpc, state-model + per-round retro).

The recipe is repeatable; R79 candidates (audit log, span tree,
live trace pane) all fit the same shape.

## R79 retrospective

See [R79.md](R79.md).

Third **backend + TUI** round. New RPC `getTrace(traceId)`
exposes the tree (one root + all descendants) for a single
trace. Tool spans are now opened with `startChildSpan(rootId,
…)` so the parent linkage is recorded. `/trace <id>` (where
`<id>` starts with `tr-`) renders the tree with `├─` / `└─` /
`│` connectors. E2E proved the tree assembly works on a real
query: `query (parent=null) └─ tool.glob (parent=rootId)`.

**Pitfalls (R79)**: 4 caught by tests / E2E / unit. The
grandchild test surfaced "tree emit order ≠ deque order" and
"only root has children wired" — both fixed by emitting during
the BFS and iterating `byId` to wire every node. The orphan
test surfaced "orphan detection" — should be `parent not in
spans list` not `parentSpanId == null`. The `/trace` arg
detection must check the `tr-` prefix before numeric parsing
or `tr-1` would become `limit: 1`.

**Pattern (R79 generalises R78)**: tree assembly is the same
recipe as a flat-list display — backend collector +
parent linkage + RPC + TUI state + slash command + render
+ tests + docs. The visual difference (tree vs list) is
isolated to the TUI render function.

**Three rounds in a row (R77, R78, R79)**: each round adds
~1 Java class, ~1 RPC, ~1 slash command, ~1 render style,
~1 doc. The cadence is sustainable; the next axis is
**multi-step task execution** (DagPlan + PlanExecutor →
`executeDag` RPC + `/dag`).

## R80+ (planned)

Next-up candidates (in priority order):

1. **R80: live trace pane** — push model instead of pull.
   Daemon emits a `trace_event` notification on every
   `startSpan` / `endSpan`; the TUI keeps a rolling list of
   in-flight spans.
2. **R81: span persistence** — write completed spans to
   `~/.aethercode/traces.jsonl` so `/trace <id>` works
   across daemon restarts.
3. **R82: audit log** — persist every `permission_request` /
   `permission_response` to `~/.aethercode/audit.jsonl`;
   `/audit tail` shows the last 20 entries.
4. **R68: DAG execution** — `executeDag` RPC that accepts
   a step list and runs them via `PlanExecutor`. `/dag
   "step1" "step2" "step3"` runs sequentially.

After R82 the pattern is exhausted and the next axis is
multi-step task execution (DAG) or long-running jobs
(caching, checkpoint + resume).
