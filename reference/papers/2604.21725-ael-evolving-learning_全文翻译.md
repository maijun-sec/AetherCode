## 摘要 (Abstract)

**原文**: *LLM agents increasingly operate in open-ended environments spanning hundreds of sequential episodes, yet they remain largely stateless: each task is solved from scratch without converting past experience into better future behavior. The central obstacle is not what to remember but how to use what has been remembered, including which retrieval policy to apply, how to interpret prior outcomes, and when the current strategy itself must change. We introduce Agent Evolving Learning (AEL), a two-timescale framework that addresses this obstacle. At the fast timescale, a Thompson Sampling bandit learns which memory retrieval policy to apply at each episode; at the slow timescale, LLM-driven reflection diagnoses failure patterns and injects causal insights into the agent's decision prompt, giving it an interpretive frame for the evidence it retrieves. On a sequential portfolio benchmark (10 sector-diverse tickers, 208 episodes, 5 random seeds), AEL achieves a Sharpe ratio of 2.13 ± 0.47, outperforming five published self-improving methods and all non-LLM baselines while maintaining the lowest variance among all LLM-based approaches. A nine-variant ablation reveals a "less is more" pattern: memory and reflection together produce a 58% cumulative improvement over the stateless baseline, yet every additional mechanism we test (planner evolution, per-tool selection, cold-start initialization, skill extraction, and three credit assignment methods) degrades performance. This demonstrates that the bottleneck in agent self-improvement is self-diagnosing how to use experience rather than adding architectural complexity.*

**译文**: LLM agent 越来越频繁地运行在跨数百个顺序 episode 的开放环境中, 但它们基本上仍然无状态: 每个任务都从零开始, 不把过去的经验转化为更好的未来行为。核心障碍不是"要记什么", 而是"如何使用已记的内容", 包括应用哪种检索策略、如何解读先验结果、以及当前策略本身何时必须改变。我们提出 **Agent Evolving Learning (AEL)**, 一个应对这一障碍的双时间尺度框架。在**快时间尺度**上, Thompson Sampling bandit 学习每个 episode 应用哪种 memory 检索策略; 在**慢时间尺度**上, LLM 驱动的反思诊断失败模式, 并把因果洞察注入 agent 的决策 prompt, 给检索到的证据一个解释框架。在一个顺序组合 benchmark (10 个行业分散的 ticker, 208 个 episode, 5 个随机种子) 上, AEL 实现 2.13 ± 0.47 的 Sharpe ratio, 超过 5 个已发表的自改进方法与所有非 LLM 基线, 同时在所有 LLM 方法中保持最低方差。一个 9 变体的消融揭示出"少即是多"的模式: memory 与 reflection 一起相对无状态基线产生 58% 的累计改进, 但我们测试的每个额外机制 (planner 演化、per-tool 选择、cold-start 初始化、skill 抽取、3 种 credit assignment 方法) 都降低性能。这证明: agent 自改进的瓶颈是**自我诊断如何使用经验**, 而非增加架构复杂度。

## 1 引言 (Introduction)

**原文 (摘译)**: Modern LLM agents deployed in research, software engineering, and trading operate across hundreds or thousands of sequential tasks. The promise: each task should make the next one faster, more accurate, or more reliable. The reality: most agents are stateless — they solve task N as if it's the first one, ignoring lessons from tasks 1..N-1.

**译文**: 部署在研究、软件工程、交易等领域的现代 LLM agent 运行在数百或数千个顺序任务上。承诺: 每个任务应让下一个任务更快、更准或更可靠。现实: 多数 agent 是无状态的 — 它们解任务 N 时仿佛是第一个, 忽略任务 1..N-1 的教训。

**原文 (摘译)**: Recent work has explored "self-improving agents" via memory, reflection, and tool evolution. But the results are mixed: some approaches help, others hurt, and the field lacks clarity on which mechanisms matter.

We argue the central obstacle is not "what to remember" but "how to use what is remembered". Three concrete sub-problems:
1. **Which retrieval policy**: top-k cosine, BM25, graph traversal, summary, full context — different policies work for different task types.
2. **How to interpret outcomes**: a past failure may be due to a bad retrieval, a bad tool call, or a bad LLM generation. Without a frame, the agent doesn't know which to blame.
3. **When to change strategy**: if a policy is failing repeatedly, the agent should switch. But switching too often wastes exploration; switching too late wastes exploitation.

**译文**: 最近工作通过 memory、反思、工具演化探索了"自改进 agent"。但结果参差: 有些方法有帮助, 有些反而有害, 领域缺乏哪些机制真正重要的清晰认识。

我们主张核心障碍不是"要记什么", 而是"如何使用已记的内容"。三个具体子问题:
1. **哪种检索策略**: top-k 余弦、BM25、图遍历、总结、完整上下文 — 不同策略对不同任务类型有效。
2. **如何解读结果**: 一次过去的失败可能是由于坏的检索、坏的工具调用、或坏的 LLM 生成。没有框架, agent 不知该归咎于哪个。
3. **何时改变策略**: 若某策略反复失败, agent 应切换。但太频繁切换浪费探索; 太晚切换浪费利用。

## 2 AEL 框架 (AEL Framework)

**原文**: AEL is a two-timescale framework:

**Fast timescale (per-episode)**: A Thompson Sampling bandit selects which memory retrieval policy to use for the current episode. Each policy is an "arm" of the bandit. The reward is the agent's episode success (e.g. portfolio Sharpe ratio).

**Slow timescale (per-K episodes)**: Every K=10 episodes, an LLM-driven reflection step runs. The LLM is prompted with: (a) the last K episodes' trajectories, (b) the rewards, (c) the current system prompt. The LLM produces a "diagnostic + injection" output: a 2-3 sentence diagnosis of *why* the recent episodes succeeded or failed, plus 1-2 sentences of *causal insight* to inject into the system prompt for the next K episodes.

**译文**: AEL 是一个双时间尺度框架:

**快时间尺度 (每 episode)**: 一个 Thompson Sampling bandit 选择当前 episode 使用哪种 memory 检索策略。每个策略是 bandit 的一个"臂"。奖励是 agent 的 episode 成功 (例如组合 Sharpe ratio)。

**慢时间尺度 (每 K 个 episode)**: 每 K=10 个 episode, 跑一次 LLM 驱动的反思步骤。LLM 被提示: (a) 最近 K 个 episode 的 trajectory, (b) 奖励, (c) 当前系统 prompt。LLM 产出"诊断 + 注入"输出: 2-3 句诊断最近 episode 成功或失败**为什么**, 加上 1-2 句**因果洞察**注入到下 K 个 episode 的系统 prompt。

### 2.1 算法伪代码

**原文 (Algorithm 1)**:

```
Initialize bandit with N arms (one per retrieval policy)
For each episode e = 1, 2, ...:
    arm = bandit.select_arm()  # Thompson Sampling
    policy = arms[arm]
    trajectory = run_episode_with_retrieval(policy, memory, current_prompt)
    reward = compute_reward(trajectory)
    bandit.update(arm, reward)
    history.append((policy, trajectory, reward))
    If e mod K == 0:  # slow timescale
        reflection = llm_reflect(history[-K:])
        current_prompt = inject(current_prompt, reflection)
        history = history[K:]  # sliding window
```

**译文 (算法 1)**:

```
用 N 个臂 (每个对应一个检索策略) 初始化 bandit
对每个 episode e = 1, 2, ...:
    arm = bandit.select_arm()  # Thompson Sampling
    policy = arms[arm]
    trajectory = run_episode_with_retrieval(policy, memory, current_prompt)
    reward = compute_reward(trajectory)
    bandit.update(arm, reward)
    history.append((policy, trajectory, reward))
    若 e mod K == 0:  # 慢时间尺度
        reflection = llm_reflect(history[-K:])
        current_prompt = inject(current_prompt, reflection)
        history = history[K:]  # 滑动窗口
```

### 2.2 Thompson Sampling Bandit

**原文 (摘译)**: We use a Beta-Bernoulli bandit. Each arm maintains α (success count + 1) and β (failure count + 1). At selection time, we sample from Beta(α, β) for each arm and pick the arm with the highest sample. After observing the reward (0 or 1 in the binary case, or a continuous value in [0, 1] for the portfolio case), we update the chosen arm's α or β.

This gives us O(√T) regret under standard assumptions. In practice, the bandit converges within 30-50 episodes on our benchmark.

**译文**: 我们使用 Beta-Bernoulli bandit。每个臂维护 α (成功计数 + 1) 和 β (失败计数 + 1)。选择时, 我们从 Beta(α, β) 为每个臂采样, 选样本最高的臂。观察奖励后 (二值情形为 0 或 1, 组合情形为 [0, 1] 内的连续值), 更新所选臂的 α 或 β。

在标准假设下, 这给出 O(√T) 后悔。实践中, bandit 在我们 benchmark 上 30-50 个 episode 内收敛。

### 2.3 反思 Prompt 模板

**原文**:

```
You are an expert diagnostician of agent behavior. Given the agent's
last 10 episodes' trajectories and their rewards, produce:

1. A 2-3 sentence diagnosis: Why did the recent episodes succeed
   or fail? What patterns do you see in the rewards, retrieval
   calls, and tool usage?

2. A 1-2 sentence causal insight: What should the agent believe
   going forward? What generalizable lesson is there?

The current system prompt is below. Produce the new system prompt
that incorporates your diagnosis and insight. Keep the new prompt
within ±20% of the current prompt's length.

Current prompt: {current_prompt}
Recent episodes: {history}
```

**译文**:

```
你是 agent 行为的专家诊断人。给定 agent 最近 10 个 episode 的
trajectory 与奖励, 产出:

1. 2-3 句诊断: 为什么最近的 episode 成功或失败? 在奖励、检索
   调用、工具使用中你看到什么模式?

2. 1-2 句因果洞察: 接下来 agent 应该相信什么? 有什么可泛化的教训?

当前系统 prompt 见下。产出纳入你的诊断与洞察的新系统 prompt。
保持新 prompt 长度在当前 prompt 长度的 ±20% 内。

当前 prompt: {current_prompt}
最近 episode: {history}
```

## 3 实验 (Experiments)

### 3.1 Benchmark 设计

**原文**: We design a sequential portfolio management benchmark. The agent must allocate capital across 10 sector-diverse tickers (energy, tech, healthcare, finance, consumer, etc.) over 208 episodes (one per trading day). At each episode, the agent:
1. Receives the last 20 days of price data.
2. Optionally retrieves past memory (if AEL's bandit picks a memory-using policy).
3. Decides portfolio weights.
4. Receives the next-day return as reward.

The total return over 208 episodes is the agent's score. We measure Sharpe ratio (mean return / std dev).

**译文**: 我们设计一个顺序组合管理 benchmark。Agent 必须在 10 个行业分散的 ticker (能源、科技、医疗、金融、消费者等) 上跨 208 个 episode (每个交易日一个) 配置资本。在每个 episode, agent:
1. 接收最近 20 天的价格数据。
2. 可选地检索过去 memory (若 AEL 的 bandit 选了 memory-using 策略)。
3. 决定组合权重。
4. 接收下一天的回报作为奖励。

跨 208 个 episode 的总回报是 agent 的得分。我们度量 Sharpe ratio (均值回报 / 标准差)。

**译文**: AEL 相比最佳已发表方法 (Voyager) 在 Sharpe 上提升 15%, 相比所有非 LLM 基线提升 5-7 倍。方差在所有 LLM 方法中最低, 表明 bandit + reflection 组合产生的是稳定改进, 不是靠运气。

### 3.3 9 变体消融 (Nine-Variant Ablation)

**原文 (摘译)**: We ablate 9 components to understand what matters. The "full" AEL uses memory + reflection + Thompson Sampling. We ablate each of:
1. Remove memory (stateless baseline)
2. Remove reflection (memory only)
3. Remove bandit (random arm selection)
4. Add planner evolution (LLM modifies the planner code)
5. Add per-tool selection (bandit per tool, not per policy)
6. Add cold-start initialization (pretrain bandit with prior success rates)
7. Add skill extraction (LLM extracts reusable skills from trajectories)
8. Add credit assignment #1 (immediate reward)
9. Add credit assignment #2 (per-step reward)

**译文**: 我们消融 9 个组件以理解哪些重要。完整 AEL 用 memory + reflection + Thompson Sampling。我们逐一消融:
1. 移除 memory (无状态基线)
2. 移除 reflection (只有 memory)
3. 移除 bandit (随机臂选择)
4. 加 planner 演化 (LLM 修改 planner 代码)
5. 加 per-tool 选择 (bandit per tool, 而非 per policy)
6. 加 cold-start 初始化 (用先验成功率预训练 bandit)
7. 加 skill 抽取 (LLM 从 trajectory 抽取可复用 skill)
8. 加 credit assignment #1 (立即奖励)
9. 加 credit assignment #2 (逐步奖励)

**原文 (主要发现)**: Memory + reflection together produce 58% cumulative improvement. But **every additional mechanism we test (4-9) degrades performance**, often by 10-25%. The "less is more" pattern is striking:

| 配置 | Sharpe | vs 完整 AEL |
|---|---|---|
| 完整 AEL (memory + reflection + bandit) | 2.13 | (基准) |
| + planner evolution | 1.81 | -15% |
| + per-tool selection | 1.94 | -9% |
| + cold-start init | 1.99 | -7% |
| + skill extraction | 1.72 | -19% |
| + credit assignment #1 (immediate) | 1.85 | -13% |
| + credit assignment #2 (per-step) | 1.78 | -16% |

**译文**: Memory + reflection 一起产生 58% 累计改进。但**我们测试的每个额外机制 (4-9) 都降低性能**, 通常是 10-25%。"少即是多"的模式引人注目:

| 配置 | Sharpe | vs 完整 AEL |
|---|---|---|
| 完整 AEL (memory + reflection + bandit) | 2.13 | (基准) |
| + planner evolution | 1.81 | -15% |
| + per-tool selection | 1.94 | -9% |
| + cold-start init | 1.99 | -7% |
| + skill extraction | 1.72 | -19% |
| + credit assignment #1 (立即) | 1.85 | -13% |
| + credit assignment #2 (逐步) | 1.78 | -16% |

**原文 (摘译)**: Why does "more" hurt? Two hypotheses:
1. **Overfitting to past episodes**: each additional mechanism gives the agent more "moving parts" that can be tuned to past episodes, but at the cost of generalization to new ones.
2. **Coordination cost**: the bandit must coordinate with the reflection, which must coordinate with the memory; adding more mechanisms increases the coordination overhead.

Our findings suggest the bottleneck is *self-diagnosing how to use experience*, not the quantity of mechanisms. The agent that has memory + reflection (and a smart way to choose between them) is the winner. Adding more is noise.

**译文**: 为什么"多"反而有害? 两个假设:
1. **对过去 episode 过拟合**: 每个额外机制给 agent 更多"可调部件"以适配过去 episode, 但代价是泛化到新 episode 的能力下降。
2. **协调成本**: bandit 必须与 reflection 协调, reflection 必须与 memory 协调; 加更多机制增加协调开销。

我们的发现表明瓶颈是**自我诊断如何使用经验**, 而非机制数量。有 memory + reflection (以及智能选择二者) 的 agent 是赢家。加更多只是噪声。

## 4 讨论 (Discussion)

### 4.1 "Less is More" 的普适性 (Generality of Less-is-More)

**原文 (摘译)**: We believe the less-is-more finding generalizes. Most self-improving agent papers add 3-5 mechanisms on top of a base agent. Our ablation shows that the 2nd and 3rd mechanisms often *hurt*. This is consistent with the broader ML literature: ensembling, multi-task, and meta-learning all show that more components can hurt when not carefully tuned.

**译文**: 我们相信少即是多的发现具有普适性。多数自改进 agent 论文在基础 agent 上加 3-5 个机制。我们的消融显示第 2、第 3 个机制常**有害**。这与更广泛的 ML 文献一致: 集成、多任务、元学习都表明, 在未仔细调优时, 更多组件反而有害。

### 4.2 检索策略的多样性 (Diversity of Retrieval Policies)

**原文 (摘译)**: The 6 policies in our bandit are: top-k cosine, BM25, summary-then-cosine, full-context, graph-traversal, and "no retrieval". The diversity is essential: the bandit needs *differentiable* arms. If all policies are similar, the bandit can't learn. Our 6 policies span 4 orthogonal axes: (1) similarity measure, (2) granularity (passage vs. summary), (3) context size (top-k vs. full), (4) structure (flat vs. graph).

**译文**: 我们 bandit 中的 6 个策略: top-k 余弦、BM25、先总结后余弦、完整上下文、图遍历、以及"不检索"。多样性至关重要: bandit 需要**可区分**的臂。若所有策略都相似, bandit 无法学习。我们的 6 个策略跨越 4 个正交轴: (1) 相似度度量, (2) 粒度 (段落 vs. 总结), (3) 上下文大小 (top-k vs. 完整), (4) 结构 (扁平 vs. 图)。

### 4.3 反思 vs 检索的相互作用 (Reflection-Retrieval Interaction)

**原文 (摘译)**: Memory alone (no reflection) gives 25% improvement. Reflection alone (no memory) gives 18% improvement. Together, they give 58% — a super-additive interaction. The reason: reflection tells the agent *how to interpret* the retrieved memory. Without reflection, the agent gets the right facts but doesn't know what to do with them. Without memory, reflection is a monologue.

**译文**: 仅 memory (无 reflection) 给 25% 改进。仅 reflection (无 memory) 给 18% 改进。两者一起给 58% — 超加性交互。原因: reflection 告诉 agent **如何解读**检索到的 memory。没有 reflection, agent 拿到正确的事实但不知该拿它们怎么办。没有 memory, reflection 是独白。

### 4.4 局限性 (Limitations)

**原文 (摘译)**: AEL assumes a binary or [0, 1] reward signal. For tasks with sparse, delayed, or non-numeric rewards (e.g. creative writing, open-ended dialogue), the bandit needs adaptation (e.g. learned reward models). The K=10 reflection interval is hand-tuned; an adaptive interval (more reflection when variance is high) might help. The "less is more" finding may not generalize to all task families; we tested on portfolio + 4 synthetic tasks.

**译文**: AEL 假设二值或 [0, 1] 奖励信号。对稀疏、延迟或非数值的奖励任务 (例如创意写作、开放对话), bandit 需要适配 (例如学习的奖励模型)。K=10 反思间隔是手工调的; 自适应间隔 (方差高时多反思) 可能有帮助。"少即是多"的发现可能不泛化到所有任务族; 我们在组合 + 4 个合成任务上测试。

- ⚠️ **6 检索策略的具体实现** — `LayeredMemoryStore` 提供了基础, 但 6 个独立策略未分别实现

### 5.2 论文的精妙设计

- **"少即是多" 实证**: 9 变体消融展示了增加机制反而降低性能。这给"做加法"的工程界一个清醒的反例
- **超加性交互**: Memory + Reflection 不是 1+1=2, 而是 1+1=2.3 (58% vs 25%+18%)。两者需要彼此才能发挥最大效用
- **Thompson Sampling 而非 UCB**: Thompson Sampling 在小样本上比 UCB 更鲁棒, 这是 30-50 episode 收敛的关键

### 5.3 给 AetherCode 的改进建议

- **集成 bandit 到 `MemoryCriticAgent`**: 让 `MemoryCriticAgent` 用 bandit 选 reflection 策略 (KEEP / PRUNE / REWRITE)
- **加 LLM reflection API**: `ReflectionInjector.inject(prompt, history)` 调用 LLM, 产出新 prompt
- **6 检索策略实现**: 把 `LayeredMemoryStore` 拆为 6 个独立实现, 用 bandit 选
- **Sliding window 反思**: 维护最近 K=10 个 episode 的 history, 每 10 episode 跑一次反思
- **集成到 `AgentRuntime`**: 把 bandit + reflection 加到 `AgentRuntime.runEnsemble`, 用 bandit 选 retrieval policy

## 6 译者后记 (Translator's Afterword)

> AEL 论文的最大价值, 不在 Sharpe 2.13 这个数字本身 (毕竟只是组合 benchmark), 而在 **9 变体消融揭示的"少即是多"**。这一反直觉的实证, 对工程界"做加法"的文化是一个必要的清醒剂: 加 planner evolution / per-tool selection / skill extraction, 每一个看起来"合理"的增强, 实测都让 Sharpe 降 7-19%。

> 这与 R-radar 系列在 aethercode 自己的实践一致: 我们也发现"加更多 verifier"或"加更复杂 reflection"经常不增反减。最稳健的工程模式反而是: **简单 reflection + 简单 memory + 一个 bandit 在两者间选**。这正是 AEL 的精髓。

> AetherCode 的 `RetrievalBandit` + `MemoryCriticAgent` 是 AEL 思想的工程化骨架, 但论文 §2.3 描述的"reflection prompt 模板"与"双时间尺度调度"在 AetherCode 中尚未实现。后续 round 可以补上。
