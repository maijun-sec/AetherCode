## 摘要 (Abstract)

**原文**: *LLM-based agents often interleave thinking and acting in a single loop, which can lead to planning errors propagating into execution. We propose Plan-and-Act, a two-stage framework that explicitly separates the planning phase from the execution phase. In the planning phase, the LLM produces a complete plan before any action is taken. In the execution phase, the LLM executes the plan one step at a time, with the option to revise the plan between steps. We evaluate Plan-and-Act on 3 benchmarks (HotpotQA, ALFWorld, AppWorld) and show 8-15% absolute improvement over ReAct, with 20-40% fewer LLM calls. The key insight: separating planning from execution reduces compounding errors by giving the agent an explicit "thinking" phase before any irreversible action.*

**译文**: 基于 LLM 的智能体常常在单循环中交错思考与行动, 这会导致规划错误扩散到执行。我们提出 **Plan-and-Act**, 一个把规划阶段与执行阶段显式分离的双阶段框架。在规划阶段, LLM 在采取任何动作前产出完整规划。在执行阶段, LLM 一步步执行规划, 步骤间可选择修订。我们在 3 个 benchmark (HotpotQA、ALFWorld、AppWorld) 上评估 Plan-and-Act, 展示比 ReAct 提升 8-15 个绝对百分点, LLM 调用减少 20-40%。关键洞察: 规划与执行的分离, 通过给 agent 一个在任何不可逆动作之前的显式"思考"阶段, 减少了复合错误。

## 1 引言

**原文 (摘译)**: 现有 LLM agent 框架 (ReAct, Reflexion) 在单一循环中交错 thought 与 action。问题: 规划错误在第一步就潜入, 然后每步基于错误前提, 错误在执行中放大。ReAct 的缓解: 在每步后让 LLM 重新思考 — 但这贵 (每步一次额外 LLM 调用) 且不可靠 (重新思考也可能错)。

Plan-and-Act 的方案: 显式分两阶段, 第一阶段专心规划, 第二阶段专心执行。中间可插入 reflection。

**译文**: 现有 LLM agent 框架 (ReAct、Reflexion) 在单一循环中交错思考与行动。问题: 规划错误在第一步就潜入, 然后每步基于错误前提, 错误在执行中放大。ReAct 的缓解: 在每步后让 LLM 重新思考 — 但这贵 (每步一次额外 LLM 调用) 且不可靠 (重新思考也可能错)。

## 2 Plan-and-Act 框架

### 2.1 两阶段设计

**原文**: The framework has 2 main phases:

**Phase 1 (Planning)**: Given the user query and the available tools, the LLM produces a complete plan (a sequence of steps). The plan is verified for completeness and coherence (e.g. by a second LLM call or by rule-based checks).

**Phase 2 (Execution)**: The LLM executes the plan step by step. After each step, the LLM can:
- **Continue** to the next step (if current step succeeded and next is straightforward)
- **Re-plan** the remaining steps (if current step revealed new information or failed)
- **Finish** early (if the goal is achieved before all steps are done)

**译文**: 框架有 2 个主要阶段:

**阶段 1 (规划)**: 给定用户查询与可用工具, LLM 产出完整规划 (步骤序列)。规划经完整性与一致性验证 (例如用第二次 LLM 调用或基于规则检查)。

**阶段 2 (执行)**: LLM 一步步执行规划。每步后, LLM 可:
- **继续** 下一步 (若当前步成功且下一步直接)
- **重新规划** 剩余步骤 (若当前步揭示新信息或失败)
- **提前结束** (若目标在所有步完成前已达成)

### 2.2 规划验证 (Plan Verification)

**原文 (摘译)**: We adopt two verification strategies:
1. **Rule-based**: The plan must (a) end with a "final" step, (b) reference only available tools, (c) have no circular dependencies. Cheap (< 50 ms).
2. **LLM-based**: A second LLM call reviews the plan for "would this lead to the goal?". Costs an extra LLM call but catches 30-40% more errors.

**译文**: 我们采用两种验证策略:
1. **基于规则**: 规划必须 (a) 以"最终"步结束, (b) 只引用可用工具, (c) 无循环依赖。便宜 (< 50 毫秒)。
2. **基于 LLM**: 第二次 LLM 调用审查规划是否"会导致目标"。多一次 LLM 调用, 但多捕获 30-40% 错误。

## 3 实验 (Experiments)

### 3.1 主要结果

| 方法 | HotpotQA F1 | ALFWorld 成功率 | AppWorld 成功率 | 平均 LLM 调用 |
|---|---|---|---|---|
| **ReAct** | 0.42 | 0.55 | 0.18 | 15.2 |
| **Reflexion** | 0.51 | 0.68 | 0.29 | 22.4 |
| **Plan-and-Act (LLM verify)** | **0.56** | **0.74** | **0.34** | 11.5 |

**原文 (摘译)**: Plan-and-Act beats ReAct by 8-15% absolute across all 3 benchmarks while using 20-40% fewer LLM calls. The savings come from the planning phase: by thinking once at the start, the agent avoids costly mid-execution replanning. The LLM verification adds 1 extra call per task but improves accuracy by 3-5 points over rule-based verification alone.

**译文**: Plan-and-Act 在 3 个 benchmark 上比 ReAct 提升 8-15 个绝对百分点, LLM 调用减少 20-40%。节省来自规划阶段: 在开始时想一次, agent 避免执行中昂贵的重新规划。LLM 验证每任务多一次调用, 但比纯规则验证多提升 3-5 个百分点。

## 4 工程解读: 跟 AetherCode 的对应关系

| Paper 观点 | AetherCode 实现 |
|---|---|
| 两阶段 (Plan → Act) | `AgentRuntime.run()` 阶段化: V (verify) → self-correct → ensemble |
| Rule-based 规划验证 | `RuleVerifier` / `SchemaVerifier` (cheap) |
| LLM-based 规划验证 | `LlmJudgeVerifier` (贵但更准) |
| 步间 re-plan | `SelfCorrectionLoop` (每个 attempt 是 re-plan 机会) |
| Finish 提前 | `AgentRuntime.RuntimeResult.passed()` 提前退出 |

### 关键工程启示

- **避免在单循环中"思考+行动"**: AetherCode 的 `AgentRuntime` 已经按阶段化设计, 跟 Plan-and-Act 思路一致
- **LLM 验证贵但值得**: 论文显示 +3-5 pp, 值得在 critical 路径上加
- **早退机制重要**: 用户体验上"快答"比"答全"更重要

## 5 译者后记

> Plan-and-Act 的洞察看似平凡 (把规划与执行分开), 实际上 30%+ 的 LLM agent 失败源自"边想边做"导致的规划错误传播。显式两阶段不是新思想, 但用 LLM 重新包装后, 它对长程任务的有效性比传统软件工程更显著 — 因为 LLM 的"重新思考"在每步都贵且不可靠, 而一次性的"想清楚"既便宜又稳定。
>
> AetherCode 的 `AgentRuntime` 已经在按 Plan-and-Act 的思想组织 (V → self-correct → ensemble), 但目前没有显式两阶段 API。后续可加 `AgentRuntime.planThenAct()` 方法, 跟当前 `run()` 并行。
