# 2601.11327 Can Small Agent Collaboration Beat a Single Big LLM? (ICLR 2026 Workshop)

**作者**: Agata Zywot, Xinyi Chen, Maarten de Rijke (University of Amsterdam)

**会议**: ICLR 2026 Workshop on MALGAI (Multi-Agent LLM)

**日期**: 2026-04-13 (v2)

**PDF**: 0.79 MB · 10 pages

**核心**: 极小 LLM (4B) + 工具 + 多 agent 协作 > 大 LLM (32B) 无工具 — **orchestrator capacity > sub-agent capacity**。

## 1. 3 大 RQ

- **RQ1**: 小模型多 agent 能超过大单 agent?
- **RQ2**: 不同层级 (orchestrator / sub-agent) 显式 thinking 效果?
- **RQ3**: 性能由 orchestrator 容量还是 sub-agent 容量决定?

## 2. 关键发现

| 因素 | 影响 |
|---|---|
| 工具调用 | **最大最稳定** 的提升 (search / code / mind-map) |
| 模型规模 (4B → 32B) | 仅在 orchestrator 层有效 |
| Orchestrator 显式 thinking | 显著提升 |
| Sub-agent 显式 thinking | 有限或负向 |
| Sub-agent 容量 | **影响小** |

**结论**: 4B + tools > 32B without tools (在 GAIA benchmark)。

## 3. 实践意义

- **不要 all-in 大模型** — 多 agent + 工具用小模型性价比更高
- **Orchestrator 是性能关键** — 给它最大模型, sub-agent 小即可
- **Thinking 应放在 orchestrator** — sub-agent 直接干活, 别让它们再 think

## 6. 教训

- **Orchestrator 容量是关键** — 投资 orchestrator, sub-agent 可省
- **4B + tools > 32B no tools** — 工具调用是杠杆点
- **ICLR 2026 Workshop 实证** — 不是理论, GAIA benchmark 实测
- **跟 MAKER (2511.09030) 共识** — 极小 LLM + 大量 micro-agent 即可
- **Sub-agent 别让它 think** — orchestrator think, sub-agent do
