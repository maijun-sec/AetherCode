# R200 — UX feedback round (7 fixes from one user message)

## TL;DR
The user pasted one batch of 7 issues; all are fixed in v0.2.43. The
two genuine bugs were #4 ("本项目始终" not effective) and #5 (LeftPanel
showing "0 sessions" while a task was running). The other five are
display / truncation improvements to the tool event markdown, the
permission banner, the left-rail task summary, and the input config bar.

## Per-issue

### #1 — bash / file_write should show specific command, not generic label
- `compactToolInput` (Java side, `AetherCodeMethods.java:5378`) already
  picks the most identifying field per tool. The desktop's `toolEventToMarkdown`
  was correctly using `ev.inputSummary` (the compactToolInput result).
  What was missing: a fallback when the model emits an empty call
  (e.g. `bash` with no `command`).
- Fix: `missingInputHint(toolName)` in `MessageList.tsx` and
  `PermissionPromptBanner.tsx`. Bash → `"(missing command)"`, file_* →
  `"(missing file_path)"`, web_* → `"(missing url)"` / `"(missing query)"`,
  etc. A bare `"(no input)"` was uninformative.

### #2 — empty bash command renders the full schema dump
- The bash tool's `tool_result` for a missing-command failure is the
  full JSON schema (~1 KB). Pre-R200 `truncateOutput` had one cap
  (4000 chars) for both success and error output, so a single bad
  call filled the chat with `accepted parameters: - command (string,
  required): ... - cwd (string, optional): ...` etc.
- Fix: `TOOL_ERROR_PREVIEW = 200` chars for `isError` events; the
  default 4000-char cap is for successful output. So an error
  message is now one line, the full error stays in the transcript
  for debugging.

### #3 — verbose loop_warn_2 system message (9198 chars)
- The engine's loop-detection report can be 9 KB. Pre-R200 the
  renderer pushed the full text into the chat transcript,
  drowning the actual conversation. The full message was already
  in the `loopWarn.message` field for the banner.
- Fix: in `store/index.ts` the `loop-warn-1` / `loop-warn-2`
  handler now writes `shortMsg = msg.length > 100 ? msg.slice(0, 97) + '...' : msg`
  into the chat transcript. The banner (which shows the full
  message) is unchanged.

### #4 — "本项目始终" button does not actually persist
- **Root cause**: `permissionPolicyOverride` TS wrapper used
  `target: opts?.target ?? null`. JSON serialised this to
  `"target": null`. Java's `String.valueOf(null)` returns the
  literal string `"null"`, not `""`. The rule's `matcher` became
  `Pattern.quote("null")` = `\Qnull\E`, and bash's `extractPrompt`
  returns the empty command (or the file path), so
  `empty.matches("\\Qnull\\E")` is always `false`. The rule was
  effectively dead.
- **Fix (two-sided, defence in depth)**:
  1. TS: omit the `target` field entirely when no target was
     supplied (the wrapper now builds the params object
     conditionally, defaulting `target` to "not present").
  2. Java: detect `p.get("target") == null` AND
     `"null".equals(target)` and treat both as `""` (which
     `isBlank` already collapsed to), so the rule's `matcher`
     stays `null` and the rule matches ALL invocations of the
     tool — the expected "本项目始终" semantics.

### #5 — LeftPanel shows "0 sessions" while a task is running
- **Root cause**: `useSessionList` (TanStack Query) called
  `client.call('session/list', ...)`. The wire name `session/list`
  matched a Java *class* name (`SessionListParams` /
  `SessionListResult`) but the daemon dispatcher only registers
  `listSessions` (via `dispatcher.register("listSessions", ...)`).
  So the WS call returned `METHOD_NOT_FOUND`, `query.data` was
  `undefined`, and `all = query.data?.sessions ?? []` evaluated to
  `[]`. The "0 sessions" count was real — there was no data.
- **Fix**: `useSessionList` now calls `client.call('listSessions', ...)`.
  Updated `MockRpcServer.ts` + `types.ts` + tests to use the same
  wire name so the mock and production exercise the same path.

### #6 — left-rail session id is truncated
- Pre-R200 the left-rail `TaskSummary` was a vertical list of
  7 `label → value` rows (ID, CWD, Name, Model, Perm, Uptime,
  Daemon) under two section headers, eating ~170px of vertical
  space. The session id was already `slice(0, 8)`, so the visible
  truncation was caused by the 56px-wide label column + the
  narrow panel eating the remaining id width.
- **Fix**: rewrote `TaskSummary` as a single-row chip layout.
  `cwd | id | model | perm | daemon | stream` (with `uptime` /
  `name` on an optional second row when present). The CWD chip
  takes `flex: 1 1 140px` and ellipsises from the right; the
  other chips are content-sized. Vertical footprint went from
  ~170px to ~28px.

### #7 — CWD chip drops to a second row, wasting space
- Pre-R200 the input config bar was `flex-wrap: wrap` and the
  cwd group had `max-width: 360px`. On a 1280px window the
  `thinking | model | perm | tools | workflow` cluster was wide
  enough that the cwd group wrapped to row 2.
- **Fix**:
  1. `input-config-bar` is now `flex-wrap: nowrap` with
     `overflow-x: auto` (the strip scrolls horizontally on tiny
     windows instead of breaking the layout).
  2. `cwd-group` `max-width: 360px` → `220px` and
     `flex: 0 1 auto`. A typical path like `D:\tmp\abc_2` fits
     comfortably; a 32-char path ellipsises cleanly.

## Lessons
1. **`null` is a JSON-RPC footgun.** `String.valueOf(null) = "null"`,
   not `""`. Always treat the literal string `"null"` as null at
   the protocol boundary. Better: don't send null at all — omit
   the field. We do both.
2. **Wire names are contract; class names are not.** The query
   was named `session/list` because there was a Java class
   `SessionListParams`, but the daemon dispatcher only registers
   `listSessions`. The two never agreed, so the call always
   failed silently. Pinned: use the wire name on the caller,
   register it on the server.
3. **Errors deserve a tighter chat cap than success.** A 50 KB
   stdout is legitimate (the model asked for a build log). A 1 KB
   error path on a missing parameter is the schema dump, not
   useful info. R200 splits `TOOL_OUTPUT_PREVIEW = 4000` and
   `TOOL_ERROR_PREVIEW = 200`.
4. **Loop-detection reports are too long for the chat.** Keep
   them in the banner; truncate the chat copy. The full
   message is one click away via the banner UI.
5. **"Show specific command" is two layers: compactToolInput
   picks the field; missingInputHint fills the gap when the
   field is empty.** Both layers needed.
6. **`flex-wrap: wrap` is fine for content, dangerous for
   chrome.** The input config bar was wrapping the cwd pill
   to row 2 at common window widths. Changing the strip to
   `flex-wrap: nowrap` + `overflow-x: auto` keeps the row
   coherent. The chips themselves are flex-shrinkable, so a
   long path ellipsises instead of pushing siblings off.
