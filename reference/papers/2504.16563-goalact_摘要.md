# 2504.16563 GoalAct: Enhancing LLM-Based Agents via Global Planning and Hierarchical Execution

**作者**: Junjie Chen, Haitao Li, Jingli Yang, Yiqun Liu, Qingyao Ai (清华大学 DCST)

**日期**: 2025-04-23 (v3)

**PDF**: 657 KB · 13 pages

**核心**: **GoalAct = 持续更新的全局规划 (Global Plan) + 分层执行 (Hierarchical Execution)**, 在 LegalAgentBench 上 +12.22% SOTA。

## 1. 问题

| 现有方法 | 缺点 |
|---|---|
| ReAct | 增量式 Thought-Action-Observation, 无全局视角, 陷入 local branch |
| Plan-and-Execute | 静态 plan + 动态调整, 但 plan 含具体动作, 超 action space |
| CodeAct | Python 代码作 action space, 但 planning 仍短视 |

## 2. GoalAct 架构

```
User Query → Global Plan G_t = {(P_1,A_1), ..., (P_n,A_n)}
              ↓ 每步 update
           π(Q, T, S_t)  →  G_{t+1}   (S_t = 历史 (P_i, A_i, O_i))
              ↓
       High-level skills (searching / coding / writing / reasoning)
              ↓
       Skill-specific action space (text/json OR python code)
              ↓
       Environment
```

### 2.1 Global Planning (持续更新)

- Plan G 是 `(P_i, A_i)` 序列, P 是 high-level skill, A 是目标
- 每个 time step 重新生成 G (类似 dynamic replan, 但带完整历史 S_t)
- 末位 step 必为 `Finish`

### 2.2 Hierarchical Execution (技能分层)

- Plan 只指定 **high-level skill** (searching / coding / writing / reasoning / etc.)
- 同一 skill 内部有特定 action space:
  - **Searching skill**: text/json 调用
  - **Coding skill**: Python 代码 (含 loop / branch)
  - **Writing skill**: 特定流程 (gather → draft → polish)
  - **Reasoning skill**: 自由推理
- 不同 skill 可动态增删, 扩展性好

## 3. 关键贡献

| 贡献 | 数据 |
|---|---|
| Global Plan 持续更新 | 每步重新生成, 不丢失历史 |
| Hierarchical skill 抽象 | plan 只需指定 skill, 简化 plan 复杂度 |
| LegalAgentBench SOTA | **+12.22% 平均** 准确率提升 |
| 5 种 skill 抽象可扩展 | 任务多样化适应 |

## 4. AetherCode 关联

| 论文观点 | AetherCode 对应 | 实现状态 |
|---|---|---|
| 持续更新 Global Plan | `DagPlan.update(step, result)` | ⚠️ 需暴露 mutator |
| Hierarchical skill | `StandardTools` 17 个 tool 按 skill 分组 | ⚠️ 无显式 skill 抽象 |
| Plan 末位为 Finish | `DagPlan.terminalStep` 强制约束 | ⚠️ 缺 |
| 多 action space (text/code) | Tool 接口统一, 不分 text/code | N/A (统一更简单) |

## 5. 兼容实现候选

| 类 | 用途 | 文件位置 |
|---|---|---|
| `GlobalPlan` | 持续更新的 plan, 每步 query 重新生成 | `orchestration.plan` |

## 6. 教训

- **Skill 抽象简化 plan** — plan 不指定具体动作, 只指定 high-level skill
- **Global Plan 持续更新是长链任务关键** — 不是一次生成后就走完
- **不同 skill 适配不同 action space** — 强行统一会损失灵活性 (text 调用 vs Python 代码)
- **Plan 末位强制 Finish** — 显式终止条件, 避免无限循环
